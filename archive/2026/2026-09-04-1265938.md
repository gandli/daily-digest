# Training a coding model to paint watercolours with TRL and OpenEnv

*作者：Sergio Paniego（Hugging Face）*

2026 年 8 月 23 日，Surya Narreddi 发布了一段视频：一个语言模型通过 [p5.brush](https://github.com/acamposuribe/p5.brush) 写 JavaScript 画出了水彩画。视频迅速走红，发布时已超 150 万次观看。

我尝试用 [TRL](https://huggingface.co/docs/trl) 和 [OpenEnv](https://github.com/huggingface/OpenEnv) 复现他的想法——参考池数据集、RL 环境、训练脚本、训练好的模型全部开源。整个流水线跑在 Hugging Face 上（Jobs 训练 + Spaces 跑环境与评分器 + Inference Providers 跑成对评审）。

## 人们为什么喜欢它

画作看起来松弛、不完美、手工感十足——而此刻图像模型产出的是完美（统计上平均）的图片。我的猜测是这种反差是视频走红的原因。这让我想起生成式 AI 艺术的早期，那时的重点是探索媒介本身。

项目的另一半想法是媒介。模型写一段约 150 行的 JavaScript 程序来画图。模型输出是代码。你可以读它、编辑它、重新运行它，每一笔背后的决策都可见。风格来自一个限制：**模型只被允许使用库的 10 个方法**。

## 对品味做 RL

最近的语言模型 RL 大多使用可验证的奖励（数学题有已知答案、代码通过测试）。这个项目更接近更老的例外 RLHF——从人类偏好学一个奖励模型。

这里的奖励是**审美偏好**。没有"正确"答案。项目的真正问题是：**能不能对品味做 RL？**

奖励定义（权重 + 测量）：

- `gate` 0.05：草图能编译、画了东西、不作弊
- `length` 0.05：轻微推动更长的代码
- 成对评审 0.60：风格，对比参考池
- HPSv3 0.30：渲染的审美偏好

HPSv3 是开源的 7B 偏好模型（给它图片+描述，返回人偏好分数）。成对评审是 Qwen3-VL-30B-A3B-Instruct，通过 Inference Providers 调用，拿候选画与参考池中随机选 4 张对比。**池定义了品味**——工作从调超参变成了构建"决定什么是美"的集合。

## 复现的三个关键发现

我训练了三个 run，只改两个评分器之间的权重分配：

- `judge-led`（0.60/0.30，原配方，110 步停）
- `hps-led`（0.30/0.60，中点，110 步停）
- `hps-only`（0.00/0.90，验证，60 步停）

**第一个发现：** 在成功之前，有很长一段奖励曲线平躺。每轮运行测试的都是我以为合理的理论。最后开始简单能起作用的再往上叠——答案是**学习率太低**。改学习率 2e-5→5e-5、调度器 linear→constant_with_warmup、scale_rewards group→none、target_modules 手列→all-linear（MoE 模型 Qwen3.5-35B-A3B 的投影命名不同，手列表只训到 40 层中的 10 层）——这四步解锁了第一个成功 run。

**第二个发现：** 每个 run 里，模型学到的第一件事是**停止产出糟糕的画**。`judge-led` 里低于 0.3 的 rollout 从 99 降到 16。这就是为什么"最佳画作"几乎没变化——改变在分布的中部。**成对评审改变的是顶端**：`hps-only` 让画更可靠但没变更好；有评审在，画"更像池子"（更像我的品味），覆盖颜料的面积翻倍。

**第三个发现：** 模型无视一条显式指令，而且它是对的。系统提示要求 15-30 个填充形状，实际均值在 7-9 之间，且 n_shapes 与奖励几乎不相关。策略没有被奖励要求服从那句话，所以它不服从。

## 基础设施很难

一个 run 需要训练器、两个 Spaces、一个推理路由和一条 websocket 保持数小时健康，每个静默失败的部件都会在别处变成错误数字。**基础设施的失败以 0 进入奖励**——渲染超时或评分器没响应，和差画一样得 0.0——跨所有 run 约 1.5% 的 rollout，最差 run 达 5.2%。这些路径现在返回 None 并从组中排除。我还发现了一个 OpenEnv 的 bug 并提交了上游修复（websocket 被远端关闭后仍被缓存）。

## 成本与结论

- 训练器：1 张 H200，18 小时（60 步）/ 约 34 小时（110 步）
- 一个 step = 8 个 rollout，15-18 分钟，其中 **70-80% 是渲染**（无 GPU 的 Space 用软件渲染 WebGL）
- 评分器可能比训练还贵：HPSv3 要全程在线，run 结束记得暂停

最终：三个奖励混合、三个风格。以我的眼光，`judge-led` 是最多样、艺术上最有意思的；`hps-led` 水彩令人信服但最好的那些共享一种湿画湿的软质感；`hps-only` 收敛最狠，多数画落在同样颜色上。

**最大的局限**：178 张模型生成的画定义了"这个训练模型认为什么是美"。**池是瓶颈，是整条流水线里没有原则性答案的部分。** 替换数据集，奖励会自动改变而不用改一行代码——但"决定什么该进奖励集"是一个非常人类的活。AI 把瓶颈从制造移到了品鉴。
