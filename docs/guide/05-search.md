## /search 关键词 — 搜索历史存档

`/search` 命令用于在历史存档中进行关键词检索,Bot 会在内存索引中按关键词过滤并按相关度排序,然后以卡片形式返回命中结果。本章按照真实操作顺序,逐步演示从首次调用到翻页浏览的完整流程。

### 步骤 1: 查看用法

在聊天窗口中直接输入 `/search` 并发送,不带任何关键词参数。

Bot 会回复一行用法提示,告诉你该命令必须附带关键词才能工作:

> 用法: /search 关键词 例: /search rust cli

此时说明参数为空,Bot 不会进入检索流程,只做语法提示。

![用法提示](assets/05-search-r1.png)

### 步骤 2: 输入完整关键词

按照提示格式,带上要检索的关键词再次发送命令,例如输入 `/search bat` 并回车。

Bot 会在内存索引中执行关键词过滤,并按相关度对命中的存档条目排序,然后以结果卡片的形式回复。卡片内容包含三部分信息:搜索关键词、命中数量与分页信息(例如 "第 1/1 页")、以及命中条目本身。每条结果以 ⭐ 加 GitHub 仓库路径加简介的形式呈现。

本例中,Bot 返回内容如下:

> 🔍 「bat」1 条命中 (第 1/1 页): ⭐ sharkdp/bat 带语法高亮的 cat 命令克隆

可以看到,关键词 "bat" 在历史存档中只匹配到一条高度相关的结果,即 sharkdp/bat 这个命令行工具的介绍条目。

![关键词检索结果](assets/05-search-r2.png)

### 步骤 3: 浏览更多结果(可选)

当命中数量较多、结果跨越多页时,Bot 会在回复中附带翻页按钮,通常以 callback 形式标记(例如 `sch:page`),用于在结果集的不同页之间切换。每次翻页请求中,Bot 会通过 KV 存储临时保存当前的查询关键词,以保证后续翻页动作仍能检索到同一结果集。

如果本次检索只有 1 条命中(如上例所示),则不会出现翻页按钮,直接进入下一步即可。

### 步骤 4: 基于结果继续操作

拿到结果卡片后,你可以根据卡片中显示的仓库路径或简介,决定下一步动作:例如使用其他命令(如 `/repo` 或 `/topic`)进一步查看该项目的详细信息,或返回日常对话。`/search` 本身仅承担检索职责,不直接打开存档内容。

---

### 小贴士

- 关键词支持空格分隔的多词组合,例如 `/search rust cli` 会同时匹配包含 "rust" 与 "cli" 的存档条目,适合按技术栈或主题进行更精确的检索。
- 当结果跨越多页时,留意 Bot 回复中附带的翻页按钮;翻页过程由 Bot 自动维护查询上下文,你无需重复输入关键词。
- 如果一次检索返回的命中数过多,可以加上更具区分度的限定词,例如将 `cli` 收紧为 `rust cli`,以缩小结果范围、加快定位速度。
