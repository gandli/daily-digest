## /trending — 今日 GitHub Trending

`/trending` 用于拉取当天 GitHub Trending 仓库列表。Bot 在收到命令后会先检查本地缓存:若当天已有结果,直接秒回卡片;若未命中,则先回一条「⏳ 生成中」占位消息,再在后台跑完整流水线(抓取 → 翻译 → 存档 → 发卡),完成后自动推送到当前对话。

### 步骤 1: 发送命令

在任意与 Bot 的私聊或群聊中输入:

```
/trending
```

发送后无需追加任何参数。Bot 会立即判定缓存状态并决定回复形态。

### 步骤 2: 等待首次响应(未命中场景)

若当天尚无缓存,Bot 立即返回一条占位消息,提示生成预计耗时:

> ⏳ Trending 生成中(10-30 秒), 完成后自动推送。

此时命令已成功受理,你可以保持对话窗口开启,无需重复发送命令。占位消息不会附带任何仓库卡片,这是正常现象,不是错误。

![占位消息与后续推送](assets/02-trending-r1.png)

### 步骤 3: 接收后台生成的卡片(未命中场景)

大约 10 至 30 秒后,Bot 会在同一对话中自动推送当天 Trending 列表。卡片按 `序号/总数 仓库名 ⭐ Star 数 👤 作者 一句话简介 #标签` 的格式逐条发送,通常为 2 条左右,每条末尾附带 🗂 链接按钮,点击即可跳转到对应仓库首页。首批仓库样例如下:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending 🗂

### 步骤 4: 命中缓存时的快速返回

当天再次发送 `/trending` 时,Bot 不再发送占位消息,而是直接、逐条地把同一份卡片推回当前对话,响应几乎是即时的。

![命中缓存时的秒回卡片](assets/02-trending-r2.png)

由于命中的是同一份当日缓存,卡片内容与步骤 3 保持一致;若想强制刷新,需等待第二天或联系管理员清缓存。

### 小贴士

- 触发生成后请耐心等待,不要连续多次发送 `/trending`,否则会生成多份并行任务,反而拖慢推送。
- 卡片中的简介与标签由 Bot 自动翻译生成,可能与仓库原始 `README` 存在细微差异,精确描述以仓库主页为准。
- Trending 列表按 GitHub 当日榜单生成,跨时区请求时,「当天」以 Bot 服务端所在时区为准。
