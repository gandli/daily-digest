## /trending — 今日 GitHub Trending

`/trending` 命令用于拉取当天的 GitHub Trending 仓库，并以编号卡片的形式推送到当前聊天。该命令内置缓存机制：当日首次请求触发完整管线（抓取 → 翻译 → 存档 → 发卡），后续请求直接命中缓存，秒回卡片。

### 步骤 1: 发送命令

在任意已添加 Bot 的聊天中输入：

```
/trending
```

向 Bot 发送即可，无需附带任何参数。Bot 会立即识别该命令并开始处理。

### 步骤 2: 首次请求——等待生成

如果是当日第一次请求，Bot 会先回复一条占位消息，提示用户稍候：

> ⏳ Trending 生成中(10-30 秒), 完成后自动推送。

此时 Bot 在后台执行完整管线：抓取 GitHub 当日 Trending 列表、对仓库描述进行翻译整理、写入缓存存档。无需用户做任何额外操作，等待 10–30 秒即可。

![首次请求：占位提示与随后推送的 Trending 卡片](assets/02-trending-r1.png)

### 步骤 3: 查看推送的卡片

后台管线完成后，Bot 会按 `1/2`、`2/2` 的编号顺序自动推送 Trending 卡片，每张卡片包含以下信息：

- **序号与仓库全名**：例如 `1/2 antirez/kilo`
- **Star 数与作者**：例如 `⭐ 3.2k 👤 antirez`
- **中文描述**：对仓库核心功能的中文简介
- **话题标签**：例如 `#trending #c #editor`
- **原文链接**：以 🗂 图标引出的 GitHub 仓库地址

如果当天的仓库数量不止两条，Bot 会依次编号推送，直到全部发送完毕。

### 步骤 4: 再次请求——缓存命中

当天再次发送 `/trending` 时，Bot 不再走完整管线，而是直接从缓存中读取当日已生成的卡片并立即推送，因此响应速度明显更快，表现为「秒回」。卡片内容与首次请求完全一致。

![再次请求：直接命中缓存，秒回卡片](assets/02-trending-r2.png)

### 步骤 5: 点击链接查看原文

推送完成后，可点击任一卡片末尾的 🗂 链接，跳转至 GitHub 上的对应仓库页面，查看源码、README、Star 历史等详细信息。

---

### 小贴士

- **命令无参数**：`/trending` 不支持附加筛选条件（如语言、日期范围），如需更细粒度的过滤，可结合其他代码搜索命令使用。
- **每日刷新**：缓存以「天」为粒度，第二天首次请求时会重新触发完整管线，拿到最新的当日 Trending 列表。
- **耐心等待占位消息**：看到「⏳ 生成中」时不要重复发送 `/trending`，重复发送在缓存生成前可能被视作新的管线触发请求；等待卡片自动推送即可。
