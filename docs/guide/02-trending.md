# /trending — 今日 GitHub Trending

## 步骤 1: 发送指令

在 Telegram 对话框中输入 `/trending`(也可使用短别名 `/gt`),然后发送。Bot 收到请求后,会立刻判断当天是否已有缓存。

## 步骤 2: 查看占位提示

如果当天还没有现成的 Trending 卡片,Bot 会先返回一条提示消息,告知用户内容正在生成中,无需再次发起请求:

> ⏳ GitHub Trending 生成中(10-30 秒),完成后自动推送。

这条占位消息的作用是让用户知道后台已经开始处理(抓取 → 翻译 → 存档 → 发卡),而不是忽略了他的指令。整个流程通常在 10 到 30 秒之间完成。

![首次发送 /gt,Bot 返回占位提示并陆续推送卡片](assets/02-trending-r1.png)

## 步骤 3: 接收第一条卡片

后台管线完成后,Bot 会以单独消息的形式把每条 Trending 仓库依次推送出来。每条卡片包含四部分信息:

1. **序号与仓库名**:例如 `1/2 antirez/kilo`,表示当天第几条以及仓库的 `作者/仓库名`。
2. **数据指标**:⭐ 星标数(如 `3.2k`、`50.0k`)与 👤 作者昵称。
3. **中文简介**:Bot 自动翻译并润色后的仓库描述,方便不熟悉英文的用户快速判断。
4. **话题标签**:以 `#` 开头的关键词(如 `#trending`、`#c`、`#editor`),以及末尾的 🗂 存档标记和仓库链接。

## 步骤 4: 接收后续卡片

Bot 会继续推送当天的其他 Trending 条目,直到全部发完。例如同一次会话中,接下来会看到第二条卡片 `2/2 sharkdp/bat`,格式与第一条完全一致,只是仓库信息不同。

## 步骤 5: 二次调用,体验缓存加速

当天再次发送 `/trending`(或 `/gt`)时,Bot 会直接命中缓存,跳过整个抓取与翻译流程,几乎瞬时返回所有卡片,不再出现 ⏳ 占位消息。这种「首次稍慢、二次秒回」的行为就是缓存机制的体现。

![当天第二次发送 /gt,Bot 直接秒回完整卡片,无占位提示](assets/02-trending-r2.png)

## 小贴士

- **别重复点击**:看到 ⏳ 占位提示后耐心等待即可,反复发送 `/trending` 并不会让结果来得更快,反而可能挤占处理队列。
- **善用短别名**:在手机端输入 `/gt` 比 `/trending` 更省事,两者完全等价。
- **结果以天为周期**:每天 0 点(UTC)左右会刷新一次,如果你想看新的榜单,等到第二天再请求即可。
