## /trending — 今日 GitHub Trending

本指令用于拉取当天的 GitHub Trending 列表，并自动翻译为中文简介推送给你。Bot 内部维护一份缓存,首次请求未命中时会启动后台管线(抓取 → 翻译 → 存档 → 发卡),通常耗时 10–30 秒;后续在缓存有效期内重复调用,会立即返回同一份卡片。

### 步骤 1:发送触发指令

在任意 Bot 对话窗口中输入:

```
/trending
```

也可以使用别名 `/gt`,两者行为完全一致。发送后无需附带任何参数,Bot 会自动按当天日期(服务器时区)生成 Trending。

### 步骤 2:等待「占位」回应

指令发出后,Bot 会先回复一条占位消息,告知你生成已启动:

> ⏳ GitHub Trending 生成中(10–30 秒),完成后自动推送。

此时请保持对话窗口开启,不要重复发送指令,否则会重复入队、消耗额外配额。

### 步骤 3:接收首条卡片

后台管线完成后,Bot 会按 1/2、2/2 的顺序逐条推送,每条卡片包含仓库名、Star 数、作者、中文简介、话题标签、分类图标与跳转链接。例如首条可能为:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂 <a href="…">

在首次(未命中缓存)调用场景下,你会先看到步骤 2 的占位消息,再依次收到 1/2、2/2 两条卡片,完整效果如下图所示:

![首轮调用:占位消息 + 两条 Trending 卡片依次推送](assets/02-trending-r1.png)

### 步骤 4:接收余下卡片并确认链接

第二条卡片紧随其后,格式与首条一致,带有仓库专属的话题标签与直达链接:

> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending 🗂 <a href="https:…">

点击 HTML 锚文本即可跳转至对应的 GitHub 仓库页面。当天生成的卡片总数通常为 N 条,Bot 会按 `1/N`、`2/N` …… 顺序完整送达;若中途断开,需重新调用一次 `/trending`。

### 步骤 5:在缓存有效期内复用

缓存命中时,Bot 不再发送「⏳ 生成中」占位,而是直接按相同顺序推送与上次一致的两条卡片,响应几乎是秒回。例如第二次发送 `/trending`(即 `/gt`)时,Bot 直接输出 1/2、2/2,不再出现占位消息:

![第二轮调用:无占位消息,直接秒回两条卡片](assets/02-trending-r2.png)

由此可以验证:同一日内的重复请求,会复用缓存;而日期变更或缓存失效后,管线会重新执行,流程回到步骤 2。

### 小贴士

- 默认每次返回若干条热门仓库(以卡片中 `1/N`、`2/N` 标注的 N 为准),卡片按 Trending 排名顺序推送。
- 卡片中的 `<a href="…">` 为可点击的 HTML 锚文本,大多数 Telegram 客户端会渲染为可跳转链接;若客户端不支持,链接会以明文 URL 形式展示,直接复制到浏览器即可打开。
- 若等待超过 30 秒仍未收到卡片,可能是后台管线异常,建议重新发送一次 `/trending` 触发重试;短时间内多次发送只会在缓存命中时直接复用已有结果,不会重复抓取。
