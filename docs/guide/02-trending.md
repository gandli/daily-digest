# /trending — 今日 GitHub Trending

通过 `/trending` 命令(测试中使用的触发形式为 `/gt`),Bot 会把当天 GitHub Trending 仓库整理成中文摘要卡片推送给您。当日首次请求会触发一次完整生成流程,后续请求可直接命中缓存,秒级返回。

### 步骤 1: 发送命令

在 Bot 对话窗口中输入 `/trending`(或配置的别名 `/gt`)并发送。

### 步骤 2: 等待占位消息(首次或缓存失效时)

Bot 检测到当日尚无缓存结果,会立即回复一条占位提示,告知您生成已开始,无需重复发送命令:

> ⏳ GitHub Trending 生成中(10-30 秒),完成后自动推送。

此时 Bot 正在后台运行抓取、翻译、存档全流程。

### 步骤 3: 接收完整卡片(同一会话内顺序到达)

后台管线完成后,Bot 会按顺序向同一会话连续推送卡片消息,每条以 `n/m` 标识序号,内容包含仓库名、星标数、作者、简介、话题标签与链接。例如收到两条摘要时,格式如下:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂
>
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending 🗂

首次请求的占位与最终卡片会一起出现在同一会话中,效果如下:

![首次请求:占位消息生成中,随后连续收到 1/2 与 2/2 两张仓库摘要卡片](assets/02-trending-r1.png)

### 步骤 4: 缓存命中,直接拿结果(当日再次请求)

当日再次发送 `/trending` 时,Bot 直接从缓存读取已生成的当日卡片并立刻推送,不再返回占位消息,也不再重新跑完整管线。您会按顺序看到 `1/2`、`2/2` 等卡片,内容与首次生成保持一致:

![二次请求:跳过占位,Bot 直接连续推送当日的 1/2 与 2/2 摘要卡片](assets/02-trending-r2.png)

### 步骤 5: 查看与跳转

每条卡片末尾的链接指向 GitHub 仓库页;点击后即可在浏览器中查看完整说明、源码与 Star 列表。

## 小贴士

- 不要在收到占位消息后反复发送 `/trending`:重复触发只会让 Bot 反复返回相同的占位提示,真正完成的卡片只会在首次请求对应的会话中推送。
- 卡片以 `n/m` 顺序推送,若网络或 Bot 转发延迟导致消息未按顺序到达,可等待几秒再刷新会话,避免中途再次发命令打断推送。
- 每日 Trending 由当日首次请求触发生成并缓存,如需重新跑一次完整管线,请等待次日或在 Bot 重启缓存失效后再请求。
