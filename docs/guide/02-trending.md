# /trending — 今日 GitHub Trending

通过 `/trending`(别名 `/gt`)命令,快速获取当天 GitHub Trending 仓库的精选摘要。Bot 会自动抓取、翻译并整理为带话题标签与链接的卡片推送给你。系统内置缓存机制,相同请求在缓存有效期内会立即返回,无需等待。

### 步骤 1:发送命令

在 Telegram 对话中输入命令并发送:

```
/gt
```

或使用完整命令名:

```
/trending
```

### 步骤 2:首次请求——等待生成

首次触发(或缓存失效后)时,Bot 会立即回复一条占位消息,告知正在生成:

```
⏳ GitHub Trending 生成中(10-30 秒), 完成后自动推送。
```

这条消息表明后台已开始执行完整管线:抓取 GitHub Trending 数据、翻译仓库描述、归档到数据库、整理为卡片。整个过程通常需要 10 至 30 秒,期间你可以正常使用 Bot 的其他功能,完成后卡片会自动推送到当前对话。

![首次请求生成中提示与最终推送的卡片](assets/02-trending-r1.png)

### 步骤 3:接收整理好的卡片

生成完成后,Bot 会按 `N/M 序号` 的格式逐条推送仓库卡片,每条卡片包含:

- 仓库名(如 `antirez/kilo`)
- Star 数(如 ⭐ 3.2k)
- 作者(如 👤 antirez)
- 仓库简介的中文摘要
- 话题标签(如 `#trending #c #editor`)
- 原始仓库链接

如截图所示,本次推送了两张卡片:第一条是 `antirez/kilo`(⭐ 3.2k),第二条是 `sharkdp/bat`(⭐ 50.0k)。

### 步骤 4:缓存命中——即时返回

当你再次发送 `/gt` 时,如果当日缓存仍然有效,Bot 会直接返回完整卡片列表,不再发送「生成中」占位消息,响应几乎是即时的。

![缓存命中后直接返回完整卡片列表](assets/02-trending-r2.png)

对比两次截图可以清晰看到差异:首次请求多了一条 ⏳ 占位提示,而重复请求直接呈现最终卡片内容。

### 步骤 5:阅读与跳转

卡片中的链接指向 GitHub 原始仓库,你可以直接点击跳转到感兴趣的仓库页面查看源码、Star 或 Fork。话题标签(如 `#trending`、`#c`、`#editor`)帮助你快速识别仓库所属的技术领域。

## 小贴士

1. **合理利用缓存**:每天前几次请求可能触发完整生成流程,稍等片刻即可;同一天内的重复请求会秒回,适合频繁查看。
2. **配合其他命令使用**:可以先通过 `/trending` 发现感兴趣的仓库,再用 `/search 关键词` 深入检索历史归档中的特定技术栈。
3. **关注话题标签**:卡片末尾的 `#标签` 是筛选仓库的便捷线索,例如看到 `#python` 即可快速判断该仓库属于 Python 生态。
