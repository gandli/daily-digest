### 步骤 1: 发送命令

在 Telegram 对话中输入 `/gt` 并发送,向 Bot 请求当天的 GitHub Trending 仓库列表。该命令是触发生成的唯一入口,无需额外参数。

### 步骤 2: 收到占位提示

Bot 收到命令后,若当天缓存未命中,会立即回复一条提示消息:

> ⏳ GitHub Trending 生成中(10-30 秒),完成后自动推送。

此占位消息用于告知用户请求已被接收,后台正在启动完整的抓取与翻译流水线。

### 步骤 3: 等待后台处理

后台会依次执行四个阶段:从 GitHub 抓取当天的 Trending 仓库、对仓库描述进行翻译、将结果写入缓存存档、最后逐条推送卡片。整个过程通常需要 10 至 30 秒,期间用户无需任何操作。

### 步骤 4: 接收仓库卡片

处理完成后,Bot 会按顺序自动推送仓库卡片,每条消息对应一个仓库。卡片内容包括仓库全称(如 `antirez/kilo`)、Star 数、作者用户名、中文简介以及话题标签和链接。完整效果如下图所示:

![首次调用 /gt,先收到占位提示,随后自动推送 1/2 与 2/2 两张仓库卡片](assets/02-trending-r1.png)

### 步骤 5: 再次调用命中缓存

当天再次发送 `/gt` 时,Bot 会直接命中缓存,不再发送占位提示,而是立即按顺序推送卡片,响应速度接近秒回。效果如下图所示:

![重复调用 /gt,跳过占位提示直接秒推两张仓库卡片](assets/02-trending-r2.png)

### 小贴士

- 触发占位提示是正常现象,无需重复发送 `/gt`,等待 10-30 秒即可收到卡片,重复发送只会触发更多次流水线。
- 同一自然日内,缓存命中可保证内容一致;若想查看次日数据,可在第二天再发 `/gt`。
- 卡片中的链接可点击直达仓库,话题标签(如 `#trending`、`#c`)便于快速识别仓库所属领域。
