## /trending — 今日 GitHub Trending

### 步骤 1: 发送指令

在 Telegram 对话框中输入 `/trending`（或命令别名 `/gt`）并发送。Bot 收到指令后会立刻判断是否已有当天缓存结果：

- **缓存命中**：秒回完整卡片（参考 步骤 2 中的“稳态输出”）。
- **缓存未命中**：先返回一条占位消息，告诉用户正在生成，需要等待 10–30 秒。

### 步骤 2: 等待“生成中”占位消息（仅首次或过期时）

当当天 Trending 还未生成时，Bot 会先回复一条提示：

> ⏳ GitHub Trending 生成中（10–30 秒），完成后自动推送。

此时后台会依次执行抓取 → 翻译 → 存档 → 发卡 完整管线。**请勿重复发送指令**，避免触发多次生成任务。

下图展示了首次触发时的完整交互过程：先看到“生成中”提示，随后在同一会话中陆续收到编号为 1/2 和 2/2 的两张仓库卡片。

![首次触发 /gt 时，先返回生成中占位，再陆续收到 1/2 与 2/2 的仓库卡片](assets/02-trending-r1.png)

### 步骤 3: 查看推送的仓库卡片

后台管线完成后，Bot 会主动向同一会话连续推送多条消息，每条对应一个 Trending 仓库，按当天的热度顺序排列。每张卡片包含：

1. **序号**：形如 `1/2`、`2/2`，表示当天共多少个仓库以及当前是第几个。
2. **仓库路径**：例如 `antirez/kilo`、`sharkdp/bat`。
3. **星标数**：例如 `⭐ 3.2k`、`⭐ 50.0k`。
4. **作者**：例如 `👤 antirez`、`👤 sharkdp`。
5. **中文简介**：由后台翻译生成，例如“这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。”
6. **话题标签**：以 `#` 开头的关键字，例如 `#trending #c #editor`。
7. **图标与链接**：末尾的 🗂 与 `<a href="…">` 指向仓库详情页。

例如完整的一条 1/2 卡片形如：

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="…">…</a>

### 步骤 4: 后续调用复用缓存

当天再次发送 `/gt` 时，由于缓存已命中，Bot 会跳过“生成中”占位，**直接连续回放当天的完整卡片列表**。如下面这张截图所示：第 2 轮直接以 1/2、2/2 两条消息开始，不再出现“⏳ 生成中”提示。

![第二轮调用直接命中缓存，秒回 1/2 与 2/2 卡片](assets/02-trending-r2.png)

### 小贴士

- **耐心等待首次结果**：如果看到“⏳ 生成中”，请耐心等待 10–30 秒；后台抓取与翻译耗时与当日仓库数量和网络状况相关。
- **避免重复触发**：生成中提示出现后请勿连续发送 `/gt`，多次调用会让后台重复排队，反而拉慢推送。
- **跨设备同步**：由于结果按“当天”缓存，在手机、平板或桌面端任一客户端上调用过 `/gt` 后，其它客户端再次调用都会立即拿到同一份卡片。
