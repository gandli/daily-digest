### 步骤 1:发送指令

在 Bot 对话窗口中输入命令 `/trending` 并发送。该命令用于请求查看当天的 GitHub Trending 仓库列表,系统会根据缓存状态选择立即返回结果或启动后台生成流程。

### 步骤 2:等待生成占位提示

若 Bot 后台尚未缓存今日的 Trending 数据,系统会立即返回一条占位提示,告知用户需要等待若干秒:

> ⏳ Trending 生成中(10-30 秒), 完成后自动推送。

此时无需重复发送命令,只需保持对话窗口打开,等待 Bot 自动推送结果。完整的生成流程包括抓取 GitHub 当日 Trending 页面、翻译仓库描述、写入存档数据库、最终发送卡片消息四个环节。

![第 1 轮首次请求,Bot 先返回占位提示,再分两条消息推送 Trending 卡片](assets/02-trending-r1.png)

### 步骤 3:接收第一张卡片

后台管线跑完后,Bot 会按编号依次推送仓库卡片。第 1 条消息的格式示例如下:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">...</a>

卡片包含分页序号、仓库全称、Star 数量、作者、中文简介、话题标签以及直达链接。分页序号 `1/2` 表示这是当日第 1 张、共 2 张卡片。

### 步骤 4:接收第二张卡片

紧接着,Bot 推送当日第 2 张仓库卡片:

> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending 🗂 <a href="...">...</a>

`2/2` 表明本次 Trending 总共 2 条记录,至此当日的卡片推送完毕。

### 步骤 5:查看缓存命中场景

当用户当天再次发送 `/trending` 时,系统会直接从缓存中读取结果,无需触发后台管线,Bot 会立刻在同一条消息中把 `1/2` 与 `2/2` 两张卡片一起发出,不再出现“生成中”提示。

![第 2 轮缓存命中,Bot 直接连续返回两张 Trending 卡片](assets/02-trending-r2.png)

## 小贴士

- 看到 ⏳ 占位提示后请耐心等待 10–30 秒,**不要重复发送** `/trending`,否则会生成多个后台任务。
- 卡片中的 Star 数量与排名为请求时刻的快照,GitHub 实际数据会持续变动,以链接打开后页面为准。
- 建议每天固定一个时间点查看,可充分利用缓存,获得秒回体验;若想强制刷新,可等待次日首次请求触发新一轮生成。
