## /trending — 今日 GitHub Trending

`/trending` 用于拉取当天 GitHub Trending 榜单,Bot 会以多卡片的形式把仓库简介、标签和原仓库链接推送给你。Bot 内部会优先复用今日缓存,若未命中则会在后台跑完「抓取 → 翻译 → 存档 → 发卡」整条管线,期间先给你一张占位提示。

### 步骤 1:发送指令

在任意 Bot 对话中输入:

```
/trending
```

回车后,Bot 会先判断当天缓存是否可用。

### 步骤 2:命中缓存 → 直接收卡

若当日缓存命中,Bot 会立即按编号 1/N、2/N …… 依次推送仓库卡片,无需等待,通常在 1-2 秒内全部送达。

### 步骤 3:未命中 → 收到占位提示

若当日缓存未命中,Bot 会先回一条占位消息,告知你任务已进入后台队列,无需你做任何额外操作,稍等片刻即可。

> ⏳ Trending 生成中(10-30 秒), 完成后自动推送。

这条消息只出现一次,Bot 不会因为长时间未完成而重复打扰你,管线跑完后会主动把卡片推回当前对话。

### 步骤 4:接收并阅读仓库卡片

每张卡片遵循统一的排版,字段含义如下:

- **仓库名**:形如 `owner/repo`,例如 `antirez/kilo`、`sharkdp/bat`。
- **⭐ 星标数**:仓库当前的 Star 数量,例如 `⭐ 3.2k`、`⭐ 50.0k`。
- **👤 作者**:仓库 Owner 的用户名,例如 `antirez`、`sharkdp`。
- **简介**:用中文对仓库用途做的简短概括,便于快速判断是否值得深入。
- **标签**:以 `#` 开头的关键词,例如 `#trending`、`#c`、`#editor`,可用于粗筛方向。
- **🗂 链接**:卡片底部的 `<a href="…">` 即原 GitHub 仓库地址,点击即可跳转查看源码、README 和 Issues。

### 步骤 5:再次请求,验证秒回

当你已经拿到过一次当日榜单后,在同一天内再次发送 `/trending`,Bot 会直接走缓存分支,跳过生成步骤,几乎瞬间把同样的卡片再发一次,适合重复查看或分享给同事。

### 小贴士

- 首次当日请求可能需要 10-30 秒,这是后台在抓取并翻译所有仓库;之后重复触发就是秒回,建议先发一次,后续慢慢看。
- 卡片使用编号 `n/N` 标识,例如 `2/2` 表示当日共 2 张卡、当前是第 2 张,方便你确认有没有漏看。
- 若长时间(超过 30 秒)只看到占位消息而没有后续卡片,可在对话中再发一次 `/trending` 触发重试,或联系 Bot 管理员查看管线日志。
