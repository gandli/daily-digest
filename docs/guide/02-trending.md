# /trending — 今日 GitHub Trending

通过本命令,可以一键获取当天 GitHub Trending 榜单,内容包含仓库简介、标签、作者及链接,帮助快速发现值得关注的项目。系统内置缓存机制,常用查询可实现秒级返回。

### 步骤 1: 发送触发命令

在 Bot 对话框中输入斜杠命令触发查询。命令格式为:

- `/gt`:查询今日 GitHub Trending

发送后,Bot 会立即响应两条消息:

1. 一条提示当前正在抓取数据,文案为 `⏳ GitHub Trending 生成中(10-30 秒), 完成后自动推送。`
2. 随后按顺序推送本次榜单,每条消息对应一个仓库,序号格式为 `n/N`,其中 n 为当前条数、N 为总条数。

### 步骤 2: 首次触发时的占位与异步生成

首次发起查询时,缓存通常未命中,Bot 会先返回占位消息,告知用户进入生成流程。后台会按以下顺序执行完整管线:

- 抓取当日 GitHub Trending 页面数据
- 对仓库描述进行翻译处理
- 将结果写入存档,供下次快速返回
- 完成后自动推送卡片消息

从用户视角看,整个过程透明,无需手动干预。

### 步骤 3: 查看返回的仓库卡片

每条仓库卡片包含以下信息:

- 序号 `n/N`:例如 `1/2`、`2/2`,便于判断是否已收齐
- 仓库路径:形如 `antirez/kilo`
- Star 数:以 `⭐` 前缀展示
- 作者:`👤` 后接 GitHub 用户名
- 简介:经翻译后的中文描述
- 标签:以 `#` 开头的关键词,例如 `#trending`、`#c`、`#editor`
- 链接:通过 `🗂` 后接 `<a href="...">` 提供原始仓库地址

### 步骤 4: 二次触发享受缓存加速

当首次查询完成后,数据已写入缓存。再次发送 `/gt` 时,Bot 不再返回 `⏳ 生成中` 占位消息,而是直接推送已存档的卡片,响应速度为秒级。这种设计既避免了重复抓取对 GitHub 的压力,也为用户提供更流畅的体验。

二次触发的快速返回效果,可参考下图:

### 步骤 5: 识别完成与处理异常

- 若先收到 `⏳ 生成中` 占位消息,再收到 `1/N`、`2/N` 形式的卡片,说明首次走通了完整管线。
- 若仅收到 `⏳ 生成中` 占位消息、未见后续卡片,可能是网络或上游异常,可稍后重试 `/gt`。
- 若仅收到部分卡片(例如只有 `1/2`),可再次发送 `/gt` 触发一次,系统会从缓存补齐剩余条目。

## 小贴士

- 常用 `/gt` 的用户,建议在固定时间(例如每天早晨)发起一次,首次走完整管线,后续一天内的查询均可享受秒级缓存返回。
- 卡片中的标签以 `#` 开头,便于快速识别仓库所属领域(如 `#c`、`#editor`),可用于筛选关注方向。
- 仓库链接通过 `🗂 <a href="...">` 提供,在支持 HTML 渲染的客户端中可直接点击跳转,无需手动复制域名拼接路径。
