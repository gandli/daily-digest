# /trending — 今日 GitHub Trending

## 概述

`/trending`（也支持简写 `/gt`）用于拉取当天的 GitHub Trending 仓库列表，并以精炼卡片的形式推送到聊天窗口。Bot 内部维护一份缓存：缓存命中时秒回卡片；缓存未命中时先回一条占位提示，后台再跑抓取→翻译→存档→发卡的完整流水线。

## 逐步操作

### 步骤 1：发送触发命令

在 Bot 对话窗口输入 `/trending` 或其简写 `/gt`，然后发送。

### 步骤 2：等待首次占位提示（仅缓存未命中时）

如果当日尚未生成过 Trending 列表，Bot 会立即返回一条「⏳ 生成中」提示，告知用户预计需要 10–30 秒。无需重复发送命令，生成完成后 Bot 会自动将卡片推送到当前聊天。

> Bot 回执示例：
> `⏳ GitHub Trending 生成中(10-30 秒), 完成后自动推送。`

随后后台依次完成抓取 GitHub Trending 页、翻译仓库描述、写缓存、向当前会话发送卡片等动作。

### 步骤 3：接收 Trending 卡片

流水线完成后，Bot 会按 `当前排名 / 当日总数` 的格式逐条推送卡片，例如 `1/2`、`2/2`。每张卡片包含以下字段：

- `仓库全称`：形如 `antirez/kilo`，对应 GitHub 仓库链接。
- `⭐ Star 数`：以 k 为单位的当日热度，例如 `⭐ 3.2k`、`⭐ 50.0k`。
- `👤 作者`：仓库所有者昵称。
- `简介`：一句话中文摘要，概括仓库的主要用途与亮点。
- `#话题标签`：例如 `#trending`、`#c`、`#editor`，便于按主题筛选。
- `🗂 链接`：卡片底部的 GitHub 仓库直链，点击即可跳转。

### 步骤 4：再次发送复用缓存

由于步骤 2 中已将当日结果写入缓存，再次在同一聊天中发送 `/gt` 时，Bot 会跳过抓取与翻译，直接返回上一次的卡片列表，因此响应几乎是即时的，不再出现「⏳ 生成中」提示。

## 小贴士

- 不要在看到占位提示后反复发送 `/gt`。同一聊天窗口当日只需要触发一次，后台任务完成后 Bot 会自动推送卡片；重复发送只会命中缓存，徒增消息噪音。
- 想了解每个标签对应的仓库类型，可以留意卡片中的 `#话题标签` 字段，例如 `#c`、`#editor`、`#trending`，便于快速判断是否值得点击。
- 卡片中以 `k` 为单位的 Star 数反映的是当日热度，而非仓库的总 Star 累计量；判断项目成熟度时，建议结合仓库主页的累计 Star 与更新时间综合评估。
