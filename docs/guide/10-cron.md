## 每日自动推送(cron)

本章介绍 Bot 的定时任务功能:系统会在每天北京时间 08:30 自动触发抓取、翻译、存档、推送流程,并执行仓库描述相关的维护任务,使用者无需手动操作即可收到当日热门仓库推荐。

### 步骤 1:确认时区与触发时间

确保 Bot 配置文件中时区设置为 `Asia/Shanghai`(北京时间)。系统会在每天 08:30 自动执行一次完整的推送事务,无需用户发送任何指令。事务依次完成:抓取当日 trending 仓库、翻译描述、写入存档、推送到订阅会话,随后运行 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务以保证描述数据完整。

### 步骤 2:等待自动推送

08:30 时刻到达后,Bot 会自动在已绑定的会话中按序号逐条推送当日仓库。推送内容包含仓库名、Star 数、作者、翻译后的简介、相关话题标签以及存档链接,格式示例如下:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">...</a>

### 步骤 3:确认多条结果连续到达

由于 cron 事务会推送当日所有符合条件的仓库,Bot 会按 `1/N`、`2/N` … 的形式连续发出 N 条消息。请耐心等待直到编号抵达 `N/N`,即代表当日推送已完成。

### 步骤 4:核查推送结果

收到推送后,使用者可点击消息末尾的存档链接,跳转至存档页面核对翻译内容与原仓库信息是否一致;若发现翻译异常或描述缺失,通常由随后的 `refreshLookupDescriptions` / `backfillDescriptions` 在下一次触发前自动修复。

### 步骤 5:如未收到推送,排查 cron

若 08:30 后仍未收到任何消息,建议先确认 Bot 进程处于运行状态,随后检查调度器日志中是否出现 `scheduled trigger` 字样以及对应时间戳,以此判断事务是否成功入队。

### 小贴士

- 推送窗口固定为北京时间 08:30,若所在时区不同,请以 `Asia/Shanghai` 时间为准,避免错过当日内容。
- 维护任务 `refreshLookupDescriptions` 与 `backfillDescriptions` 与推送并行执行,首次部署或新增大量仓库后,完整回填可能需要数次 cron 周期才能收敛。
- 建议将常用会话(如个人频道或群组)设置为默认推送目标,这样每日多条消息会自动汇聚到同一位置,便于回溯与检索。
