### 步骤 1：等待每日 08:30（北京时间）定时触发

你无需在 Bot 内执行任何命令，只需让 Bot 保持运行状态。每天早晨 08:30（北京时间），内置的定时任务会自动唤醒并开始处理流程。该触发由调度器接管，即使本地电脑处于待机或闲置状态，云端也会按计划执行。首次使用前，建议确认 Bot 实例处于在线状态，并在管理面板中查看 cron 表达式 `0 30 8 * * *` 是否启用（对应 Asia/Shanghai 时区）。

### 步骤 2：观察 Bot 自动完成「抓取 → 翻译 → 存档」流水线

触发后，Bot 会先从 GitHub Trending 与 Product Hunt 等数据源抓取当日热门项目，随后调用翻译接口将描述转为中文，并写入本地存档库。整个过程无需人工干预，你只需留意控制台或日志面板是否出现异常条目（例如连续 403、超时等）。

### 步骤 3：接收每日推送消息

抓取与处理完成后，Bot 会按 1/2、2/2 的格式依次发送当日的热门仓库卡片，每条消息包含仓库路径、Star 数、作者、简介、标签与跳转链接。例如本轮你将看到 `antirez/kilo` 与 `sharkdp/bat` 两条结果：

1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂
2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂

### 步骤 4：处理可选的拉取失败提示

若某个上游接口（如 Product Hunt）抓取失败，Bot 会紧随推送列表发送一条警告，例如：

⚠️ Product Hunt 拉取失败，请稍后再试。

这是预期内的容错行为，不影响 GitHub Trending 主流程的推送结果。你可在稍后通过手动指令补拉，或等待次日自动重试。

### 步骤 5：自动执行维护任务

推送结束后，Bot 会在后台静默调用 `refreshLookupDescriptions` 与 `backfillDescriptions` 两个维护任务。前者用于刷新语言/标签查询缓存，后者负责补齐历史缺失的翻译条目。这些任务同样无需你操作，但其执行日志可在「系统日志 → 维护任务」中查阅，便于追踪翻译覆盖率。

## 小贴士

- **时区确认**：cron 触发时间以 Asia/Shanghai 为基准；如你身处海外，08:30 推送对应本地时间会偏移，注意按目标时区安排阅读。
- **失败提示 ≠ 整体失败**：看到 Product Hunt 拉取失败警告时，请优先关注 GitHub Trending 列表是否完整；可使用 `/retry ph` 单独重试该数据源。
- **维护任务不可手动取消**：`refreshLookupDescriptions` 与 `backfillDescriptions` 在推送后立即启动，若推送时段 Bot 负载较高，可在 `/settings` 中将维护任务调度到凌晨低峰窗口。
