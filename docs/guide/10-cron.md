### 步骤 1:确认 Bot 已加入目标频道/群组

在等待 08:30(北京时间)自动推送之前,请确保 Bot 已经被添加为你要接收每日推送的频道或群组成员,并授予其发送消息的权限。若 Bot 不在目标会话中,定时任务会正常触发,但消息无处投递,造成任务"看似失败"的假象。

### 步骤 2:等待每日 08:30 定时触发

无需任何手动操作。系统会在每天北京时间 08:30 由 scheduled 任务自动启动,执行顺序为:新鲜抓取(拉取 GitHub Trending 仓库)→ 翻译(将仓库描述翻译为中文)→ 存档(将数据写入历史库)→ 推送(向已配置的目标会话发送消息)。与此同时,系统还会并行执行 refreshLookupDescriptions 与 backfillDescriptions 两个维护任务,用于刷新查表描述与补齐历史缺失条目。

### 步骤 3:接收每日推送消息

定时触发完成后,Bot 会按顺序向目标频道/群组逐条发送当日抓取到的 Trending 仓库,每条消息包含仓库名、Star 数、作者、翻译后的中文简介、相关话题标签以及跳转链接。例如当天会依次看到:

- `1/2 antirez/kilo ⭐ 3.2k 👤 antirez` — 该仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。`#trending #c #editor`
- `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp` — 该仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。`#trending`

消息的 `N/M` 前缀表示当天共抓取到 M 条,当前为第 N 条,便于按序阅读。

### 步骤 4:点击链接查看仓库详情

每条消息末尾都附带了对应的 GitHub 仓库链接(在支持渲染的客户端中以锚文本形式呈现,例如 `<a href="https:…">`),直接点击即可跳转到对应仓库页面,无需手动复制粘贴。

### 步骤 5:核对维护任务是否正常执行

如果你在频道中拥有查看 Bot 日志或管理面板的权限,可以在每日首次推送后留意 refreshLookupDescriptions 与 backfillDescriptions 两个维护任务的执行状态。这两个任务在推送流水线中并行运行,负责刷新翻译查表与回填历史缺失描述,长期保证推送内容的完整性与一致性。

---

**小贴士**

- **时区确认**:所有定时推送均以北京时间(UTC+8)为准,若你身处其他时区,请自行换算实际接收时间。
- **数量不一定为 2**:示例中展示了 2 条记录,实际每日条目数取决于当天 GitHub Trending 的抓取结果,可能多于或少于 2 条,`N/M` 中的 M 会随之变化。
- **静默期不一定是故障**:若某天未收到推送,请先检查 Bot 是否仍在目标会话中、是否被禁言或踢出,再排查任务调度日志。
