### 每日自动推送（cron）

本章节介绍 Bot 的定时推送功能。每天 08:30（北京时间），Bot 会自动触发一系列后台任务，把最新抓取到的热门仓库经过翻译整理后推送给订阅用户，整个过程无需任何手动操作。

### 步骤 1：等待定时触发

用户无需执行任何命令，只需确保 Bot 处于在线运行状态即可。每天 08:30（北京时间），Bot 会按照预定计划自动唤醒，开始执行后台任务。

后台任务包括：

- 新鲜抓取：从数据源获取当日热门仓库列表
- 翻译：对仓库描述进行中文翻译处理
- 存档：将翻译结果持久化保存
- 推送：把整理好的内容发送到订阅频道或群组
- 维护任务：执行 refreshLookupDescriptions 与 backfillDescriptions，刷新与回填仓库描述缓存

### 步骤 2：接收自动推送内容

定时任务执行完毕后，Bot 会将当日的热门仓库依次推送给用户。推送内容包含仓库名称、Star 数量、作者、中文简介、话题标签等关键信息。

例如，Bot 会按编号逐条发送类似以下格式的消息：

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">...</a>
> 
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href="...">...</a>

格式 `当前序号/总条数` 便于用户清晰了解本次推送的总量。实际推送的截图示例如下：

### 步骤 3：无需手动确认

推送完成后，Bot 不要求用户进行任何回执或确认操作。用户可直接阅读推送内容，或点击消息中的链接跳转至对应的 GitHub 仓库页面查看详情。如果 Bot 连续多天未发送推送，请联系管理员检查 Bot 进程状态或定时任务配置。

### 小贴士

- 定时推送以「北京时间」为准，若你身处其他时区，请注意换算 08:30 对应的本地时间。
- 单次推送通常包含多条仓库信息（示例中为 2 条），请耐心等待全部内容发送完毕。
- 后台的 refreshLookupDescriptions 与 backfillDescriptions 维护任务在推送期间静默运行，用于保障描述翻译的质量与完整性，无需用户介入。
