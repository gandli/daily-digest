## 每日自动推送(cron)

本章介绍如何让 Bot 按照预定时间,自动完成「抓取 → 翻译 → 存档 → 推送」的全链路流程,以及在后台运行的描述维护任务。

### 步骤 1:理解触发规则

每天 08:30(北京时间),Bot 的定时任务(scheduled cron)会自动唤醒,无需人工干预。唤醒后 Bot 会依次执行:新鲜抓取最新热门项目、对摘要进行翻译、写入历史存档、推送给订阅用户,最后异步运行 `refreshLookupDescriptions` 与 `backfillDescriptions` 等维护任务,补齐和刷新仓库描述字段。

### 步骤 2:查看自动推送结果

08:30 之后,在与 Bot 的对话窗口中,即可看到当天自动发出的推送消息。Bot 会按 `1/2`、`2/2` 的序号逐条列出抓取到的仓库,每条包含仓库名(如 `antirez/kilo`)、Star 数、作者、翻译后的中文简介以及话题标签,并附上链接。例如:

> `1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂 <a ...>`
>
> `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending 🗂 <a ...>`

### 步骤 3:留意告警提示

如果当天某个外部数据源暂时不可用,Bot 会在推送末尾追加一行告警,例如:

> ⚠️ Product Hunt 拉取失败,请稍后再试。

此时该渠道的内容会被跳过,但其他渠道(例如 GitHub Trending)的推送依然正常送达。告警属于一次性提示,无需用户回复,下次 cron 触发时会自动重试。

### 步骤 4:确认维护任务静默运行

推送完成后,Bot 在后台继续执行 `refreshLookupDescriptions` 与 `backfillDescriptions` 这两个维护任务,用于刷新查找表中的描述字段、并向历史存档中缺失描述的仓库回填信息。这两个任务不会向用户推送消息,只在内部数据库中生效,因此你在聊天窗口中看不到它们的反馈——这是正常现象,说明历史数据正在被持续校正。

### 小贴士

- 时区敏感:推送时间固定为北京时间 08:30,身处其他时区的用户可据此换算本地接收时间。
- 告警 ≠ 失败:看到「⚠️ XX 拉取失败」时,说明只是单个数据源异常,其他渠道的推送不受影响,无需额外操作。
- 想手动补发:若错过 08:30 的推送或希望提前查看,可使用 `/trending` 等即时命令,效果与 cron 推送一致。
