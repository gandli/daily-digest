### 每日自动推送（cron）

本章介绍 Bot 的定时自动推送功能。每天北京时间 08:30，Bot 会自动唤醒，按顺序执行抓取、翻译、存档、推送以及索引维护等一系列任务，无需您手动干预。

### 步骤 1：等待定时触发

您无需执行任何操作。每天 08:30（北京时间）到达后，Bot 内部的 cron 调度器会准时唤醒本次推送任务。在触发之前，您可以正常关闭客户端或进行其他工作。

### 步骤 2：接收推送内容

任务唤醒后，Bot 会依次向您发送当日抓取并翻译好的仓库卡片。每条卡片包含仓库名、Star 数、作者、简介、标签以及跳转链接。例如，本次推送依次发送了两张卡片：

> `1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂`
>
> `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂`

您可以点击卡片末尾的链接直接访问 GitHub 仓库。

### 步骤 3：关注异常提示

抓取过程中若遇到外部平台异常，Bot 会在推送末尾追加一条警告。例如本次就附带了一条：

> `⚠️ Product Hunt 拉取失败，请稍后再试。`

看到此类提示时无需慌张，它仅代表当次 Product Hunt 数据源拉取未成功，其他来源（如 GitHub Trending）的卡片依然正常送达。

### 步骤 4：忽略后台维护任务

除可见的推送外，Bot 还会自动运行 `refreshLookupDescriptions` 和 `backfillDescriptions` 两个维护任务，用于刷新和回填仓库描述缓存。这些任务在后台静默执行，您不会收到任何额外消息，但其结果会体现在下一次推送的描述质量上。

### 小贴士

- **时区说明**：cron 时间以服务器时区为准，本文档中标注的 08:30 指北京时间（UTC+8），如您位于其他时区，请按相差小时数推算实际送达时间。
- **失败重试**：若收到 `⚠️ 拉取失败` 提示，无需重复触发；下一日 08:30 会自动重试，您也可手动发送对应命令拉取当天的内容。
- **维护任务可见性**：`refreshLookupDescriptions` 与 `backfillDescriptions` 仅维护描述缓存，不影响推送数量与顺序，您不必为这两项任务执行任何操作。
