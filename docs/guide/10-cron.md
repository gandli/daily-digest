# 每日自动推送（cron）

本章节介绍如何启用由后台定时任务（cron）驱动的每日自动推送功能。每天 **北京时间 08:30**，Bot 会自动执行"抓取 → 翻译 → 存档 → 推送"的完整链路，并在推送结束后运行 `refreshLookupDescriptions` / `backfillDescriptions` 维护任务，刷新仓库描述缓存。下面按时间顺序逐步说明用户侧的操作与 Bot 行为。

### 步骤 1: 等待定时触发（无需手动操作）

cron 在每天 08:30 自动唤醒任务。用户此时无需发送任何指令，Bot 会在后台开始拉取当日榜单并完成翻译与存档。

### 步骤 2: 接收首批推送结果

任务完成后，Bot 会按照队列顺序逐条向用户推送当日上榜的仓库消息。典型消息包含仓库序号、名称（`owner/repo`）、星标数、维护者、简介、相关标签，以及外链与归档链接。例如：

> **Bot**: `1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href=…>`
>
> **Bot**: `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href=…>`

推送分页以 `n/total` 的形式编号，便于用户核对条目数量。下图展示了 Bot 真实推送的样式：

### 步骤 3: 阅读与跳转

用户点击消息末尾的链接（`href`）即可跳转至对应仓库页面，或查看 Bot 自动生成的归档详情。每条消息都附带了星标数与维护者信息，方便快速判断仓库热度与可信度。

### 步骤 4: 接收维护任务日志（隐式步骤）

在推送流程结束后，Bot 会静默执行 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务，更新仓库描述缓存。用户不会收到额外的干扰消息，但下次手动查询时会自动命中最新描述，无需手动触发。

### 步骤 5: 故障感知

若 cron 在执行过程中失败，Bot 会按既有告警通道发出提示（参考"消息可靠性"章节）。用户可据此选择是否手动重跑当日推送。

---

## 小贴士

- **保持时区一致**：cron 以 **北京时间** 触发。若你在其他时区，请将本地时间与北京 08:30 进行换算，避免错过首条推送。
- **消息分页耐心阅读**：当日上榜数量较多时，Bot 会以 `n/total` 形式逐条发送，请勿在看到 `1/2` 时误以为推送已中断。
- **点击归档链接可补看历史**：即使错过了 08:30 的实时推送，也可在每条消息末尾的归档链接中找回当天所有条目。
