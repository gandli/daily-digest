### 步骤 1: 等待定时任务自动触发

每天 08:30(北京时间),Bot 会自动运行定时任务,无需用户执行任何手动操作。任务会按顺序执行:抓取 GitHub Trending 仓库 → 翻译描述 → 归档到 Notion 数据库 → 推送消息到 Telegram 频道 → 执行 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务。

### 步骤 2: 查看推送内容

定时任务完成后,Bot 会自动向频道推送当日抓取结果。用户无需发送任何指令,只需打开 Telegram 频道即可看到类似如下格式的推送:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">链接</a>
>
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending 🗂 <a href="...">链接</a>

每条消息包含仓库序号、仓库名、星标数、作者、翻译后的中文描述、话题标签以及原始链接。用户点击链接即可跳转到对应 GitHub 仓库。

### 步骤 3: 关注告警信息

如果某个数据源(例如 Product Hunt)抓取失败,Bot 会在推送末尾附带一条告警提示,例如:

> ⚠️ Product Hunt 拉取失败, 请稍后再试。

此时 GitHub 部分仍会正常推送,Product Hunt 部分会被跳过。Bot 会自动重试,用户无需手动介入,但可以留意告警频率——若连续多天出现,可联系管理员检查上游接口状态。

## 小贴士

- **时区确认**:定时任务按北京时间(UTC+8)08:30 执行。身处其他时区的用户请自行换算接收时间。
- **失败不阻塞主流程**:即使 Product Hunt 抓取失败,GitHub Trending 推送与 Notion 归档仍会照常完成,维护任务也会继续执行。
- **手动重跑**:若错过推送或需补跑当日数据,可使用「补发命令」章节中的指令手动触发,但请避免与定时任务同时执行,以免产生重复归档。
