## 每日自动推送（cron）

本章节说明 Bot 每天定时自动运行的工作流：按照计划任务在指定时间抓取 GitHub Trending 仓库，翻译描述、维护元数据，并推送到订阅频道。整个流程由 Bot 后端自动完成，使用者无需手动触发。

### 步骤 1：了解推送时间

Bot 配置了 scheduled 任务，每天北京时间 08:30 自动触发，无需任何手动操作。事务包含四个环节：抓取新鲜 Trending 数据、对仓库描述进行翻译、存档历史快照、推送当天的精选结果到频道。此外还会顺带执行 refreshLookupDescriptions 与 backfillDescriptions 两个维护任务，用于刷新和补全描述缓存。

### 步骤 2：查看推送结果

到了 08:30，Bot 会把当日 Trending 中排名靠前的仓库逐条推送到频道。推送样式与每日自动推送的格式一致，按 `序号/总数 owner/repo ⭐ Star数 👤 作者` 的形式呈现，紧接着是翻译后的中文描述、话题标签以及原始链接。

例如，频道中会看到类似下面的两条推送：

`1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a …`

`2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href="https:…`

每天推送的总条数取决于当日 Trending 的上榜数量，每条之间用换行分隔，方便阅读与复制链接。

### 步骤 3：核对维护任务是否完成

推送结束后，Bot 后端会继续执行 refreshLookupDescriptions 和 backfillDescriptions。这两个任务不直接对用户可见，但会影响后续查询的体验：如果某个仓库的描述在缓存中缺失，下一次手动 `查询仓库` 时会自动补全；若描述过时，刷新任务会在后台静默更新到最新版本。验证方式是过几分钟后对同一条仓库再次发起查询，观察返回描述是否与 GitHub 原文一致。

### 小贴士

- 推送时间为固定北京时间 08:30，如需调整请通过 Bot 配置接口修改 cron 表达式，重启后生效。
- 推送内容与频道订阅状态绑定，未将 Bot 拉入目标频道的用户不会收到消息。
- 若某天未收到推送，可先在频道中搜索最近 24 小时的 Trending 消息，确认是否因频道被静音或 Bot 掉线导致。
