## 每日自动推送(cron)

本章介绍 Bot 的定时推送功能。每天固定时刻,Bot 会自动完成「抓取 → 翻译 → 存档 → 推送」全链路,并在推送期间运行 refreshLookupDescriptions 与 backfillDescriptions 等维护任务,确保描述库的完整性。

### 步骤 1:了解触发时机

Bot 已配置定时任务,每天 **北京时间 08:30** 自动触发 scheduled 推送。无需任何手动命令,只要 Bot 处于运行状态,推送就会按计划执行。该 cron 由后端调度器维护,使用者无需关心底层实现。

### 步骤 2:观察自动推送内容

触发时刻到达后,Bot 会依次推送当天的热门仓库,每条消息按「序号/总数 + 仓库名 + Star 数 + 作者 + 描述 + 标签 + 链接」的格式输出。例如:

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。#trending #c #editor 🗂
>
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。#trending 🗂

推送过程中,后端会并行执行翻译、存档、refreshLookupDescriptions 与 backfillDescriptions 维护任务,使用者只需静静等待即可。

### 步骤 3:处理异常提示

若某外部数据源(如 Product Hunt)当日不可用,Bot 会推送一条警告消息,例如:

> ⚠️ Product Hunt 拉取失败,请稍后再试。

看到此类提示时无需慌张,其他源的推送通常仍会正常完成。如果连续多天出现同类告警,可联系运维排查。

### 步骤 4:查看历史推送

如需回顾过往推送内容,可通过 `/archive` 或历史命令查询已存档的每日汇总,存档在步骤 2 的流水线中已自动落库。

### 小贴士

1. **时区确认**:cron 使用 **北京时间(UTC+8)**,若你在其他时区,请按北京时间 08:30 估算本地接收时间。
2. **告警不等于失败**:Product Hunt 等单一源失败时,其他源的推送不受影响,不要误以为整个任务中断。
3. **维护任务静默运行**:refreshLookupDescriptions 与 backfillDescriptions 在推送窗口内后台执行,无需额外指令,长期使用下描述库会越来越准确。
