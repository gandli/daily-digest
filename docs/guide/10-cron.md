### 每日自动推送（cron）

本章介绍 Bot 内置的定时任务功能：每天北京时间 08:30，Bot 会自动执行一次「热门仓库抓取 → 中文翻译 → 存档 → 推送」的完整流水线，并附带 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务，确保历史数据也保持最新。

### 步骤 1：确认 Bot 已启用定时任务

**用户**：无需任何手动操作。Bot 在部署时已默认开启 cron 调度器。

**Bot**：保持静默，等待预定时间到达。

> 该任务由系统级调度器在每天 08:30（UTC+8）自动触发，不依赖用户发送任何指令。

### 步骤 2：等待 08:30 自动触发

**用户**：在 08:30 之前进入与 Bot 的对话窗口。

**Bot**：到达预定时间后，开始执行抓取与翻译流水线。此过程对用户透明，通常持续数秒到数十秒。

### 步骤 3：接收自动推送结果

**用户**：保持 Bot 窗口开启，或在事后翻阅消息记录。

**Bot**：按 1/2、2/2 的分页格式依次推送当日抓取并翻译完成的热门仓库，每条消息包含仓库名（如 `antirez/kilo`）、Star 数、作者、简介中文译文、话题标签（`#trending`、`#c`、`#editor` 等）以及分类图标（🗂 等）和外部链接。

![每日 08:30 自动推送的热门仓库列表](assets/10-cron-r1.png)

### 步骤 4：阅读并访问仓库

**用户**：点击消息中嵌入的 `<a href="…">` 链接，或直接复制仓库全名（如 `antirez/kilo`、`sharkdp/bat`）前往 GitHub 查看源码。

**Bot**：无后续回复，推送任务结束。

### 步骤 5：后台维护静默进行

**用户**：无需介入。

**Bot**：在推送主流程完成后，调度器继续在同一事务内执行 `refreshLookupDescriptions`（刷新查找表中的描述缓存）与 `backfillDescriptions`（补齐历史缺失的翻译条目）两个维护任务，全程静默运行，不打扰用户。

---

### 小贴士

- **时区说明**：cron 表达式使用 `TZ=Asia/Shanghai`，请勿按 UTC 时间推算；08:30 即北京时间清晨，醒来即可在消息列表中查看当日精选。
- **错过推送怎么办**：所有推送结果都会在对话窗口中持久保留，直接向上滑动即可查阅历史每日清单；若有链接无法点击，仓库名以 `owner/repo` 形式给出，可手动拼接 `https://github.com/` 前缀访问。
- **手动触发区别**：若想立即获取而非等待定时任务，可使用「立即抓取」相关命令（详见对应章节），但 cron 推送是唯一会同时执行 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务的入口，建议保留定时任务开启以维持数据完整性。
