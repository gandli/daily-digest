## 每日自动推送（cron）

本章介绍 Bot 的定时推送功能。每天 08:30（北京时间），Bot 会自动执行一次「抓取 → 翻译 → 存档 → 推送」的完整链路，把当日 GitHub Trending 仓库送到你的会话里，同时在后台运行描述信息的维护任务。

### 步骤 1：等待定时触发

用户无需任何手动操作。Bot 按照服务器 cron 计划，在每天北京时间 08:30 自动启动一次推送事务。该事务会依次完成四件事：

1. 抓取 GitHub Trending 当日榜单
2. 调用翻译服务生成中文简介
3. 将原始与翻译结果写入存档库
4. 调度 refreshLookupDescriptions 与 backfillDescriptions 维护任务，补齐仓库描述信息

### 步骤 2：接收推送消息

定时触发后，Bot 会按榜单顺序逐条推送仓库卡片。每条卡片包含仓库名、星标数、作者、中文简介、话题标签以及跳转链接，格式形如：

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">

当存在多条记录时，Bot 会自动编号（`1/2`、`2/2` …），保证接收顺序与榜单一致。

### 步骤 3：处理抓取告警

由于依赖的外部源（如 Product Hunt）可能偶发不可用，Bot 在检测到抓取失败时，会在推送末尾附加一条告警，例如：

> ⚠️ Product Hunt 拉取失败，请稍后再试。

收到此类告警无需惊慌：GitHub Trending 主体推送不会受影响，仅表示对应数据源当日缺勤，可在稍后手动补查。

### 步骤 4：查看维护任务执行情况

推送事务结束后，refreshLookupDescriptions 与 backfillDescriptions 会在后台异步运行，刷新或回填仓库描述字段。该过程对用户透明，无需干预；若在后续手动查询时发现某仓库简介缺失或陈旧，正是这些任务在逐步收敛的结果。

---

### 小贴士

1. **时区以北京时间为准**：cron 表达式锚定 Asia/Shanghai，若你身处其他时区，注意 08:30 对应的当地时间，避免错过推送窗口。
2. **告警 ≠ 推送失败**：Product Hunt 等第三方源告警仅影响该源数据，GitHub 榜单照常送达；如需重试，可在告警后等待下一次手动触发或联系管理员。
3. **历史可追溯**：所有原始与翻译结果都会落入存档库，若 08:30 推送时不便阅读，可随时通过「查询历史」相关命令回看当日完整榜单。
