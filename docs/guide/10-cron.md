### 每日自动推送（cron）

本章节介绍 Bot 每日定时自动推送功能的完整流程。每天北京时间 08:30，Bot 会自动执行抓取、翻译、存档、推送等任务，无需任何人工干预。配合维护任务，仓库描述会持续保持新鲜与准确。

### 步骤 1：等待定时触发

用户无需执行任何操作。Bot 已配置好 cron 表达式，会在每天 **08:30（北京时间）** 自动唤醒并开始工作。如果当前时间尚未到 08:30，Bot 处于静默状态，不会有任何输出。

### 步骤 2：接收每日推送

08:30 到点后，Bot 会依次将当日上榜的热门仓库推送到对话窗口。每条消息以「序号/总数 仓库路径 ⭐ 星标数 👤 作者」开头，紧接着是该仓库的翻译介绍与话题标签（#trending 等），末尾附上 HTML 锚链接方便跳转。多个仓库会按 1/N、2/N 的方式分条发送。

### 步骤 3：后台静默维护

推送完成后，Bot 会在后台继续执行两个维护性任务：`refreshLookupDescriptions` 负责刷新本地查表缓存中的描述字段，`backfillDescriptions` 会回填历史仓库中缺失的描述。这两个任务不会向用户发送任何消息，属于静默运行，目的是保证后续查询与推送内容的完整性。

### 步骤 4：核查当日结果

用户可以打开推送消息，逐条点击末尾的链接跳转到 GitHub 仓库页面验证内容。如果发现某条翻译存在疑问或想了解历史推送，可在对话窗口中直接发起查询指令，Bot 会从已存档的数据中返回结果。

## 小贴士

- 推送窗口为每天 08:30（北京时间），若错过可手动触发一次补推，也可直接查询当日 trending 列表。
- 维护任务（refreshLookupDescriptions、backfillDescriptions）仅在后台运行，**不会**发送消息，请勿因没有新消息而误判 Bot 失联。
- 推送格式中 `1/N`、`2/N` 的分母 N 表示当日上榜总数，便于快速判断是否完整收到当日内容。
