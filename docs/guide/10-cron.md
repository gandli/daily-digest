## 每日自动推送（cron）

Bot 内置定时任务调度,会在每天 **北京时间 08:30** 自动执行一次完整的工作流:从 GitHub 抓取当日热门仓库、对描述进行翻译润色、写回存档数据库,然后以两条一组的消息推送到你的聊天窗口。与此同时,Bot 还会顺带执行 `refreshLookupDescriptions` 与 `backfillDescriptions` 两项维护任务,确保翻译缓存与历史回填数据始终是最新的。整个过程无需你手动干预,适合希望每日醒来就能直接看到精选内容的用户。

### 步骤 1: 等待定时触发

每天 08:30(北京时间),Bot 后端的 cron 调度器会准时启动本轮任务。你无需发送任何指令,也不需要提前打开聊天窗口。任务一旦触发,就会进入「抓取 → 翻译 → 存档 → 推送」流水线。

### 步骤 2: 查看自动推送结果

任务完成后,Bot 会向你的对话窗口依次发送两条消息(1/2、2/2),每条对应一个当日热门仓库。每条消息包含以下要素:

- **仓库名称与作者**:例如 `antirez/kilo`、`sharkdp/bat`,带原始链接;
- **Star 数与作者 ID**:例如 ⭐ 3.2k 👤 antirez;
- **中文翻译描述**:由 Bot 翻译并润色后的中文简介,例如「这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言」;
- **话题标签**:自动追加的相关标签,如 `#trending` `#c` `#editor`;
- **归档标记**:消息末尾的 🗂 表示该条目已成功写入存档数据库,后续可被检索或回填引用。

### 步骤 3: 静默运行的维护任务

在主推送流程进行的同时,Bot 还会自动执行两项维护任务:

- `refreshLookupDescriptions`:刷新查找表中的描述缓存,保证下一次抓取时翻译结果一致;
- `backfillDescriptions`:对历史仓库中尚未翻译或翻译缺失的条目进行回填,逐步完善存档库。

这两项任务同样不产生可见消息,属于后台静默执行,不会打扰你的聊天记录。

### 步骤 4: 如需补推,手动触发命令

若你错过了 08:30 的推送,或希望在其他时段立即看到当日内容,可直接向 Bot 发送手动抓取指令(具体命令请参考「指令速查」章节)。Bot 会复用相同的流水线立即执行一次,并在完成后推送与定时任务格式一致的结果。

---

**小贴士**

1. **时区提示**:cron 触发时间固定为北京时间 08:30,若你身处其他时区,请按 UTC+8 换算实际接收时间。
2. **静默维护无需确认**:`refreshLookupDescriptions` 与 `backfillDescriptions` 不会推送消息,如果你在 08:30 之后只看到 2 条仓库消息、没有任何额外提示,这属于正常现象。
3. **存档标记可追溯**:消息末尾的 🗂 是存档成功的视觉信号,带有该标记的条目都已被写入数据库,可用于后续检索与历史回填。
