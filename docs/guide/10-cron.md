# 每日自动推送（cron）

本章节介绍如何启用 Bot 的每日自动推送任务。每天北京时间 08:30，Bot 会自动执行以下工作流：抓取 GitHub Trending 新鲜仓库 → 翻译仓库描述 → 归档至数据库 → 通过 Telegram 推送给你，同时在后台静默运行 `refreshLookupDescriptions` 与 `backfillDescriptions` 两个维护任务，补齐历史数据的描述与翻译。

### 步骤 1: 触发每日 cron 任务

cron 由 Bot 服务端托管，无需你手动运行命令或编写脚本。你只需要在任意时间点向 Bot 发送关键词 `⏰ 每天 08:30(北京时间)自动推送`（也可发送 `cron` 或 `每日推送` 等同义关键词），Bot 便会立刻在当前会话中模拟执行一次当日的工作流，让你预览推送内容。

### 步骤 2: 查看 Bot 推送的当日仓库列表

Bot 会按"热门度从高到低"分条推送当日抓取到的 Trending 仓库，每条消息包含三段信息：序号与仓库全称、⭐ Star 数与 👤 作者、`#标签` 与翻译后的中文简介。完整推送示例如下：

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">链接</a>
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href="...">链接</a>

注意"X/Y"中的 Y 表示当日仓库总数；序号 1 代表 Star 数最高，越靠后热度越低。点击每条消息末尾的 🗂 链接可直接跳转到 GitHub 仓库详情页。

### 步骤 3: 等待真实定时触发

手动触发只是预览。真正的定时推送由服务器 cron 守护：每个自然日的 **08:30（Asia/Shanghai）**，Bot 会自动执行完整流程——抓取、翻译、归档、推送，并在结束后静默运行 `refreshLookupDescriptions`（刷新查找表描述）与 `backfillDescriptions`（补齐历史缺失描述）两个维护任务，无需你介入。

### 步骤 4: 查看归档与维护结果

推送完成后，仓库数据已写入数据库。你随时可发送 `📊 统计` 或 `📜 历史` 等关键词查询当日及过往归档；若发现某条仓库描述为空或显示英文原文，说明维护任务尚未补齐，等待次日的 `backfillDescriptions` 即可自动修复。

## 小贴士

- **时区确认**：cron 严格使用 Asia/Shanghai（UTC+8）。如果你的设备时区不同，请以服务器时间 08:30 为准，必要时在系统日历中订阅提醒。
- **重复触发无副作用**：多次发送触发关键词只会产生多条预览消息，不会污染归档表；定时触发的数据带有"定时来源"标记，便于与手动预览区分。
- **维护任务静默执行**：`refreshLookupDescriptions` 与 `backfillDescriptions` 仅更新数据库，不会向你的会话发送任何消息，因此你看不到它们的运行日志，属正常现象。
