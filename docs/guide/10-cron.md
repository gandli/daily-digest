## 每日自动推送（cron）

本章介绍 Bot 在每天 08:30（北京时间）自动执行的抓取、翻译、存档、推送全流程，以及维护任务 `refreshLookupDescriptions` / `backfillDescriptions` 的协同方式。该事务由调度器触发，无需用户手动干预，但用户可以在推送时刻观察 Bot 在群组或私聊中的输出。

### 步骤 1：等待定时任务触发

用户无需执行任何操作。每天 08:30（北京时间），Bot 内部的 cron 调度器会按计划自动唤醒，启动一次完整的「抓取 → 翻译 → 存档 → 推送」流水线。后台会同步启动 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务，用于刷新和回填仓库描述信息。整个过程在用户端是无感的。

### 步骤 2：观察 Bot 输出当日 Top 仓库

定时任务完成后，Bot 会按排名逐条推送当日的热门仓库。每条消息通常包含仓库名、Star 数、维护者、一句话简介、标签，以及跳转链接。例如在一次触发中，Bot 依次输出了：

- `1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。#trending #c #editor 🗂 <a …`
- `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。#trending 🗂 <a href="https:…`

### 步骤 3：留意异常告警

如果某个数据源在本次抓取中失败，Bot 会在推送末尾追加一条告警，明确告知用户是哪个平台出了问题、应当稍后再试。例如本次输出末尾就出现了：

- `⚠️ Product Hunt 拉取失败，请稍后再试。`

看到该提示时，无需回复或重试，Bot 会随下一次定时任务重新尝试拉取。

### 步骤 4：核对推送与维护任务状态

在用户侧，一次健康的 08:30 推送通常满足以下要点：

1. 出现了按 `1/N`、`2/N` 编号的多条仓库消息；
2. 消息中可见仓库名、Star 数、标签和链接；
3. 若存在失败源，会附带 `⚠️` 告警行；
4. `refreshLookupDescriptions` 与 `backfillDescriptions` 在后台静默运行，不会在群内产生噪音。

### 小贴士

- 时区与时间：08:30 以北京时间为准。若你位于其他时区，请自行换算「到达群组」的本地时间。
- 推送失败可观察 `⚠️` 告警：看到告警行说明对应数据源（如 Product Hunt）单次拉取失败，无需重试，等待下次定时任务即可。
- 维护任务透明执行：`refreshLookupDescriptions` 和 `backfillDescriptions` 只在后台更新仓库描述，不会向群组推送消息，因此你不会看到它们的输出。
