## 每日自动推送（cron）

本节介绍 Bot 每天 08:30（北京时间）自动运行的定时推送任务，包括热门仓库的抓取、翻译、存档、推送，以及索引维护等子任务。该任务由 scheduled cron 触发，无需用户手动干预，到点即可收到当日热门仓库摘要。

### 步骤 1：等待定时触发

用户无需任何操作。Bot 会按预设时间表在每天 08:30（北京时间）自动唤醒本次推送流程。系统在后台依次完成新鲜抓取、翻译、存档三道工序，期间请耐心等待片刻。

### 步骤 2：接收当日热门仓库摘要

Bot 会在一个会话中连续推送当日上榜的热门仓库，每条消息以 `n/总数` 的序号开头，依次包含仓库名（如 `antirez/kilo`）、星标数（如 `⭐ 3.2k`）、作者名（如 `👤 antirez`）、一句话简介、相关话题标签（如 `#trending #c #editor`），以及指向详情页的链接 `🗂 <a href="...">`。例如：

`1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="https:...>`

`2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href="https:...>`

所有仓库消息发送完毕后，Bot 会紧接着汇报抓取过程中其他数据源的状态，例如：

`⚠️ Product Hunt 拉取失败，请稍后再试。`

上述三条消息正是每日 08:30 推送时用户会看到的内容，效果如下图所示。

### 步骤 3：留意数据源异常提示

如果在推送末尾看到类似 `⚠️ xxx 拉取失败，请稍后再试` 的告警，说明当天对应数据源（如 Product Hunt）暂时不可用，Bot 已跳过该来源并继续完成其余推送。无需回复或重试，下一个 08:30 任务会自动再次尝试。

### 步骤 4：后台维护任务静默完成

推送结束后，Bot 会在后台自动执行 `refreshLookupDescriptions` 和 `backfillDescriptions` 两项维护任务，用于刷新与补全仓库描述缓存。整个过程对用户不可见，也不会产生任何消息，无需任何操作。

## 小贴士

- **时区以北京时间为准**：cron 表达式已固定为 `30 8 * * *`（北京时间），海外用户请自行换算当地时间，必要时可通过调整服务器时区保证推送落在期望的工作时间窗内。
- **失败提示不是 Bug**：看到 `⚠️ ... 拉取失败` 时不必担心，该信息仅表示某一外部数据源临时不可用，Bot 会按设计继续完成其它来源的推送与维护。
- **维护任务无需手动触发**：索引与描述的刷新、补全已嵌入到每日任务末尾，重复执行 `refreshLookupDescriptions` 或 `backfillDescriptions` 命令并不会带来额外收益，反而可能造成重复写入。
