## 每日自动推送（cron）

本章介绍 Bot 的定时推送能力。每天北京时间 08:30，Bot 会自动按"抓取 → 翻译 → 存档 → 推送"的流程工作，并在推送前后执行仓库描述的维护任务（`refreshLookupDescriptions`、`backfillDescriptions`），保证你看到的简介始终是新鲜且一致的。

### 步骤 1：等待定时触发

你不需要做任何操作，只要 Bot 在线，到点就会自动执行。如果你的客户端开启了通知，Bot 会以"⏰ 每天 08:30（北京时间）自动推送"作为本次推送的标题，让你在消息列表里一眼认出这是定时任务，而不是手动触发的结果。

![定时推送标题示例](assets/10-cron-r1.png)

### 步骤 2：查看自动推送的消息

Bot 会按 1/2、2/2 的格式，依次把当天入选的仓库推送给消息列表，每条消息都包含三部分内容：

- **仓库信息**：以 `用户名/仓库名` 开头，方便你直接识别；
- **简介**：由翻译流水线产出，例如"这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。"——这是 `refreshLookupDescriptions`、`backfallDescriptions` 维护任务保障后的最新版本；
- **标签与链接**：尾部会附带 `#trending` 等话题标签和仓库链接，便于快速打开。

例如本次定时任务就推送了两条消息：1/2 `antirez/kilo` 与 2/2 `sharkdp/bat`，文案结构完全一致。

### 步骤 3：留意异常提示

如果某一路外部数据源暂时不可用，Bot 会单独发出一条警告，例如"⚠️ Product Hunt 拉取失败，请稍后再试。"。这只是说明这一次抓取被跳过，本次推送里与该源相关的仓库会缺失，其它源（如 GitHub Trending）不受影响，可以正常浏览；下一次定时触发通常会自动恢复。

## 小贴士

- 把通知权限给到 Bot，并把"⏰ 每天 08:30（北京时间）自动推送"这条消息**置顶或加星**，第二天上班前打开就能直接扫一遍今日热门仓库。
- 看到"⚠️ XXX 拉取失败"的提示时，无需立刻重试，**等下一个 08:30** 即可；如果连续多天失败，再反馈给管理员排查。
- 翻译后的简介可能与仓库原始 `README` 略有差异，如果你对原始内容感兴趣，可以直接点消息里的仓库链接查看原文。
