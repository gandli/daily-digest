## 每日自动推送(cron)

本章介绍 Bot 配置好的定时任务:每天北京时间 08:30 自动执行「抓取 → 翻译 → 存档 → 推送」完整流程,并在推送间隙穿插 `refreshLookupDescriptions` 与 `backfillDescriptions` 维护任务,确保仓库描述库持续保鲜。你无需手动触发,只要在 08:30 前后保持与 Bot 的对话窗口可用,即可收到当日精选仓库推送。

### 步骤 1:确认定时任务已就绪

打开与 Bot 的私聊或群组,无需发送任何命令。Bot 会在每个工作日 08:30(北京时间)自动开始本轮推送任务。在等待期间,你可以正常关闭聊天窗口,Bot 会在到达时主动向你发送消息。

### 步骤 2:接收首批仓库推送

到达 08:30,Bot 会先输出一条简短的「⏰ 每天 08:30(北京时间)自动推送」横幅,告知你本次定时任务已启动。

![每日 cron 触发后 Bot 自动开始推送](assets/10-cron-r1.png)

紧接着,Bot 会按 `1/N` 的顺序逐条推送当日抓取并翻译好的仓库卡片,每条包含序号、仓库名(形如 `owner/repo`)、星标数、作者名、中文简介以及话题标签。

### 步骤 3:逐条查看翻译结果

在第一条卡片推送完毕后,Bot 会继续推送第二条,格式与第一条完全一致,例如 `2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp ……`。你只需按序号顺序阅读,即可在短时间内掌握 GitHub 当日趋势仓库的中文要点。

### 步骤 4:等待存档与维护任务

所有仓库卡片推送完成后,Bot 会自动在后台执行两项维护任务:

- `refreshLookupDescriptions`:刷新已存在仓库的本地描述缓存,纠正翻译漂移;
- `backfillDescriptions`:补齐历史推送中缺失中文描述的仓库条目。

这两项任务对用户透明,你看不到直接的输出,但它们会让下一次推送的描述更准确、更完整。

### 步骤 5:当日推送结束

存档与维护任务结束后,本轮 cron 流程即告完成。你无需回复任何确认消息。如果当日需要补充查询,可在 Bot 空闲时手动调用搜索命令,与定时推送互不冲突。

### 小贴士

- 建议把 Bot 所在的群组或私聊置顶并开启「消息免打扰(但保留通知)」,这样 08:30 推送既能准时触达,又不会打扰你的早晨。
- 若某日 08:30 之后仍未收到推送,请检查 Bot 的 cron 调度是否被运维重启中断,或直接手动触发一次抓取命令验证连通性。
- 推送顺序按抓取时间排序,想看完整列表可在 Bot 空闲时使用「今日趋势」命令补全历史条目。
