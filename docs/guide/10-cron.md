### 每日自动推送（cron）

本章节介绍 Bot 每日定时自动推送功能的运行方式与典型输出。该任务由调度器在每天 08:30（北京时间）自动触发，无需用户手动干预，即可完成仓库新鲜抓取、翻译、存档、推送等一连串动作，并附带运行刷新查找描述、回填描述等维护任务。

### 步骤 1：等待定时触发

每天 08:30（北京时间），Bot 内部调度器会自动唤起每日推送任务。用户无需在聊天窗口中输入任何指令，Bot 会在任务编排完成后主动向用户所在的频道推送当日内容。

### 步骤 2：查看抓取与翻译结果

Bot 会按"序号/总数 仓库名 ⭐ 星标数 👤 作者"的格式逐条推送仓库简介，并在末尾附带主题标签、分类图标与仓库链接。例如：

> 1/2 antirez/kilo ⭐ 3.2k 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">…</a>
> 2/2 sharkdp/bat ⭐ 50.0k 👤 sharkdp 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending 🗂 <a href="...">…</a>

翻译内容会同时包含仓库简介、原作者信息以及分类标签，便于读者快速浏览当日热门仓库。

### 步骤 3：关注异常提示

若推送过程中部分数据源失败，Bot 会在内容末尾追加一行 ⚠️ 警告，例如：

> ⚠️ Product Hunt 拉取失败，请稍后再试。

此时其他来源（如 GitHub Trending）的仓库仍会正常推送，遇到该提示时请耐心等待下一个执行周期再观察。

### 步骤 4：自动维护后台任务

完成推送后，Bot 会在后台依次执行 refreshLookupDescriptions 与 backfillDescriptions 等维护任务，用于刷新查找表中的仓库描述并补齐缺失字段，整个过程对用户透明，无需任何操作。

### 小贴士

- 推送时间固定为北京时间 08:30，若所在时区不同，可在客户端开启消息免打扰时段，避免清晨收到推送。
- 当看到"⚠️ ... 拉取失败"提示时，表示对应数据源在本次抓取中异常，其他数据源仍然有效，请勿误判为整个功能失效。
- 定时推送由 Bot 内部调度完成，不需要发送任何命令；若希望临时调整频率或来源，可联系管理员修改 cron 表达式与抓取源配置。
