### 步骤 1: 发送网页链接

在 Bot 对话窗口中,直接粘贴或输入一个普通网页的完整 URL(以 `http://` 或 `https://` 开头),然后发送。本例中,用户发送的是 `https://example.com/blog/demo-post`。Bot 会识别这是一个普通网页,而不是 Telegram 已支持预览的特定站点,从而触发网页转 markdown 存档流程。

![用户发送普通网页链接,Bot 解析后返回存档卡片](assets/08-webpage-r1.png)

### 步骤 2: 等待 Bot 抓取与转换

Bot 在后台依次完成以下处理:抓取目标页面的 HTML 内容 → 提取正文并转换为 Markdown 格式 → 计算文件路径并推送到 GitHub 仓库归档 → 调用 Telegraph 接口生成可读的在线浏览页。整个过程通常需要数秒到十几秒,期间 Bot 不会推送中间状态,用户只需耐心等待。

### 步骤 3: 查看返回的存档卡片

处理完成后,Bot 会推送一条包含完整存档信息的卡片消息,内容包含以下要素:

- **标题**:从网页正文中提取的核心标题(本例为《小而美命令行工具》)。
- **摘要**:一段中文概述,概括原文的关键信息(本例为"这是一段用于手册演示的中文摘要,说明该内容的核心要点。")。
- **标签**:从内容中自动提炼的若干 `#` 话题标签(本例为 `#archive #开发工具 #命令行`)。
- **📁 存档链接组**:同一行内的三组链接,分别指向 GitHub 仓库中的 Markdown 源文件、原始网页快照(Wayback Machine)、以及 Telegraph 在线阅读页。

用户点击这三个链接中的任意一个,即可用对应方式查看存档内容:GitHub 链接适合查阅与版本管理、Wayback 链接适合核对原始内容、Telegraph 链接适合直接阅读。

### 小贴士

- 仅支持公网可访问的普通网页链接,登录墙、验证码或动态加载过多的页面可能抓取失败,建议改用 RSS 或手动复制正文。
- 若想为存档补充自定义说明,可在发送 URL 的同时附上一句备注文本,Bot 会把备注合并到摘要中。
- 所有历史存档都保存在 GitHub 仓库内,可通过搜索标签(如 `#开发工具`)快速定位同一主题的过往归档。
