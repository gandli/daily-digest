## 任意网页链接 → markdown 存档

本节介绍如何将任意网页链接转换为结构化的 markdown 存档,并通过 GitHub 与 Telegraph 双通道沉淀,最终在对话中以富文本卡片形式回执。

### 步骤 1: 复制目标网页链接

在浏览器地址栏或分享菜单中复制您希望存档的网页 URL。该链接必须是普通可公开访问的 HTTP(S) 地址,例如博客文章、文档页、新闻稿等。

### 步骤 2: 发送给 Bot

将链接作为一条普通文本消息粘贴并发送给 Bot。Bot 会自动识别 URL,无需附带额外指令或命令前缀。

### 步骤 3: 等待 Bot 处理与回执

Bot 接收到链接后会执行以下动作:抓取网页正文、提炼标题与摘要、转换为 markdown 格式、上传至 GitHub 仓库生成存档,并同步生成一个 Telegraph 镜像页。处理完成后,Bot 会以一张富文本卡片回执,卡片内包含:

- **标题**:文章原始标题。
- **摘要**:一段中文概述,说明该内容的核心要点。
- **标签**:由 Bot 根据正文自动生成的若干 hashtag(例如 `#archive`、`#开发工具`、`#命令行`)。
- **📁 三链**:分别指向 Web Archive 快照、GitHub markdown 文件与 Telegraph 页面的快捷入口。

![Bot 收到网页链接后返回的存档卡片,包含标题、中文摘要、hashtag 与三链入口](assets/08-webpage-r1.png)

### 步骤 4: 在对话中浏览或转发

卡片渲染完成后,您可以直接在 Telegram 对话中点击标题跳转阅读,也可以点击 📁 区中的任意链接跳转到对应存档通道。若需分享给同事,直接转发该条消息即可,卡片格式与三条链接会一并保留。

---

### 小贴士

- **链接类型**:Bot 会优先解析 HTML 正文;若链接指向的是 PDF、视频页或需要登录的页面,可能无法提取正文,建议改用纯文本或公开博客链接。
- **批量处理**:连续发送多条链接时,Bot 会按接收顺序逐条处理并分别回执卡片,无需等待上一条完成后再发送下一条。
- **存档检索**:由于 GitHub 通道与 Telegraph 通道是独立维护的,您可通过 📁 链接随时回访历史存档;若日后需要修改标签或分类,直接编辑 GitHub 仓库中的对应 markdown 文件即可。
