### 步骤 1: 粘贴网页链接

用户在 Bot 对话中直接发送一个普通网页 URL,无需添加任何前缀或指令。例如发送 `https://example.com/blog/demo-post`,Bot 即可识别这是一个需要归档的网页链接,而非普通聊天内容。

### 步骤 2: 等待 Bot 处理

Bot 在收到链接后会执行一系列后台操作:抓取目标网页正文、将 HTML 内容转换为 Markdown 格式、上传至 GitHub 仓库生成存档、发布至 Telegraph 生成可读页面,并从正文中提取关键信息用于卡片展示。这一过程通常需要数秒,用户只需耐心等待,无需重复发送链接。

### 步骤 3: 查看返回卡片

处理完成后,Bot 会回复一张格式化的归档卡片,包含三个要素:

- **标题**:从网页正文中提炼的核心主题,例如 *小而美命令行工具*。
- **摘要**:一段简洁的中文概述,概括该网页内容的核心要点。
- **标签**:以 `#` 开头的关键词标签,便于分类检索,例如 `#archive`、`#开发工具`、`#命令行`。
- **📁 三链区**:卡片末尾以 📁 图标引出的若干链接,分别指向 Web Archive 快照、GitHub Markdown 原文、Telegra.ph 可读页等归档入口。

![Bot 返回的归档卡片,含标题、摘要、标签与三链入口](assets/08-webpage-r1.png)

### 步骤 4: 访问归档链接

用户点击 📁 区域中的任意链接即可跳转:Web Archive 链接适合查阅历史快照与原始页面;GitHub 链接适合查看纯净的 Markdown 源码或进行二次编辑;Telegra.ph 链接适合获得最佳的在线阅读体验。三者互为补充,用户可根据需要自由选择。

## 小贴士

- **链接格式不限协议**:Bot 同时支持 `http://` 与 `https://` 开头的链接,部分带追踪参数的长链接也能被正确解析,无需手动精简。
- **批量发送请间隔片刻**:若需归档多个网页,建议逐条发送并等待上一条卡片返回后再发下一条,以避免后台任务堆积导致处理延迟。
- **摘要为自动生成**:卡片中的摘要由 Bot 根据正文提炼,可能与原文侧重点略有差异;如需精确引用,建议直接打开 GitHub 链接查看完整 Markdown 存档。
