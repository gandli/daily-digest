### 步骤 1: 复制网页链接

在浏览器中找到希望存档的网页, 将其完整 URL 复制到剪贴板。链接可以是普通文章、博客、文档页面, 不需要额外的预处理。例如, 本次演示使用的链接是 `https://example.com/blog/demo-post`。

### 步骤 2: 发送给 Bot

将链接粘贴到与 Bot 的对话中, 直接按回车发送。Bot 会自动识别这是一个网页 URL, 无需附加任何指令或命令前缀。

### 步骤 3: 等待 Bot 处理

Bot 接收到链接后, 会依次完成以下动作: 抓取目标页面的正文内容, 将 HTML 转换为结构化的 markdown 文本, 同时生成一段简短的中文摘要, 并从正文里提取相关的话题标签。整个过程通常在数秒内完成, 用户无需额外操作。

### 步骤 4: 查看返回的存档卡片

处理完成后, Bot 会回执一张包含四项信息的存档卡片: 一是文章标题, 二是自动生成的中文摘要, 三是依据正文内容提炼的话题标签, 四是以 📁 图标引导的三个存档链接, 分别指向 GitHub 仓库中的 markdown 文件、GitHub Issue 讨论页以及 Telegraph 公开镜像页。卡片样式示例如下:

> 小而美命令行工具 📝 这是一段用于手册演示的中文摘要, 说明该内容的核心要点。 #archive #开发工具 #命令行 📁 GitHub · Issue · Telegraph](https://web.archive.org/web/

![Bot 输出的网页存档卡片](assets/08-webpage-r1.png)

### 步骤 5: 点击链接完成访问

在卡片中根据需要点击对应的链接。若希望长期检索与版本管理, 推荐使用 GitHub 链接; 若希望分享给不熟悉 GitHub 的读者, Telegraph 页面拥有更好的阅读体验。三个链接指向同一份内容的不同载体, 互为冗余备份。

### 小贴士

- 仅发送纯 URL 即可触发存档流程, 不要附加说明文字, 否则 Bot 可能将整段内容识别为普通文本而忽略链接。
- 对于需要登录才能访问的网页, Bot 仅能抓取公开部分的内容; 建议提前在浏览器中确认页面可被匿名访问。
- 如果页面包含大量图片或代码块, 转换后的 markdown 可能略有简化, 可通过 GitHub 链接查看原始排版细节。
