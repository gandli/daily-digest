### 步骤 1: 粘贴普通网页链接

在任意聊天窗口中,直接向 Bot 粘贴一个普通 HTTP(S) 链接,例如 `https://example.com/blog/demo-post`,无需附加任何指令或前缀。Bot 会自动识别这是一个网页归档请求,并立即开始抓取与处理。

### 步骤 2: 等待 Bot 回执卡片

提交链接后,稍等数秒,Bot 会返回一张包含标题、摘要、标签与三链入口的卡片。完整样式如下:

> **小而美命令行工具** 📝 这是一段用于手册演示的中文摘要, 说明该内容的核心要点。 #archive #开发工具 #命令行 📁 [GitHub 存档](#) · [Telegraph 页](#) · [Wayback 备份](https://web.archive.org/web/)

卡片由四部分组成:顶部为抓取到的网页标题;其下是一段自动生成的中文摘要;再往下是一组话题标签(以 `#` 开头);最后一行以 📁 图标引出三个跳转链接,分别对应 GitHub 仓库中的 markdown 文件、Telegraph 镜像页与 Internet Archive 备份。

### 步骤 3: 查看截图示例

下图展示了真实的一次端到端交互结果,你可以对照核对自己的卡片格式与字段顺序是否一致:

![用户粘贴链接后,Bot 返回的标题+摘要+标签+三链卡片](assets/08-webpage-r1.png)

### 步骤 4: 点开链接核对存档

收到卡片后,建议依次点开三个 📁 链接做一次肉眼校验:GitHub 存档用于长期版本管理,Telegraph 页适合在只读场景下快速分享,Wayback 备份则作为第三方独立副本。当三者内容一致时,即可视为归档完成;若发现摘要偏离主题或标签不符,可删除消息并重新粘贴链接触发一次新的处理。

## 小贴士

1. **链接越干净越好**:粘贴前请去掉 URL 末尾的 UTM 参数(例如 `?utm_source=xxx`),有助于 Bot 命中原文而非追踪链接,提升摘要准确性。
2. **支持私有页面的前提**:部分需要登录或付费墙后的网页,Bot 无法获取正文,会回退为仅基于 meta 标签生成摘要,此时建议手动补充摘要后再归档。
3. **批量提交注意节奏**:一次性连发多条链接时,Bot 会按接收顺序排队处理;若其中某条抓取失败,不会阻塞后续条目,失败的链接会在数秒后回执一条错误提示。
