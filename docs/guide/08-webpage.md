### 步骤 1：发送目标网页链接

在 Bot 对话窗口中，直接粘贴或输入任意普通网页的完整 URL（需以 `http://` 或 `https://` 开头），随后将消息发送给 Bot。例如发送 `https://example.com/blog/demo-post`。Bot 会立即识别链接类型，并自动进入网页抓取与转写流程，无需额外触发命令。

### 步骤 2：等待 Bot 处理并返回存档卡片

Bot 在后台依次完成以下动作：访问目标 URL、抓取页面正文内容、转换为标准 Markdown 格式、同步上传至 GitHub 仓库生成存档链接，同时发布到 Telegraph 生成可读页。处理完成后，Bot 会回复一张结构化卡片，包含四个组成部分：

1. **标题**：自动提取的网页主标题（例如示例中的“小而美命令行工具 📝”）。
2. **摘要**：由 Bot 提炼的内容概要，用中文概述核心要点（示例中显示为“这是一段用于手册演示的中文摘要, 说明该内容的核心要点。”）。
3. **标签**：根据正文语义自动生成的关键词，方便检索（示例中为 `#archive #开发工具 #命令行`）。
4. **📁 三链按钮**：点击展开后可看到 GitHub 存档源文件、原始网页快照（Wayback Machine）、Telegraph 阅读页三个跳转链接，便于溯源与分享。

![Webpage 存档卡片示例：标题、摘要、标签与 📁 三链按钮](assets/08-webpage-r1.png)

### 步骤 3：查看与分享存档内容

收到卡片后，点击 📁 按钮展开链接组，根据需要选择访问方式：

- **GitHub 链接**：查看结构化 Markdown 源文件，适合二次编辑或纳入知识库。
- **Wayback Machine 链接**：即使原网页后续失效或被删除，仍可通过网页时光机快照阅读。
- **Telegraph 链接**：获得排版美观的即时阅读页，适合直接转发分享。

如需将内容沉淀到个人笔记系统，可手动复制 GitHub 链接，或借助 Bot 的检索功能按标签（如 `#开发工具`）回溯历史存档。

---

### 小贴士

- **链接必须可公开访问**：Bot 仅能抓取无需登录、无地区限制的公开网页；遇到反爬机制严格或需登录的页面（如部分新闻站点、社交平台），可能返回失败或仅获取到片段摘要。
- **批量发送间隔建议**：连续发送多条链接时，每条间隔 3–5 秒可降低触发目标站点频率限制的概率；若 Bot 短时间内未回复，请耐心等待处理队列完成。
- **标签可辅助检索**：存档生成后，可通过 Bot 搜索 `标签:开发工具` 或 `标签:#命令行` 来定位历史记录，无需记忆具体标题或链接。
