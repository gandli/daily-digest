### 任意网页链接 → markdown 存档

本节演示如何将任意网页链接快速归档为 Markdown 格式,并自动同步到 GitHub 仓库、生成 Telegraph 在线阅读页,最后以一张精美的卡片形式回传归档结果。

### 步骤 1: 发送网页链接

在任意与 Bot 对话的私聊或群组中,直接粘贴一个普通网页 URL(例如 `https://example.com/blog/demo-post`)并发送。Bot 会自动识别这是一个可归档的网页资源,无需额外指令或触发关键词。

![用户粘贴 URL 触发归档流程](assets/08-webpage-r1.png)

### 步骤 2: 查看归档完成卡片

Bot 完成抓取与转换后,会立即回复一张包含完整信息的卡片消息,主要包括三部分:

- **标题与摘要**:卡片顶部为网页标题,后接 Bot 自动生成的中文摘要,概括该网页的核心内容要点。
- **话题标签**:摘要下方会附带若干 `#` 标签(如 `#archive`、`#开发工具`、`#命令行`),方便后续按主题检索。
- **📁 三链归档入口**:卡片底部以 📁 图标开头的区域,提供三个关键链接 —— GitHub 仓库中的 Markdown 源文件、Web 时光机(archive.org)快照,以及 Telegraph 在线阅读页,便于从不同渠道访问归档内容。

### 步骤 3: 选择访问方式

用户可根据需要点击对应链接进行查看:

- 若希望阅读或编辑源文,点击 **GitHub 链接** 直接跳转到仓库中的 `.md` 文件;
- 若原始网页已失效,可通过 **archive.org 链接** 访问历史快照;
- 若希望获得排版清爽的阅读体验,点击 **Telegraph 链接** 即可在浏览器中即时阅读。

### 步骤 4: 后续操作(可选)

归档完成后,你可以继续在同一对话中发送新链接,Bot 会以相同流程处理下一条;也可以发送指令(例如搜索、删除、列出归档)对已存内容进行管理。卡片中的 `#话题标签` 也可用于跨条目聚合检索。

### 小贴士

1. **链接需为可公开访问的网页**:Bot 需要抓取 HTML 才能正确转 Markdown,登录墙或纯 PDF/图片页面可能无法生成摘要。
2. **摘要可作为二次筛选依据**:若卡片摘要与预期不符,可直接查看三链中的 GitHub 源文件确认原文,或放弃本次归档。
3. **群组中使用同样有效**:在群聊里粘贴链接,Bot 会将卡片发回该群;若需仅自己可见,建议在私聊中触发归档流程。
