## 任意网页链接 → markdown 存档

这一节介绍如何使用 Bot 把任意普通网页链接转成 markdown 文本,自动归档到 GitHub,并同时生成一份可分享的 Telegraph 镜像页。整个流程只需一条消息即可触发,适合收藏长文章、技术博客、产品文档等稍后阅读的内容。

### 步骤 1:发送待存档的网页链接

将完整的 URL 直接发送给 Bot。链接必须以 `http://` 或 `https://` 开头,Bot 会自动识别这是一条网页存档请求,而不是普通文本或图片。

例如,发送:

```
https://example.com/blog/demo-post
```

### 步骤 2:等待 Bot 抓取并渲染

Bot 在后台依次完成以下动作:抓取目标 HTML、抽取正文、按 markdown 规范转换、计算文件路径并推送到 GitHub 仓库,同时调用 Telegraph API 创建一份可读的镜像页。整个过程通常耗时数秒,期间无需任何额外操作。

### 步骤 3:接收存档卡片

处理完成后,Bot 会回复一条汇总消息。卡片内容包括四部分:

1. **标题**——抽取出的页面主标题,例如 `小而美命令行工具 📝`。
2. **摘要**——由 Bot 生成的一段中文概要,帮助你快速判断内容是否值得精读。
3. **标签**——根据正文关键词自动生成的若干 `#话题` 标签,例如 `#archive #开发工具 #命令行`,便于后续筛选与检索。
4. **📁 三链按钮**——并列提供三个链接入口:
   - GitHub 仓库中的 markdown 原文(永久存档、可版本管理);
   - Telegraph 镜像页(排版美观、适合手机阅读与转发);
   - Web Archive 历史快照(第三方独立留存,用于核对原文是否被改动)。

### 步骤 4:后续使用

- 点击 GitHub 链接即可在浏览器中查看或复制 markdown 源码;
- 点击 Telegraph 链接可把页面分享给好友或在群里转发;
- 点击 Web Archive 链接可核对原文与归档版本之间的差异。

存档成功后,这条消息会在 Bot 端的会话历史中保留,你可以随时通过历史记录回到该卡片。

### 小贴士

- **先抓后转**:如果目标页面需要登录(例如公众号后台、Notion 私密页),请改用分享后的公开 URL,否则 Bot 只能拿到登录墙 HTML,摘要质量会明显下降。
- **触发式标签**:想要更精准的标签时,可以在发送链接前先发一行 `#我的标签1 #我的标签2`,Bot 会把它们与自动生成的标签合并,方便后续按主题归档。
- **重复链接去重**:对同一 URL 再次发送时,Bot 会复用已有的 GitHub 与 Telegraph 记录并重新发一张卡片,不会产生重复文件,放心多次调用。
