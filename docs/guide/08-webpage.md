### 步骤 1: 发送网页链接

在任意聊天窗口中,将需要存档的普通网页链接复制并粘贴发送,无需添加额外说明文字或触发命令。Bot 会自动识别 URL 格式,启动网页解析流程。

例如,直接发送:`https://example.com/blog/demo-post`

### 步骤 2: 接收归档卡片

Bot 完成解析与多端存档后,会以一张富文本卡片作为回复,包含三部分核心信息:

- **标题区**:自动提取的网页主标题,例如本例中的「小而美命令行工具」
- **摘要区**:由 Bot 生成的中文内容摘要,概述文章核心要点
- **标签区**:基于内容语义自动生成的 1-3 个话题标签(如 `#archive`、`#开发工具`、`#命令行`),便于后续检索
- **存档链接区**:以 📁 图标引导的三条外链,分别指向 GitHub 原始 Markdown 文件、GitHub Pages 渲染预览页,以及 Telegraph 镜像页

如下方截图所示,Bot 在收到链接后立即返回结构化卡片:

![Bot 返回的网页归档卡片,包含标题、摘要、标签与三条存档链接](assets/08-webpage-r1.png)

### 步骤 3: 查看或转发存档

用户可直接点击卡片中 📁 下方的链接跳转查看完整存档内容,也可将卡片转发给其他用户或群组。需要再次访问时,在 Bot 历史消息中向上翻找该卡片即可,所有存档链接均为永久有效地址。

## 小贴士

- **仅支持标准 HTTP/HTTPS 链接**:粘贴时应去掉 `复制链接` 弹窗中的附加参数(部分浏览器会附带 `?utm_source=...` 追踪字段),以免 Bot 解析时将同一页面误判为不同来源。
- **仅适用于普通可访问网页**:Bot 仅抓取普通网页内容;登录后才可见的页面、私有文档、付费墙内容,以及需要 JS 动态渲染才能显示的 SPA 页面,可能无法生成准确的 markdown 摘要。
- **批量归档建议间隔发送**:若需连续存档多个链接,建议每条消息独立发送并等待 Bot 返回卡片后再发送下一条,避免请求堆积导致部分链接处理超时。
