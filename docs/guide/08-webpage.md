### 步骤 1: 发送网页链接

在聊天窗口中,将任意普通网页的 URL(例如 `https://example.com/blog/demo-post`)直接粘贴并发送给 Bot,无需附带任何额外命令或提示词。Bot 会自动识别这是一个需要存档的网页链接,而非普通文本消息。

### 步骤 2: 等待 Bot 抓取与转换

Bot 在收到链接后,会先后台抓取目标页面的正文内容,提取标题、摘要、关键词等元数据,并将其转换为结构清晰的 Markdown 格式。整个过程通常需要数秒到十几秒,具体取决于目标网页的响应速度。在此期间,你无需进行任何操作,只需等待 Bot 的回复即可。

### 步骤 3: 接收存档卡片

Bot 处理完成后,会返回一张精心排版的存档卡片,包含以下信息:

- **标题**:经过提炼的核心标题,例如"小而美命令行工具 📝"。
- **摘要**:一段简明扼要的中文摘要,概括该网页内容的核心要点,例如"这是一段用于手册演示的中文摘要,说明该内容的核心要点。"
- **话题标签**:自动从内容中提炼的标签,如 `#archive` `#开发工具` `#命令行`,方便后续检索分类。
- **📁 三链入口**:在卡片底部以 📁 图标开头,依次提供三个链——GitHub 存档(永久保存的 Markdown 原文)、Telegraph 页面(即点即看的在线阅读页)以及可选的 archive.org 快照(防止原链接失效)。

![Bot 返回的存档卡片,包含标题、摘要、话题标签和三链入口](assets/08-webpage-r1.png)

### 步骤 4: 查阅与分享

点击卡片中的 📁 链接即可在浏览器中打开对应的存档页面。如果你希望与他人分享,直接转发该卡片即可,所有链接均会随卡片一起送达。Telegraph 链接适合快速阅读,GitHub 链接适合需要引用原文或查看 Markdown 源码的场景。

### 小贴士

- **支持任意 URL**:Bot 对链接来源没有限制,无论是技术博客、新闻站点还是个人专栏,只要页面包含可解析的正文内容,均可成功存档。
- **存档不可逆**:每次发送相同链接,Bot 都会创建一条新的存档记录。若内容频繁更新(如新闻类页面),建议在正文发生重大变化时再重新存档,以避免冗余。
- **失效链接有备无患**:如果原网页日后无法访问,archive.org 快照链接依然可以帮你找回历史内容,这也是 Bot 自动提供该链接的重要原因。
