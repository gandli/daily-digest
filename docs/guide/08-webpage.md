## 任意网页链接 → markdown 存档

当你在群里看到一篇值得沉淀的长文、博客或教程,只要把链接发给 Bot,它就会自动抓取正文、转成结构清晰的 markdown,同时把副本推送到 GitHub 仓库、Wayback Machine(网页时光机)与 Telegraph,再生成一张带标题、摘要和三条链接的预览卡片,方便你随时翻阅。

---

### 步骤 1:复制目标网页的完整 URL

在浏览器地址栏选中并复制目标页面的完整链接。普通 HTTP/HTTPS 链接都可以,无需额外处理。

### 步骤 2:在 Bot 对话中粘贴链接并发送

把刚刚复制的 URL 直接粘贴进聊天窗口,像发消息一样按回车发送即可,**不要附带额外说明文字**,避免 Bot 误判意图。

### 步骤 3:等待 Bot 自动抓取与转换

Bot 会按顺序完成以下工作:

1. 抓取目标页面的 HTML,提取正文与标题;
2. 清理广告、导航栏等冗余元素,转成干净的 markdown 文本;
3. 将 markdown 同步推送到 GitHub 存档仓库,并生成 Telegraph 公开页;
4. 同时向 Wayback Machine 提交一份历史快照,确保原文失效后仍可回溯。

整个过程通常在几秒到十几秒之间,链接越短、目标站越轻量,响应越快。

### 步骤 4:查看 Bot 返回的存档卡片

抓取完成后,Bot 会回一条结构化的卡片消息,典型内容如下:

- **标题行**:来自网页原始标题,例如「小而美命令行工具 📝」;
- **摘要段**:用一段中文概述文章核心要点,方便快速判断是否值得深读;
- **标签组**:用 `#` 开头的关键词,例如 `#archive #开发工具 #命令行`;
- **链接区**(`📁` 开头):依次给出 GitHub 存档、Telegraph 镜像、Wayback Machine 快照三条链接,任选其一打开即可。

### 步骤 5:按需选择入口阅读或转发

- 想看排版精美的渲染版,优先点 Telegraph 链接;
- 想下载或二次编辑,优先点 GitHub 链接拿到原始 markdown;
- 原站已下线或网络不稳,优先点 Wayback Machine 链接。

---

### 小贴士

- **保持链接干净**:复制时不要带上 `?utm_source=...` 这类追踪参数,否则 Bot 抓到的可能是不同的统计变体,影响标题与摘要准确性。
- **私聊与群聊均可**:在群聊中使用时,记得 @Bot 或在消息中包含触发词,避免被群里的其他关键词机器人抢走。
- **失败可重试**:若 Bot 回复「抓取失败」或超时,通常是因为目标站禁止爬虫或登录墙阻挡,稍等片刻换一条同主题的公开转载链接再试一次即可。
