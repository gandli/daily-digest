## 任意网页链接 → markdown 存档

只需向 Bot 发送一个普通网页链接,它就会自动抓取正文、转换为 Markdown 格式,并同时存档到 GitHub 仓库、生成 Telegraph 页面,最后回执一张包含标题、摘要与三条存档链接的卡片。整个过程无需额外指令,粘贴即触发。

### 步骤 1:复制目标网页链接

在浏览器中打开想要存档的文章,复制其完整 URL(以 `http://` 或 `https://` 开头)。要求链接指向一个普通可公开访问的网页,而非登录后才可见的内部页面或纯 PDF/视频资源。

### 步骤 2:粘贴链接并发送给 Bot

将复制的 URL 作为消息正文发送给 Bot,无需附带任何文字说明,也不需要填写命令前缀。

**用户操作示例:**

```
https://example.com/blog/demo-post
```

Bot 接收到链接后会立即开始抓取与解析流程,这一步通常需要几秒到十几秒不等,取决于目标网页的响应速度。

### 步骤 3:接收存档卡片

解析完成后,Bot 会回执一张格式化的卡片,包含四项内容:文章标题、中文摘要(由 Bot 自动提炼)、从正文提取的话题标签(以 `#` 前缀呈现),以及一个 📁 存档区,内含三条链接,分别指向 Web Archive 快照、GitHub 仓库中的 Markdown 文件,以及 Telegraph 可读页面。卡片样式大致如下:

> 小而美命令行工具 📝 这是一段用于手册演示的中文摘要,说明该内容的核心要点。 #archive #开发工具 #命令行 📁 [Web Archive 快照链接…]

用户可直接点击 📁 中的任意链接进行查阅、分享或二次编辑。

![Bot 回执的存档卡片,包含标题、摘要、话题标签与三条存档链接](assets/08-webpage-r1.png)

### 步骤 4(可选):二次查询与补抓

如果初次抓取因网络抖动而失败,只需将同一链接再次发送给 Bot 即可重试,无需使用任何重试指令。若需要补充抓取同一域名的其他文章,直接重复步骤 1 至步骤 3 即可。

---

### 小贴士

- **链接越干净越好**:带有大量 `utm_` 参数或跟踪片段的 URL 可能会影响摘要准确性,建议先在浏览器地址栏复制去掉多余参数后的"纯净版"链接。
- **摘要由 Bot 自动生成**:摘要内容为 Bot 基于正文提炼,长度和措辞因文章而异;若需修改,可点击 GitHub 链接进入仓库直接编辑 Markdown 源文件。
- **三条存档各有用途**:Web Archive 适合作为长期引用快照,GitHub 链接便于二次编辑与版本管理,Telegraph 页面则更适合直接分享给读者阅读,按需选用即可。
