### 任意网页链接 → markdown 存档

本节介绍如何将任意网页 URL 一键转化为 markdown 文本,并自动存档到 GitHub 仓库,同步生成 Telegraph 镜像页与存档链接,最终以一张信息卡片形式返回。

### 步骤 1:复制目标网页链接

在浏览器中打开希望存档的网页,从地址栏复制其完整 URL。链接需为标准 `http://` 或 `https://` 开头,博客、文档站、技术文章均适用。

### 步骤 2:向 Bot 发送链接

打开与 Bot 的对话窗口,将复制的链接作为一条消息直接发送给 Bot。无需附加任何指令,Bot 会自动识别 URL 格式并触发网页抓取流程。

### 步骤 3:等待 Bot 处理并接收存档卡片

Bot 收到链接后,会依次执行以下动作:

1. 抓取网页正文内容;
2. 调用转换服务将 HTML 渲染为 markdown;
3. 将 markdown 文件推送到 GitHub 存档仓库;
4. 把同一份内容发布为 Telegraph 页面,获得可即时阅读的镜像链接;
5. 通过 Wayback Machine 生成历史快照链接。

处理完成后,Bot 会回复一张结构化卡片,包含三个部分:

- **标题与摘要**:提炼出的核心信息,例如「小而美命令行工具」及其要点说明;
- **话题标签**:根据内容自动生成的相关标签,如 `#archive` `#开发工具` `#命令行`;
- **📁 三链入口**:GitHub 源码、Telegraph 阅读版、Wayback 存档三个链接,均以 `<a href="…">` 形式嵌入在折叠块中。

### 步骤 4:按需使用链接

收到卡片后,可按使用场景选择不同入口:

- **日常阅读** → 点击 Telegraph 链接,获得免登录、无干扰的排版页面;
- **二次编辑或引用** → 打开 GitHub 链接,获取原始 markdown 源码,便于复制片段;
- **长期归档与溯源** → 通过 Wayback Machine 链接验证原始网页在存档时刻的快照,防止原文失效。

### 小贴士

- 发送链接时,确保 URL 前后无多余空格或换行符,避免 Bot 误判为纯文本。
- 若网页需要登录或属于反爬严格的站点,Bot 可能无法获取正文,此时建议手动复制关键段落发送。
- 同一链接重复发送,Bot 会基于内容哈希去重,不会在 GitHub 仓库中产生重复文件,但仍会返回最新的三链卡片供你取用。
