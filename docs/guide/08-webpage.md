### 步骤 1: 发送目标网页链接

在任意聊天窗口中,将想要存档的网页链接直接发送给 Bot。链接无需附带任何说明文字,Bot 会自动识别其类型。

本例中发送的链接为 `https://example.com/blog/demo-post`,即一篇示例博客文章。

### 步骤 2: 等待 Bot 抓取并转换

Bot 收到链接后,会执行以下处理流程:

1. 抓取目标网页的正文内容
2. 将 HTML 转换为 Markdown 格式
3. 同时生成 GitHub 存档副本与 Telegraph 在线阅读页
4. 提取文章标题、核心摘要、相关标签
5. 整合为一张信息卡片回传给用户

整个过程通常在数秒内完成,无需用户进行任何额外操作。

### 步骤 3: 查看 Bot 返回的存档卡片

处理完成后,Bot 会回复一条包含标题、摘要、标签和快捷链接的卡片消息。本例中 Bot 返回的内容如下:

> 小而美命令行工具 📝 这是一段用于手册演示的中文摘要,说明该内容的核心要点。 #archive #开发工具 #命令行 📁 GitHub 存档 + Telegraph 阅读页 + Wayback Machine 备份三组快捷链接(以 `<a href="...">` 锚文本形式呈现,用户可直接点击跳转)。

卡片由四个层次组成,自上而下分别为:

- **标题行**:展示抓取到的文章主标题
- **摘要行**:用一句话概括正文核心要点
- **标签行**:以 `#` 前缀列出 2 至 3 个分类标签,便于检索
- **链接区**:以 📁 图标为前缀,集中放置三种存档形式的入口链接

效果示意如下:

![Bot 返回的网页存档卡片,包含标题、摘要、标签与三组链接](assets/08-webpage-r1.png)

### 步骤 4: 点击链接完成访问

根据需要选择链接区中的对应入口:

- 点击 **GitHub 链接**查看长期保存的 Markdown 原文
- 点击 **Telegraph 链接**获得即时阅读体验,适合分享给他人
- 点击 **Wayback Machine 链接**访问网页历史快照,作为原始链接失效后的备选

任一链接均会跳转到外部站点,用户可在浏览器中继续浏览、复制或转发。

## 小贴士

- 链接以纯文本形式发送即可,**无需**添加 `md`、`archive` 等前缀指令,Bot 会依据协议头自动识别
- 若 Bot 未返回卡片而是提示抓取失败,通常是因为目标网站设置了反爬机制,可尝试更换链接或在链接前加 `r.` 前缀(若 Bot 支持)触发备用通道
- 存档卡片中的标签由 Bot 根据正文关键词自动生成,目前不支持手动指定;如需自定义分类,可在 Bot 归档后编辑 GitHub 中的 Markdown 文件补充
