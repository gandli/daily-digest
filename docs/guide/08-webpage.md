### 步骤 1：发送普通网页链接

在 Telegram 对话窗口中,直接粘贴任意公开网页的 URL 并发送,无需附带任何说明文字或指令。Bot 会自动识别 URL 类型并启动网页处理流程。

### 步骤 2：等待 Bot 抓取与转换

Bot 收到链接后,会执行以下处理动作:抓取目标页面的标题、正文内容与元信息;将正文转换为 Markdown 格式;同时把转换结果存档到 GitHub 仓库,并同步生成一个 Telegraph 阅读页。处理时间通常在几秒到十几秒不等,取决于目标网页的响应速度与内容长度。

### 步骤 3：查看返回的存档卡片

Bot 完成处理后会回复一张汇总卡片,包含三部分信息:

- **标题与摘要**:首行是网页标题,其后是 Bot 根据正文提炼的中文摘要,帮助你快速判断内容是否值得深入阅读;
- **话题标签**:摘要下方会附带若干 `#话题` 标签,例如 `#archive`、`#开发工具`、`#命令行` 等,用于内容分类与后续检索;
- **📁 三链归档区**:卡片末尾的 `📁` 图标后会列出三条链接,分别指向 GitHub 存档、Telegraph 阅读页以及网页时光机快照(通常为 web.archive.org),三个入口覆盖了原文存档、在线阅读与历史快照三种使用场景。

### 步骤 4：选择合适的入口阅读

收到卡片后,你可以根据自己的需求点击对应链接:想长期保留选 GitHub 链接;想立即流畅阅读选 Telegraph 链接;原文已失效或想查看历史版本则选择 web.archive.org 链接。

### 小贴士

- 粘贴链接时无需附加任何前缀或指令,Bot 会自动识别 URL;但请确保链接为可公开访问的 HTTP 或 HTTPS 网页,登录墙或反爬严格站点可能抓取失败。
- 如果返回的摘要过短或偏离重点,可以在粘贴链接后追加一句引导语(如"重点关注技术细节"),帮助 Bot 更准确地提炼核心要点。
- 卡片中的三条归档链接互为冗余备份,建议至少收藏其中一条(GitHub 或 Telegraph),以防原文被删除后无法回溯。
