### 步骤 1：粘贴 GitHub 仓库链接

在任意聊天窗口中，向 Bot 发送一条标准格式的 GitHub 仓库地址，例如 `https://github.com/antirez/kilo`。无需附加任何额外说明或指令，Bot 会自动识别链接类型。

### 步骤 2：等待 Bot 抓取并解析

Bot 接收到链接后，会立即调用 GitHub API 拉取该仓库的基础元数据，包括仓库名称、Star 数、Fork 数、主要语言、所有者头像与昵称等信息。同时，Bot 会并行请求 deepwiki 与 zread 两个服务，尝试为该仓库生成一段中文描述。

### 步骤 3：首次访问时的归档写入

如果这是 Bot 首次处理该仓库（即归档库中尚无记录），它会在抓取完成后执行一次"存档"操作：把仓库元数据、外部描述、原始链接、首次入库时间等信息持久化到归档数据库中。这一步为后续的"带描述归档卡"提供数据底座。

### 步骤 4：返回带描述的归档卡

完成上述步骤后，Bot 会以一条 Telegram 富文本消息作为回复，结构如下：

- 第一行：仓库短名 + Star 数 + 简介 emoji，如 `antirez/kilo ⭐ 3.2k · #C`。
- 第二行：所有者头像 + 昵称，如 `👤 antirez`。
- 第三行：由 deepwiki / zread 生成的中文描述，例如"这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。"。
- 第四行：自动打上的主题标签，如 `#trending #c #editor`。
- 末尾：归档卡片链接 `🗂 <a href="...">，点击可查看完整归档详情。

### 步骤 5：再次粘贴时的快速复用

如果同一链接已经查询过（即归档库中已存在记录），Bot 会跳过抓取与外部描述请求两个耗时步骤，直接从归档库中读取并返回同一张卡片，响应速度明显加快。这种"♻️ 带描述的归档卡"机制既能节省网络请求，也保证了你每次看到的描述内容一致、可追溯。

---

### 小贴士

- 链接必须使用 `https://github.com/owner/repo` 的标准形式，简写形式（如 `github.com/owner/repo`）或带末尾斜杠、`.git` 后缀的链接可能无法被正确识别。
- 归档卡片的描述来源于 deepwiki 与 zread 的聚合结果，对于小众或极新的仓库，描述可能较短甚至缺失，此时卡片仍会正常返回，但缺少描述段落。
- 想查看某个仓库的归档历史与首次入库时间，直接点击卡片末尾的链接即可进入归档详情页。
