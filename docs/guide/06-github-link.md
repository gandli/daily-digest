### 步骤 1: 复制 GitHub 仓库链接

在浏览器中打开目标仓库页面,从地址栏复制完整 URL。链接格式必须是 `https://github.com/<owner>/<repo>`,例如 `https://github.com/antirez/kilo`。注意不要复制多余的查询参数或分支路径,保持仓库主页链接即可。

### 步骤 2: 发送给 Bot

将复制好的链接作为消息发送给 Bot,无需添加任何说明文字,直接粘贴即可。Bot 会自动识别这是 GitHub 仓库链接并触发查询流程。

### 步骤 3: 首次查询 — 获取仓库信息

如果是第一次查询该仓库,Bot 会按顺序执行:抓取 GitHub 仓库的元数据(名称、星标数、话题标签)、调用 deepwiki 和 zread 获取仓库描述、生成快照存档、构建归档卡片。处理过程需要数秒,期间请耐心等待。

### 步骤 4: 收到归档卡片

Bot 返回一张带描述的归档卡片,包含以下内容:

- **仓库标识**:`antirez/kilo`
- **星标数**:⭐ 3.2k
- **话题标签**:#C(由仓库元数据推断)
- **作者**:👤 antirez
- **描述**:这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。(来自 deepwiki/zread)
- **话题**: #trending #c #editor
- **存档链接**:🗂 后的可点击链接

### 步骤 5: 重复查询 — 直接返回已有卡片

再次向 Bot 发送同一个 GitHub 链接时,Bot 会跳过抓取和存档流程,直接返回已有的归档卡片(以 ♻️ 标识,表示来自缓存)。这样既节省时间,也避免重复请求外部服务。

---

### 小贴士

- **链接越干净越好**:只发送 `https://github.com/owner/repo` 这种主页链接,不要附加 `/tree/main`、`?tab=readme` 等后缀,Bot 只需定位到仓库本身。
- **关注卡片中的话题标签**:归档卡片中的 `#xxx` 标签源自仓库的 GitHub Topics,可用于后续按话题筛选和检索;如果标签不符合预期,可以手动补发新链接让 Bot 重新抓取。
- **首次查询耗时稍长**:第一次粘贴新仓库链接时,Bot 要依次访问 GitHub、deepwiki、zread 并写入存档,需要数秒;之后的重复查询会秒回 ♻️ 缓存卡片。
