### 步骤 1: 复制 GitHub 仓库链接

在浏览器或 GitHub App 中找到目标仓库,复制其完整 URL。链接必须遵循 `https://github.com/owner/repo` 格式,例如 `https://github.com/antirez/kilo`。无需附带分支、路径或查询参数,Bot 只识别仓库级别的链接。

### 步骤 2: 粘贴链接并发送给 Bot

将复制的 URL 直接粘贴到与 Bot 的对话窗口中,按发送键提交。本轮示例中,用户发送的是 `https://github.com/antirez/kilo`。

### 3. Bot 抓取并整理仓库信息

Bot 接收到链接后,会调用 GitHub 接口拉取仓库元数据,包括仓库名、Star 数、主语言、作者等字段;若该仓库此前未被查询过,Bot 还会进一步请求 deepwiki 与 zread 等描述来源,生成一段中文简介,例如「这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言」。整个过程通常在数秒内完成。

### 步骤 4: 归档并返回卡片

抓取完成后,Bot 会将本次查询连同生成的描述一起存入归档,然后以一张「带描述的归档卡」回复用户。卡片正文包含仓库标题、星标数、语言标签、作者名、AI 简介以及话题标签,文末附带可点击的存档链接。

以本轮真实对话为例,Bot 返回内容如下:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 [归档链接]

![首次查询返回的归档卡,含星标、语言、作者与中文描述](assets/06-github-link-r1.png)

### 步骤 5: 二次查询同一仓库(可选)

若用户再次粘贴同一个 `https://github.com/owner/repo` 链接,Bot 不会重复抓取,而是直接读取已有归档,以 ♻️ 带描述的归档卡的形式快速返回,响应更及时。

## 小贴士

- 链接必须是仓库主页地址,不要发送具体的 `issues/123` 或 `pull/456` 等子路径,否则 Bot 无法识别仓库。
- 卡片中的描述由 AI 生成,若与实际用途偏差较大,可忽略描述,仅以星标、语言等元数据作为参考。
- 同一仓库重复发送可作为快速回看入口,适合在多次会话中追踪同一个项目时使用。
