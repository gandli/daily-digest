### 步骤 1: 直接粘贴 GitHub 仓库链接

在 Telegram 对话窗口中,直接向 Bot 发送一条 GitHub 仓库地址(支持 `https://github.com/owner/repo` 格式),无需输入任何额外命令。例如发送:

`https://github.com/antirez/kilo`

### 步骤 2: 等待 Bot 返回仓库卡片

Bot 收到链接后会自动执行查询逻辑:

- **首次查询**:抓取该 repo 的元数据(仓库名、Star 数、编程语言、作者等),然后依次请求 deepwiki、zread 等数据源补充描述,最后生成一条归档记录,并返回一张带描述的仓库卡片。
- **再次查询(命中缓存)**:Bot 会直接返回已有的归档卡片 ♻️,不再重复抓取。

下图展示了 Bot 对 `https://github.com/antirez/kilo` 这条链接首次查询后返回的卡片样例:

![GitHub 仓库链接首次查询返回的归档卡片](assets/06-github-link-r1.png)

卡片中包含了仓库名、Star 数、所属编程语言标签、作者用户名,以及由 deepwiki / zread 综合生成的仓库描述,末尾附带主题标签(如 `#trending #c #editor`)和归档入口。

### 步骤 3: 阅读卡片内容

仔细阅读 Bot 返回的卡片信息,关注以下几个字段:

- **仓库标识**:`owner/repo` 形式的名称(如 `antirez/kilo`),用于确认是目标仓库。
- **Star 数与语言**:快速判断仓库的热度与技术栈。
- **描述文本**:由 deepwiki / zread 生成的简介,帮助你了解仓库用途。
- **主题标签**:Bot 自动从仓库主题中提取,便于后续检索。

### 步骤 4: 点击归档入口(可选)

卡片底部会带有一个 🗂 归档链接(在 Telegram 客户端中以可点击的 `<a href="...">` 形式呈现)。点击它即可跳转到该仓库的完整归档页面,查看更详细的元数据、历史记录以及之前积累的相关讨论。

### 步骤 5: 继续对话或开启新查询

阅读完成后,你可以:

- 直接在当前对话中向 Bot 提新问题,例如「这个项目和 xxx 有什么区别」。
- 发送另一条 GitHub 链接,开始下一轮仓库查询,Bot 会按相同流程处理。

---

## 小贴士

1. **链接支持多种写法**:除了 `https://github.com/owner/repo` 外,通常也兼容简写形式(如 `github.com/owner/repo`)以及末尾带或不带 `.git` 的写法,粘贴后 Bot 都能自动识别。
2. **重复发送会走缓存**:对同一仓库再次粘贴链接,Bot 会返回 ♻️ 标记的归档卡而非重新抓取,既能节省时间,也能保证描述一致;若想强制刷新,可发送「重新查询 owner/repo」之类的指令(以 Bot 实际支持的语法为准)。
3. **结合标签高效检索**:Bot 会为每个仓库自动打上主题标签(如 `#c`、`#editor`),日后若想找同主题仓库,可使用 `Bot 的标签搜索指令` 配合标签关键词快速召回。
