### 步骤 1:粘贴 GitHub 仓库链接

在 Telegram 对话中,直接向 Bot 发送一个 GitHub 仓库的完整 URL,例如 `https://github.com/antirez/kilo`。无需添加任何额外说明文字,Bot 会自动识别链接类型并触发仓库查询流程。

### 步骤 2:首次查询 — 抓取元数据并生成归档卡

如果是该链接的**首次查询**,Bot 会在后台执行一系列操作:抓取 GitHub 仓库的基础元数据(包括仓库名、Star 数、默认分支、描述等),随后调用 deepwiki 与 zread 补充更深入的项目说明,接着将整理后的内容存档,最终生成一条带描述的归档卡片回复给用户。卡片中会包含仓库名、Star 数、语言标签、作者、补充描述、话题标签,以及一条指向归档详情的链接。

!首次查询返回的归档卡片,展示仓库元数据与补充描述](assets/06-github-link-r1.png)

### 步骤 3:再次查询 — 返回带描述的归档卡

如果之前已经查询过同一链接(例如隔了一段时间再次粘贴),Bot 会跳过抓取与抓取补充描述的步骤,直接从存档中读取已有记录,返回一条 **♻️** 标记的归档卡片。卡片内容与首次查询保持一致,但响应速度会明显更快,因为无需重新调用外部数据源。

### 步骤 4:点击卡片链接查看完整归档

无论首次还是再次查询,回复卡片底部都会附带一个 `🗂` 链接。点击该链接即可跳转到该仓库的完整归档页面,查看更详细的元数据、补充描述来源,以及历史查询记录。

---

**小贴士**

- **支持任意公开仓库**:只要是 GitHub 上的公开仓库链接,Bot 都能识别;暂不支持 GitLab、Gitee 等其他托管平台的链接。
- **Star 数与标签会随存档刷新**:首次查询时记录的 Star 数是抓取时刻的快照,再次查询时如果 Bot 重新抓取,数据会更新;若命中缓存,则显示存档时的数值。
- **描述来源可信赖**:补充描述来自 deepwiki 与 zread 两个信息源,经过 Bot 整合后呈现,比 GitHub 默认描述通常更详尽,适合快速了解项目定位。
