### 步骤 1: 复制 GitHub 仓库链接

在浏览器中打开 GitHub, 进入目标仓库页面(如 `https://github.com/antirez/kilo`), 从地址栏复制完整的仓库 URL。请确保链接格式为 `https://github.com/owner/repo`, 即包含协议头、域名、所有者和仓库名四部分, 缺一不可。

### 步骤 2: 粘贴链接并发送

将复制的链接粘贴到与 Bot 的对话窗口中, 直接按回车发送。无需附加任何文字说明, Bot 会自动识别 GitHub 链接格式并触发仓库查询流程。

### 步骤 3: 查看 Bot 返回的仓库归档卡

Bot 处理完成后, 会返回一张带描述的归档卡片, 内容包含仓库名称(如 `antirez/kilo`)、Star 数(如 ⭐ 3.2k)、主要编程语言标签(如 #C)、作者信息(如 👤 antirez)、由 deepwiki 或 zread 抓取的仓库描述、自动归类的标签(如 #trending #c #editor)以及归档跳转链接。

![首次查询返回的归档卡片](assets/06-github-link-r1.png)

卡片信息说明:

- **Star 数与语言标签** 直接来自 GitHub 仓库元数据, 反映仓库的热度和技术栈;
- **作者与描述** 由 deepwiki 或 zread 源补充, 帮助你在未访问 GitHub 的情况下快速判断仓库用途;
- **自动标签** 由 Bot 根据语言和描述关键词生成, 便于后续检索;
- **🗂 归档链接** 可跳转到 Bot 的存档页面, 查看完整记录。

### 步骤 4: 再次发送同一链接(验证缓存)

若你再次粘贴相同的 `https://github.com/owner/repo` 链接, Bot 将跳过抓取流程, 直接返回已有的归档卡片, 并在卡片上以 ♻️ 标记表示这是缓存的归档记录。这避免了重复调用外部接口, 响应速度更快。

## 小贴士

1. **链接必须完整**: 仅发送 `github.com/owner/repo` 而省略 `https://` 协议头时, Bot 可能无法识别为 GitHub 链接, 请始终带上完整协议。
2. **首次查询耗时较长**: 因为需要抓取 GitHub 元数据并调用 deepwiki/zread 生成描述, 首次响应可能需要数秒, 耐心等待即可, 后续同链接查询将走缓存秒回。
3. **支持多种仓库类型**: 无论是个人项目、组织仓库还是归档仓库, 只要链接符合 `https://github.com/owner/repo` 格式均可触发查询, 无需额外参数。
