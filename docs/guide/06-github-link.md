### 步骤 1：发送 GitHub 仓库链接

在 Telegram 对话窗口中，直接向 Bot 粘贴一个 GitHub 仓库的完整 URL，例如 `https://github.com/antirez/kilo`。无需输入额外指令，Bot 会自动识别链接格式并触发仓库查询流程。

### 步骤 2：等待 Bot 返回仓库卡片

Bot 接收到链接后，会根据仓库的查询记录返回不同结果：

- **首次查询的仓库**：Bot 会先抓取该仓库的基本元数据（如 star 数、作者、简介等），并请求 deepwiki 或 zread 接口补充更详细的描述，最后将所有信息整合后发送一张归档卡片。
- **已经查询过的仓库**：Bot 会跳过抓取步骤，直接从归档中读取已有的描述，以 ♻️ 标识快速返回带描述的归档卡片，避免重复抓取。

### 步骤 3：查看返回的仓库卡片内容

Bot 返回的消息中会包含以下信息：

- 仓库名称（如 `antirez/kilo`）及其 star 数量（如 ⭐ 3.2k）
- 仓库的主要编程语言（如图中的 `#C`）
- 仓库作者（如 👤 antirez）
- 通过 deepwiki/zread 获取的仓库描述（例如："这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言"）
- 自动提取的话题标签（如 `#trending #c #editor`）
- 存档链接（消息底部以 🗂 开头的 `<a href="...">` 链接）

### 步骤 4：后续操作

收到卡片后，你可以：

- 点击 🗂 后面的链接查看完整的归档页面
- 继续发送其他 GitHub 链接进行查询
- 向 Bot 发送与该仓库相关的后续问题

---

### 小贴士

1. **确保链接格式完整**：Bot 通过精确匹配 `https://github.com/owner/repo` 格式来识别查询请求，建议直接复制浏览器地址栏中的完整链接发送。
2. **重复查询会快速返回**：对于已经查询过的仓库，Bot 会以 ♻️ 标记直接返回归档卡片，不会重复抓取网络数据，响应更迅速。
3. **描述由外部服务生成**：仓库的详细描述由 deepwiki 或 zread 提供，如果首次查询时这两个服务暂时不可用，Bot 仍会返回基础元数据，但可能缺少补充描述。
