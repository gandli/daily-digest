## GitHub 仓库链接 → 单仓查询

通过粘贴 GitHub 仓库链接,可快速查询任意仓库的核心信息。Bot 会自动识别链接、抓取仓库元数据,并在首次查询时补充描述与归档,二次查询则直接返回已有的归档卡片,无需重复抓取。

### 步骤 1:复制仓库链接

在浏览器或 GitHub App 中找到目标仓库,点击地址栏,复制完整 URL,格式形如 `https://github.com/owner/repo`,确保包含协议头与 owner/repo 两段路径。

### 步骤 2:粘贴链接发送给 Bot

将链接直接粘贴到与 Bot 的对话输入框中发送,无需附加任何文字说明。Bot 会识别这是一个 GitHub 仓库链接,并触发单仓查询流程。

### 步骤 3:查看 Bot 返回的归档卡片

Bot 处理完成后,会返回一张带描述的归档卡片,内容包括仓库名、Star 数、主要语言、作者,以及一句简短的仓库描述和话题标签。例如粘贴 `https://github.com/antirez/kilo`,Bot 会返回:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂

![antirez/kilo 首次查询返回的归档卡片](assets/06-github-link-r1.png)

卡片底部的 🗂 图标表示该仓库已被归档,后续再次查询时会直接命中缓存。

### 步骤 4:复用已归档的卡片

对于已经查询过的仓库,只需再次粘贴同一链接,Bot 会跳过抓取步骤,直接返回之前生成的归档卡片,响应速度更快。

> 本节示例中的 `antirez/kilo` 仓库属首次查询,Bot 实际执行了抓取 repo 元数据、补充描述、生卡片并归档的全过程。

### 小贴士

- 只粘贴链接即可,无需手动输入仓库名或 owner,Bot 会从 URL 中自动解析。
- 若链接来自 fork 仓库,卡片中的描述与 Star 数仍指向原仓库,作者字段显示 fork 来源。
- 首次查询时 Bot 需要联网抓取描述,可能比复用稍慢;遇到超时可在数秒后重试。
