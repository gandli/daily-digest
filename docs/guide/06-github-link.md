# GitHub 仓库链接 → 单仓查询

将任意 GitHub 仓库链接直接发给 Bot，即可一键抓取仓库元数据、补充描述并生成归档卡片，便于后续检索与回看。

### 步骤 1: 复制仓库链接

在浏览器中打开你感兴趣的 GitHub 仓库页面，从地址栏复制完整 URL。链接格式必须为 `https://github.com/owner/repo`，例如 `https://github.com/antirez/kilo`。

### 步骤 2: 发送给 Bot

将复制的链接粘贴到与 Bot 的对话窗口中，直接按回车发送，无需添加任何额外文字或命令。

### 步骤 3: 等待 Bot 抓取与归档

Bot 收到链接后会按以下顺序处理：调用 GitHub 接口读取仓库元数据（仓库名、Star 数、主要语言、作者等）；请求 deepwiki 与 zread 源获取仓库说明；将完整信息写入归档；最终输出一张带描述的归档卡片。整个过程通常在数秒内完成，首次查询会略慢于已查过的仓库。

### 步骤 4: 查看返回的归档卡片

Bot 返回一张以 ♻️ 开头的归档卡片，示例如下：

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂

卡片包含仓库名、Star 数、语言标签、作者、一句话描述、自动提取的话题标签，以及归档入口。点击卡片底部的 🗂 按钮即可在归档列表中查看完整记录。

![粘贴 GitHub 链接后 Bot 返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 5: 二次发送同一链接

当你再次粘贴相同的 `https://github.com/owner/repo` 时，Bot 会识别为已查过的仓库，直接返回上一次的归档卡片，不再重复抓取与写入，确保归档内容稳定一致。

## 小贴士

- **链接必须完整**：仅发送 `owner/repo` 短格式无法触发查询，请始终带上 `https://github.com/` 前缀。
- **描述可被刷新**：若仓库作者更新了说明，删除旧归档后重新粘贴链接，Bot 会重新抓取并写入最新的 deepwiki/zread 描述。
- **配合话题检索**：卡片底部的 `#` 标签（如 #c、#editor）会同时写入归档，后续可通过话题命令按标签聚合浏览。
