## GitHub 仓库链接 → 单仓查询

本节介绍如何通过粘贴一个 GitHub 仓库链接，让 Bot 自动抓取仓库元数据、生成带描述的归档卡片，方便你快速建立个人化的仓库收藏夹。

### 步骤 1：粘贴仓库链接

在任意与 Bot 的对话窗口中，直接粘贴一个 GitHub 仓库的完整 URL，例如 `https://github.com/antirez/kilo`，无需附加任何文字或命令。Bot 会自动识别链接类型并进入「单仓查询」流程。

### 步骤 2：等待 Bot 抓取与归档

首次提交某个仓库链接时，Bot 会按以下顺序处理：

1. 调用 GitHub API 抓取仓库的基础元数据（仓库名、Star 数、主要语言、作者等）。
2. 请求 deepwiki / zread 等外部源，提取一段仓库描述或摘要。
3. 把抓到的元数据与描述一同写入本地存档。
4. 生成一张带描述的归档卡片发送给你。

如果该仓库之前已经查过，Bot 会跳过抓取步骤，直接从存档中取出已有卡片，并在卡片标题前显示 ♻️ 图标，提示这是一条复用记录。

### 步骤 3：查看归档卡片

处理完成后，Bot 会返回一张格式统一的仓库卡片，例如：

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。 #trending #c #editor 🗂 [存档链接]

卡片中包含仓库名、Star 数、主语言标签、作者、Bot 抓取到的描述，以及自动提炼的话题标签（如 `#trending` `#c` `#editor`）。点击末尾的 🗂 存档链接可以查看完整记录。

### 步骤 4：继续累积或查询其他仓库

收到卡片后，你可以继续粘贴下一个仓库链接来扩充收藏，Bot 会按相同流程逐条处理；也可以直接发送其他指令（如 `#help`）切换功能。

## 小贴士

- 粘贴链接时无需带前缀命令，Bot 会自动识别 `https://github.com/owner/repo` 形式的 URL。
- 同一仓库重复提交会触发 ♻️ 归档复用，避免重复抓取和重复入库。
- 卡片中的话题标签由 Bot 根据仓库描述自动生成，可作为后续按主题检索的入口。
