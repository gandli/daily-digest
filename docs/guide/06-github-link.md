## GitHub 仓库链接 → 单仓查询

把一个 GitHub 仓库链接直接发给 Bot，就能一次性拿到仓库元数据、AI 生成的简介，以及归档卡片。同一仓库再次发送时，Bot 会从归档中读取已有描述并刷新卡片，不会重复抓取。

### 步骤 1：复制仓库链接

在浏览器中打开目标仓库的 GitHub 页面，复制形如 `https://github.com/owner/repo` 的完整 URL。例如本次演示使用的 `https://github.com/antirez/kilo`，它是 antirez 维护的经典 C 语言文本编辑器实现。

### 步骤 2：粘贴链接并发送

回到与 Bot 的聊天窗口，将复制的链接作为一条消息直接发送，无需添加额外文字、命令或前缀。Bot 会自动识别链接属于 GitHub 仓库地址，并进入单仓查询事务。

### 步骤 3：首次发送时的 Bot 响应

Bot 首次收到该链接时，会先抓取 GitHub 仓库的实时元数据（仓库名、星标数、主语言），再调用 deepwiki / zread 生成一段中文描述，最后把描述连同元数据一起写入归档，并渲染为一条带描述的归档卡片。卡片中通常包含：

- 仓库标题与作者，例如 `antirez/kilo ⭐ 3.2k · #C 👤 antirez`
- AI 生成的一句话简介，例如“这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言”
- 话题标签，例如 `#trending #c #editor`
- 归档入口的跳转链接 `🗂`

### 步骤 4：再次发送时的 Bot 响应

如果稍后再次粘贴同一个 `https://github.com/antirez/kilo` 链接，Bot 会识别到该仓库已查询过，不再重复抓取元数据和调用 AI 描述，而是直接从归档中读取已保存的描述，刷新并重新发送一张带描述的归档卡片。卡片样式与首次一致，但响应更快，也不会产生额外的网络与 AI 开销。

### 小贴士

- 链接必须是 GitHub 仓库主页的 URL（含 `github.com/owner/repo` 形式），其他页面（如 Issue、PR、Release）不会被识别为单仓查询。
- 同一仓库多次发送不会重复生成描述，描述在首次写入归档后即被复用，适合把常用仓库固定收藏。
- 如需刷新描述（例如仓库主题发生变化），可在归档卡片中查看 Bot 提供的操作入口，而不是再次发送链接。
