## GitHub 仓库链接 → 单仓查询

本节介绍如何通过粘贴 GitHub 仓库链接，触发 Bot 的单仓查询功能。Bot 会根据是否首次抓取，返回带描述的归档卡片或已有的归档记录。

### 步骤 1: 复制仓库链接

在浏览器中打开目标 GitHub 仓库页面，复制其完整 URL。链接格式应为 `https://github.com/owner/repo`，例如 `https://github.com/antirez/kilo`。复制时注意不要带多余的分支路径或提交哈希。

### 步骤 2: 粘贴链接并发送

将链接粘贴到与 Bot 的聊天窗口中，直接发送，无需添加任何额外说明文字。Bot 会自动识别这是一个 GitHub 仓库链接，并触发查询流程。

### 步骤 3: 等待 Bot 返回归档卡片

Bot 收到链接后，会先检查该仓库是否已经抓取过：

- **已抓取（重复查询）**：Bot 直接返回已有的归档卡片，附带此前生成的描述信息。卡片格式为 ♻️，表示这是重复访问。
- **首次抓取**：Bot 会自动拉取该仓库的元数据（包括 star 数、简介、主要语言等），然后调用 deepwiki/zread 生成中文描述，最后将完整信息存档并返回归档卡。

### 步骤 4: 查看返回结果

无论重复还是首次查询，Bot 返回的卡片都包含以下要素：

- **仓库名**：`owner/repo` 格式
- **Star 数与语言标签**：例如 `⭐ 3.2k · #C`
- **作者**：仓库所有者名称
- **描述**：由 deepwiki/zread 生成的中文简介，例如"这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言"
- **话题标签**：自动提取的 trending 标签，例如 `#trending #c #editor`
- **归档链接**：点击 🗂 后的链接可查看完整快照

### 小贴士

1. **批量查询可逐条发送**：每次粘贴一个链接，Bot 会独立处理并返回对应的归档卡，便于按仓库管理归档记录。
2. **重复查询会秒回**：已抓取过的仓库不会再次调用外部接口，响应更快，且卡片内容与首次一致。
3. **关注话题标签**：Bot 自动提取的标签（如 `#c`、`#editor`）可帮助你快速归类相似主题的仓库，便于后续检索。
