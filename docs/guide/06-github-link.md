## GitHub 仓库链接 → 单仓查询

把任意 GitHub 仓库链接粘贴给 Bot, 即可一次性获得仓库元数据、AI 生成的描述摘要, 并自动归档为可回查的卡片。首次查询会触发抓取与存档, 后续重复查询则直接返回已有的归档卡片, 节省等待时间。

### 步骤 1: 发送仓库链接

在聊天窗口中粘贴完整的 GitHub 仓库 URL, 形如 `https://github.com/<owner>/<repo>`, 然后发送。Bot 会自动识别链接中的 `owner/repo` 路径, 无需额外命令或前缀。

### 步骤 2: 等待 Bot 抓取与归档(首次查询)

如果是该仓库的首次查询, Bot 会按顺序执行以下动作:

1. 调用 GitHub 接口抓取仓库的基础元数据, 包括仓库名、Star 数、主要语言、作者头像等。
2. 拉取 deepwiki 与 zread 两个数据源的描述, 生成一段中文摘要, 帮助快速判断仓库用途。
3. 将抓取到的元数据与描述一起写入存档库, 生成一条永久记录。
4. 把归档结果渲染为一张带描述的卡片, 发送给用户。

整个流程通常在数秒内完成。

### 步骤 3: 查看返回卡片

Bot 会回送一条结构化消息, 顶部是仓库标识与统计信息, 中部是 AI 生成的中文描述, 底部附带 `#标签` 与 🗂 归档入口链接。

例如发送 `https://github.com/antirez/kilo` 后, Bot 回复:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="…"

卡片同时充当「已查过」标记, 再次粘贴同一链接时, Bot 不再重复抓取, 而是直接复用已有归档记录并刷新展示。

![首次查询返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 4: 复用归档(重复查询)

对于已经查过的仓库, 粘贴同一链接即可触发快速通道: Bot 跳过抓取与 AI 描述生成步骤, 直接返回 ♻️ 标记的归档卡片, 响应几乎是即时的。这让 Bot 可以作为团队共享的 GitHub 知识库入口, 谁查过都看得到。

### 小贴士

- 链接需为完整形式 `https://github.com/owner/repo`, 不支持省略协议的简写或仅粘贴 `owner/repo`。
- 卡片中的 `#标签` 由 Bot 根据仓库主题与语言自动生成, 可作为后续按主题筛选归档的入口。
- 同一仓库的归档内容会持续保留, 即使后续 Star 数或描述更新, 再次查询仍展示最近一次刷新的快照, 避免历史信息漂移。
