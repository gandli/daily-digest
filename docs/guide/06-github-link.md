### 步骤 1：粘贴 GitHub 仓库链接

在 Telegram 对话窗口中,将形如 `https://github.com/antirez/kilo` 的仓库地址直接发送给 Bot。无需附加任何文字说明,Bot 会自动识别链接中的仓库标识。

### 步骤 2：等待 Bot 自动抓取与归档

首次发送某个仓库链接时,Bot 会自动执行以下后台操作:

1. 调用 GitHub API 获取仓库基础元数据(仓库名、Star 数、Fork 数、主要语言等);
2. 分别请求 deepwiki 与 zread 两路描述接口,补全仓库的功能说明与使用场景;
3. 将上述信息打包归档到本地存档系统,便于下次直接复用;
4. 整理为一张带描述的归档卡片返回。

整个过程通常在数秒内完成,期间 Bot 不返回中间提示,只需等待最终卡片。

### 3. 阅读 Bot 返回的归档卡

Bot 会回复一张类似下方的卡片:

> **antirez/kilo** ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 [链接]

卡片包含四类关键信息:

- **仓库标识**:`owner/repo` 格式,便于一眼确认是否为目标仓库;
- **元数据摘要**:Star 数、主语言、作者头像与昵称;
- **功能描述**:由 deepwiki / zread 生成的简短说明,帮助你快速判断仓库用途;
- **主题标签**:自动提取的 `#trending #c #editor` 等关键词,便于横向对比同类项目;
- **存档标记**:卡片末尾的 🗂 图标表示该仓库已被归档,下次查询将直接命中。

![首次查询返回的归档卡](assets/06-github-link-r1.png)

### 步骤 4：复用已归档仓库

当你再次粘贴**同一个**仓库链接时,Bot 不再重复抓取 GitHub、deepwiki、zread 接口,而是直接返回已有的归档卡片,响应速度显著提升。你可以通过对比响应时间与卡片上的 🗂 标记确认当前是「首次抓取」还是「命中归档」。

## 小贴士

1. **链接格式仅支持 `https://github.com/owner/repo`**:省略协议头或追加多余路径(如 `/issues`、`/wiki`)可能导致 Bot 无法正确识别仓库标识,粘贴前请保持链接干净。
2. **借助标签快速筛选**:同一语言或领域的多个仓库可一次性粘贴,Bot 会逐条返回卡片,你可通过 `#c #editor` 这类标签横向比较 Star 数与描述,挑选最合适的学习或参考项目。
3. **描述不满意时可重抓**:若 deepwiki / zread 生成的描述与你理解的仓库用途偏差较大,可先删除该条聊天记录,稍后重新粘贴链接触发一次新的抓取流程,覆盖旧存档。
