## GitHub 仓库链接 → 单仓查询

把 GitHub 仓库链接直接发给 Bot，就能自动抓取仓库元数据、抓取描述、归档到自己的资料库,并返回一张带描述的归档卡片。本节按首次查询的完整流程,逐步演示从粘贴链接到收到归档卡片的全过程。

### 步骤 1: 复制仓库链接

在浏览器或 GitHub App 中找到目标仓库,复制其完整 URL,形如 `https://github.com/owner/repo`。链接必须为标准仓库页地址,不要带分支路径或具体文件路径。

### 步骤 2: 粘贴并发送给 Bot

将链接粘贴到与 Bot 的私聊对话框中,直接按下发送键。Bot 会立即识别出这是一个 GitHub 仓库链接,而不是普通文本。

### 步骤 3: Bot 抓取元数据

Bot 在后台依次完成以下动作:

- 调用 GitHub API 获取仓库基础信息,包括仓库名、Star 数、主要语言和作者;
- 向 deepwiki 与 zread 发起请求,抓取仓库的简介、用途与亮点描述;
- 将上述数据连同原链接一起写入你的个人归档;
- 生成归档卡片并附带相关标签。

### 步骤 4: 查看首次返回的归档卡片

首次查询的 Bot 回复类似如下格式(以 `https://github.com/antirez/kilo` 为例):

> `antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="...">`

卡片内含仓库名、Star 数、语言标签、作者、被自动提炼的中文描述、Bot 自动追加的话题标签(如 `#trending`),以及 🗂 归档图标与指向归档详情的链接。

![首次查询 antirez/kilo 返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 5: 二次查询同一链接

再次粘贴相同的仓库链接发送时,Bot 不会重复抓取,而是直接在历史归档中定位该条目,返回与首次相同的卡片,并在卡片左上角显示 ♻️ 图标,提示这是“已查过”的归档记录。这样可以避免重复请求,也方便你在对话中快速复用历史结果。

### 小贴士

- 同一仓库只需首次查询时稍等,Bot 需要并发请求 GitHub、deepwiki 与 zread 三个数据源;之后的重复查询几乎是即时返回。
- 若希望 Bot 抓到不同侧重的描述,可换用该仓库对应的 deepwiki 或 zread 页面链接直接发送,Bot 会将其视为同一仓库并合并归档。
- 链接后追加 `#tag1 #tag2` 形式的自定义标签一同发送,Bot 会在归档卡片中保留你手写的标签,与自动标签共存,方便日后检索。
