### 步骤 1：粘贴 GitHub 仓库链接

在 Telegram 对话窗口中，发送一条只包含仓库链接的消息，例如 `https://github.com/antirez/kilo`。无需添加额外文字，Bot 会自动识别 `github.com/owner/repo` 形式的 URL。

### 步骤 2：等待 Bot 抓取与归档

发送链接后，Bot 会先判断该仓库是否已经查询过：

- **首次查询**：Bot 会访问 GitHub 抓取仓库元数据（仓库名、星标数、话题标签、作者等），再向 deepwiki / zread 等服务请求仓库描述，最后将完整快照存档到数据库，最后才发送回复卡片。这个过程可能需要几秒钟。
- **已查过**：Bot 会跳过抓取步骤，直接从归档中读取已有记录并返回卡片（带 ♻️ 标记），响应几乎瞬时。

> 注意：无论是否首次，处理过程中 Bot 不会发送“正在查询”之类的中间提示，请耐心等待卡片出现即可。

### 步骤 3：阅读归档卡片

稍候片刻，Bot 会以单条归档卡片的形式返回结果，卡片包含以下信息（以 antirez/kilo 为例）：

- 仓库标识与星标数：`antirez/kilo ⭐ 3.2k`
- 主要话题标签：`#C`，以及作者标记 `👤 antirez`
- 由 deepwiki / zread 生成的仓库描述，例如“这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言”
- 自动归类的话题标签，例如 `#trending #c #editor`
- 卡片底部的 `🗂 <a href="...">` 链接，点击即可在 Telegram 中展开完整归档

首次查询与再次查询的卡片区别在于是否带 ♻️ 归档标记：带 ♻️ 表示数据来源于历史快照，未带则表示刚刚完成抓取与描述生成。

## 小贴士

- **链接前后不要加多余文字**：附带“请帮我看看”之类的语句不会影响识别，但保持消息简洁能让 Bot 更稳定地解析 URL。
- **同一仓库二次发送即命中缓存**：再次粘贴同一链接会快速返回带 ♻️ 标记的卡片，适合快速翻看之前的归档记录。
- **支持任意公开仓库**：不限语言与主题，只要 URL 符合 `github.com/owner/repo` 格式即可触发流程。
