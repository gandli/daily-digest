### 步骤 1：粘贴 GitHub 仓库链接

在对话窗口中直接发送一个 GitHub 仓库的完整 URL，例如 `https://github.com/antirez/kilo`。无需附加任何命令或前缀，Bot 会自动识别链接格式并触发仓库查询流程。

### 步骤 2：等待 Bot 抓取元数据

Bot 接收到链接后，会立即访问 GitHub 拉取仓库的基础信息，包括仓库名、Star 数、主要语言、作者头像与昵称。同时 Bot 会尝试向 deepwiki 与 zread 等数据源请求该仓库的简介描述。这一步在后台静默完成，用户只需等待数秒。

### 步骤 3：首次访问生成归档卡片

由于这是该仓库的首次查询，Bot 在拿到元数据与描述后，会将整张卡片持久化存档到数据库，并返回一张带描述的归档卡。卡片内容通常包含仓库标识、Star 数量、语言标签、作者头像与昵称，以及一句对仓库用途的简要说明。

例如粘贴 `https://github.com/antirez/kilo` 后，Bot 会返回如下卡片：

> antirez/kilo ⭐ 3.2k · #C 👤 antirez
> 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。
> #trending #c #editor 🗂

![首次粘贴仓库链接，Bot 返回带描述的归档卡片](assets/06-github-link-r1.png)

### 步骤 4：重复粘贴触发快速回放

当用户第二次（或第 N 次）粘贴同一个仓库链接时，Bot 不再重新抓取远端数据，而是直接从归档中读取既有卡片并以 ♻️ 标记回放。这一机制保证了查询的即时性，也避免了重复请求对外部数据源造成压力。

## 小贴士

- 只支持标准 `https://github.com/owner/repo` 形式的链接；若粘贴省略协议头（如 `github.com/owner/repo`）或附加额外路径（如 `/issues`），可能无法被识别。
- 想查看某仓库的历史归档，可在粘贴链接前加上 `!history` 前缀（若 Bot 提供此变体），或直接搜索仓库名进行反查。
- 首次查询的延迟取决于 deepwiki/zread 响应速度，若长时间无回复，可重新粘贴一次触发重试。
