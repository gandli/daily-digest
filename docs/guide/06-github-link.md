### 步骤 1: 发送 GitHub 仓库链接

在聊天窗口中,直接粘贴一个 GitHub 仓库的完整 URL,例如 `https://github.com/antirez/kilo`,然后发送。无需添加任何额外文字,Bot 会自动识别链接格式。

### 步骤 2: 查看 Bot 返回的仓库卡片

Bot 接收到链接后,会首先检查本地是否已存在该仓库的归档记录:

- **如果之前已查询过**:Bot 会立即返回一张带描述的归档卡 `♻️`,复用历史抓取的元数据与描述,响应迅速。
- **如果是首次查询**:Bot 会自动执行一系列操作,包括抓取仓库的基本元数据(仓库名、Star 数、描述、所有者、头像等)、从 deepwiki/zread 等来源获取 AI 生成的仓库描述、将完整信息存档到数据库,最后生成并返回一张全新的归档卡。

无论哪种情况,你最终都会收到一张格式统一的仓库卡片,例如:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂

卡片中包含仓库名称、Star 数、主语言标签、所有者信息、AI 描述以及自动提取的话题标签。卡片底部还会附带一个存档链接,点击即可查看完整归档内容。

![首次查询返回的仓库卡片,包含元数据与 AI 描述](assets/06-github-link-r1.png)

### 步骤 3: 后续操作(可选)

收到卡片后,你可以:

- **点击卡片底部的存档链接**,跳转查看该仓库的完整归档详情。
- **继续发送其他仓库链接**,每个链接都会独立处理,互不干扰。
- **对卡片内容发起追问**,例如询问某个标签的含义或要求进一步解释。

### 小贴士

1. **单仓查询仅支持完整 URL**:请粘贴 `https://github.com/owner/repo` 格式的标准链接,省略协议或路径的短链接可能无法被正确识别。
2. **重复查询自动走缓存**:同一仓库第二次查询时,Bot 会以归档卡形式快速返回,不再重复抓取,节省等待时间。
3. **AI 描述由 deepwiki/zread 生成**:描述内容会随源站更新而变化,如果你发现描述有误或过时,可通过存档链接查看原始抓取内容。
