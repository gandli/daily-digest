### 步骤 1: 复制 GitHub 仓库链接

打开浏览器, 进入想要查询的 GitHub 仓库页面, 在地址栏复制完整的仓库 URL, 形式为 `https://github.com/owner/repo`。例如本次示例复制的是 `https://github.com/antirez/kilo`, 其中 `antirez` 是仓库所有者, `kilo` 是仓库名称。

### 步骤 2: 粘贴链接发送给 Bot

回到 Telegram, 在与 Bot 的对话窗口中, 直接粘贴刚才复制的链接并发送, 无需添加任何额外说明文字。Bot 会自动识别这是一个 GitHub 仓库链接, 而不是普通文本。

### 步骤 3: 查看 Bot 返回的归档卡片

Bot 接收到链接后, 会返回一张带描述的归档卡片。本次示例中, Bot 回复的内容如下:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="

卡片信息包含多个字段:

- **仓库标识**: `antirez/kilo`, 即 owner/repo 格式
- **星标数**: ⭐ 3.2k, 即 3200 颗星
- **主语言**: #C, 标明仓库主要使用的编程语言
- **作者**: 👤 antirez, 即仓库的所有者
- **描述**: 一段简短的中文介绍, 概括仓库的核心功能与特点
- **话题标签**: 如 #trending #c #editor, 便于分类检索
- **存档链接**: 🗂 后跟 Markdown 锚点 `<a href="`, 提供原始归档记录的访问入口

![Bot 返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 4: 后续操作

收到卡片后, 用户可以根据需要:

- 点击存档链接查看完整的历史归档
- 继续发送其他 GitHub 链接, Bot 会为每个仓库生成独立的归档记录
- 再次发送相同的链接时, Bot 会调取已存档的描述, 不会再重新抓取元数据, 响应更快

---

### 小贴士

1. **链接格式必须完整**: 仅发送 `owner/repo` 而不带 `https://github.com/` 前缀时, Bot 可能无法正确识别为 GitHub 仓库链接, 建议始终粘贴完整的 URL。
2. **避免多余文字**: 不要在链接前后添加诸如 "帮我查一下" 之类的描述, 保持纯链接发送即可, Bot 会自动触发仓库查询流程。
3. **重复发送即查询存档**: 同一链接第二次发送时, Bot 会直接返回已有的归档卡片, 而不会再次访问 GitHub、DeepWiki 或 Zread, 既节省时间也避免触发外部接口的频率限制。
