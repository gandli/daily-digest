## GitHub 仓库链接 → 单仓查询

向 Bot 发送任意 GitHub 仓库链接,Bot 会识别链接、匹配已有缓存或主动抓取仓库元数据与描述,并以一条带描述的归档卡片作为回复。同一仓库重复发送会命中历史记录并即时返回归档卡片,首次发送则会自动完成抓取、存档、卡片渲染的完整链路。

### 步骤 1: 粘贴 GitHub 仓库链接

在 Bot 对话框中粘贴任意 `https://github.com/owner/repo` 形式的链接并发送,例如 `https://github.com/antirez/kilo`。这是唯一需要主动操作的步骤,无需选择菜单或附加命令。

### 步骤 2: 等待 Bot 匹配或抓取

Bot 收到链接后会先在本地归档中检索是否已存在:

- **命中(已查过)**:直接读取历史归档,跳过抓取环节,进入步骤 4 的卡片渲染。
- **未命中(首次)**:进入抓取阶段,依次获取仓库元数据(星标、默认分支、语言等)、调用 `deepwiki` 与 `zread` 生成仓库描述,并将结果写入归档。

首次抓取通常耗时几秒,期间 Bot 不会返回中间消息;同一仓库第二次发送时会明显更快。

### 步骤 3: 首次抓取的描述合成(仅首次)

对于首次查询的仓库,Bot 会整合 `deepwiki` 与 `zread` 两路描述,提炼出仓库的核心定位与适用人群。例如对 `antirez/kilo` 这类小型 C 项目,Bot 会突出“经典文本编辑器”、“代码精炼”、“适合学习 C 语言”等要点,并提取 `#trending`、`#c`、`#editor` 等标签。

### 步骤 4: 接收带描述的归档卡片

Bot 最终回复一张结构化卡片,包含仓库名、星标数、语言标记、作者头像、描述正文、话题标签,以及指向归档详情的链接。卡片下方通常带有一个内联链接,如 `🗂 <a href="…">`,可点击进入完整归档查看更多信息。

首次与重复查询的卡片样式一致,差别仅在响应速度——重复查询走的是归档直出路径。

### 小贴士

- 重复发送同一仓库链接会即时返回归档卡片,适合在多人协作群中快速复用已有总结,而不会反复触发抓取。
- 仓库描述由 `deepwiki` 与 `zread` 综合生成,若仓库刚被创建或文档极少,描述可能偏简略,可在卡片下方的归档链接中查看更完整的元数据。
- 单次只粘贴一个链接效果最佳;若同时粘贴多个仓库链接,Bot 可能只识别并处理第一个,其余建议分开发送。
