### 步骤 1：发送 GitHub 仓库链接

在 Telegram 对话中找到你的 Bot，直接向它发送一条 GitHub 仓库链接消息。链接可以是任意标准格式的仓库 URL，例如 `https://github.com/antirez/kilo`。消息体只需包含链接本身，无需附加任何文字说明，Bot 会自动识别 URL 并提取 `owner/repo` 部分作为查询目标。

发送完毕后，请耐心等待几秒。Bot 首次遇到该仓库时需要执行一次完整的抓取流程：调用 GitHub API 获取仓库元数据（仓库名、星标数、默认分支等），随后请求 deepwiki 与 zread 服务拉取 AI 生成的描述，再将原始数据存入归档库，最后才会渲染出卡片回复你。因此首轮响应通常比后续轮次略慢，属于正常现象。

### 步骤 2：查看 Bot 返回的归档卡片

Bot 完成抓取后会立刻回复一张带描述的归档卡。卡片顶部会分行展示仓库标识（`owner/repo`）、星标数（`⭐ 3.2k`）、主要语言标签（`#C`）以及作者头像与用户名（`👤 antirez`）。中部是一段由 deepwiki 或 zread 自动生成的仓库简介，例如“这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言”。卡片底部则附带若干主题标签（`#trending #c #editor`），便于后续按主题检索。卡片最末尾会输出一个可点击的归档链接，格式形如 `🗂 <a href=…`，点击即可在 Telegram 内预览完整的归档详情。

![首次查询返回的归档卡，含仓库元数据、AI 描述与标签](assets/06-github-link-r1.png)

### 步骤 3：复用链接触发快速查询（可选）

当你再次向 Bot 发送相同的 `https://github.com/antirez/kilo` 链接时，由于仓库描述已写入归档库，Bot 会跳过远程抓取流程，直接返回一张带描述的归档卡（♻️），与步骤 2 的卡片外观一致，但响应明显更快。这一机制让你可以把常用的仓库链接收藏起来，随时调出查阅描述与标签，无需反复等待。

---

**小贴士**

1. **星标数会随归档快照固定**：卡片中显示的 `⭐ 3.2k` 是首次抓取时的快照值，后续即使仓库星标上涨，已生成的归档卡也不会自动更新；如需最新数据，可让 Bot 重新抓取（具体指令请参考 Bot 功能章节的相关条目）。
2. **链接必须为标准仓库 URL**：Bot 仅识别 `https://github.com/owner/repo` 形式的链接。如果你粘贴的是文件路径（如 `/owner/repo/blob/main/README.md`）、Issue 链接或组织主页，Bot 将无法解析为目标仓库。
3. **标签可用于反向检索**：卡片底部的主题标签（如 `#c`、`#editor`）会被纳入归档索引，未来你可以发送 `搜索 #c 仓库` 之类的指令来跨仓库聚合查看同一主题的内容。
