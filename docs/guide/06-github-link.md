## 粘贴 GitHub 仓库链接 → 单仓查询

本节介绍如何通过粘贴 GitHub 仓库链接, 让 Bot 抓取并归档指定仓库的元数据与描述信息。首次查询会触发完整抓取流程, 后续再次粘贴同一链接则直接返回已存档的归档卡片。

### 步骤 1: 复制目标仓库链接

在浏览器中打开你想查询的 GitHub 仓库页面, 从地址栏复制完整链接, 格式为 `https://github.com/<owner>/<repo>`。例如 `https://github.com/antirez/kilo`。

### 步骤 2: 粘贴链接并发送

将链接直接粘贴到与 Bot 的对话中并发送, 无需添加额外文字。Bot 会自动识别这是一个 GitHub 仓库链接, 并启动查询流程。

### 步骤 3: 接收归档卡片

Bot 处理完成后会返回一张包含仓库概要的归档卡片。卡片内容包括:

- **仓库名称**: 形如 `<owner>/<repo>` 的完整标识
- **Star 数**: 显示该仓库的 star 数量(例如 ⭐ 3.2k)
- **主语言标签**: 仓库的主要编程语言(例如 #C)
- **作者**: 仓库的所有者(例如 👤 antirez)
- **描述**: 由 deepwiki/zread 等来源提供的仓库简介, 帮助你在不打开页面的情况下快速了解仓库用途
- **话题标签**: 根据仓库内容自动生成的分类标签(例如 #trending #c #editor)
- **归档链接**: 以 🗂 开头的存档链接, 可随时回溯历史快照

若该仓库属于首次查询, Bot 会先抓取 repo 元数据、再补充 deepwiki/zread 描述、然后执行存档, 最后才输出卡片; 若之前已查询过, 则跳过抓取环节, 直接返回已有的归档卡片。

### 小贴士

- **一次只粘一个链接**: 批量粘贴多个仓库链接时, Bot 可能只处理第一个, 建议逐个发送以确保每个仓库都获得独立归档卡片。
- **链接格式要完整**: 必须使用 `https://github.com/owner/repo` 形式的完整路径, 省略协议头或拼写错误会导致 Bot 无法识别。
- **复用归档卡片**: 同一链接第二次发送时会返回带描述的归档卡, 如果你想强制重新抓取最新数据, 请先在 Bot 中删除该条历史记录再重新粘贴。
