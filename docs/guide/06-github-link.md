### 步骤 1: 复制 GitHub 仓库链接

在浏览器中打开你想查询的 GitHub 仓库页面,从地址栏复制完整的 URL。链接格式必须为 `https://github.com/owner/repo` 这样的标准形式,例如 `https://github.com/antirez/kilo`。这是触发仓库查询功能的唯一入口,其他形式(如短链接、SSH 地址)暂不支持。

### 步骤 2: 粘贴链接发送给 Bot

回到与 Bot 的聊天窗口,将刚才复制的链接直接粘贴到输入框并发送,无需附加任何说明文字。Bot 会自动识别这是一个 GitHub 仓库链接,并启动查询流程。

### 步骤 3: 首次查询 — 获取并归档仓库信息

如果这是 Bot 第一次查询该仓库,需要依次完成以下动作:抓取 GitHub 仓库的基础元数据(包括仓库名、Star 数、主要语言、作者等),调用 deepwiki / zread 等数据源补充仓库描述,然后将完整信息存档到归档系统,最后生成一张带描述的卡片回复给你。整个过程通常在数秒内完成。

如下方截图所示,Bot 回复了一张完整的归档卡片,包含仓库名 `antirez/kilo`、Star 数 3.2k、语言标签 `#C`、作者 `antirez`,并附上了仓库的简要说明("这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。")以及主题标签和归档链接。

![Bot 首次返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 4: 重复查询 — 直接返回已有归档

当你再次发送同一个仓库链接时,Bot 会跳过抓取和描述生成步骤,直接从归档中读取已有记录,返回带 ♻️ 标识的归档卡片(同一条目,响应更快)。如果某次你想强制刷新信息,可以删除该归档后重新发送链接。

---

**小贴士**

- 发送链接前确认格式为 `https://github.com/owner/repo`,owner 和 repo 之间只有一个斜杠,不要带多余的路径(如 `/tree/main`)。
- 同一仓库第二次查询速度明显更快,适合在多次讨论中反复引用。
- 卡片中的 `#trending #c #editor` 标签是 Bot 自动提取的主题分类,点击可发现同主题的其他仓库。
