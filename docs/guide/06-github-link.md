### GitHub 仓库链接 → 单仓查询

本节介绍如何通过粘贴 GitHub 仓库链接,让 Bot 快速返回仓库元数据、相关描述与归档卡片。

### 步骤 1: 复制仓库链接

在浏览器或 GitHub 客户端中找到目标仓库的 URL,例如 `https://github.com/antirez/kilo`,完整复制整段地址。无需手动添加任何前缀或后缀,原始链接即可被 Bot 识别。

### 步骤 2: 粘贴并发送

将链接粘贴到与 Bot 的对话窗口中,直接点击发送。Bot 会立刻解析这个 URL,并判断这是一个 GitHub 仓库地址,进入仓库查询流程。

![首轮查询返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 3: 等待 Bot 拉取元数据

首次查询时,Bot 会依次执行以下动作,耗时通常在数秒以内:

1. 调用 GitHub API 抓取仓库元数据,包括仓库名、Star 数、主要语言、作者头像与昵称。
2. 通过 deepwiki 与 zread 拉取该仓库的描述性内容(例如技术领域、实现亮点、适用人群)。
3. 触发存档动作,将元数据与描述整合成一条历史记录。
4. 输出归档卡片,并打上话题标签,方便后续检索。

### 步骤 4: 查看归档卡片

Bot 返回的卡片包含以下信息块,以 `antirez/kilo` 为例:

- 标题与统计:`antirez/kilo ⭐ 3.2k · #C`,后接作者信息 `👤 antirez`。
- 描述正文:概括仓库实现内容与典型用途,例如“这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言”。
- 话题标签:如 `#trending` `#c` `#editor`,便于按主题归类。
- 存档链接:卡片底部带有一个 🗂 图标,点击即可查看或跳转到完整归档。

### 步骤 5: 重复发送(已查过分支)

如果之前已经查询过同一个仓库,再次发送同一条链接时,Bot 不会重复抓取网络数据,而是直接返回 ♻️ 标记的“带描述的归档卡”。这可以避免重复调用 API,也能让你快速调出历史记录。

### 小贴士

- **保持链接完整**:只发送根仓库链接即可,不要追加 `/issues`、`/pulls` 等子路径,否则 Bot 不会触发单仓查询逻辑。
- **配合话题标签检索**:首次查询后生成的 `#语言` `#领域` 标签会自动写入存档,后续可以用 `/tag` 类命令按主题聚合。
- **重复发送是快捷键**:对于反复查阅的仓库,再次粘贴链接即可秒出归档卡,无需新建收藏。
