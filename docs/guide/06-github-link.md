### 步骤 1:粘贴 GitHub 仓库链接

在 Telegram 对话窗口中,直接向 Bot 发送一个 GitHub 仓库的完整 URL,例如 `https://github.com/antirez/kilo`。粘贴后无需添加额外文字或命令,Bot 会自动识别链接中的仓库归属。

### 步骤 2:首次查询触发的数据抓取

当 Bot 第一次收到这个仓库链接时,会进入「首次查询」流程。它会依次完成以下动作:抓取仓库的基本元数据(项目名、Star 数、主语言、作者等),再调用 deepwiki 与 zread 两个数据源补全项目描述,随后将整理后的信息写入存档,最后渲染出一张带描述的归档卡片。整套过程通常在数秒内完成,你只需要等待即可。

### 步骤 3:查看 Bot 返回的归档卡片

Bot 返回一张格式化的仓库卡片,例如针对 `https://github.com/antirez/kilo` 的回复内容大致如下:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂

卡片中依次展示了仓库名、Star 数、主语言标签、作者头像与昵称、AI 生成的简要描述、相关话题标签,以及用于展开存档详情的 🗂 按钮。点击 🗂 即可看到完整的归档元数据。

![首次粘贴链接后 Bot 返回的归档卡片示例](assets/06-github-link-r1.png)

### 步骤 4:再次查询命中缓存

如果你或群里的其他成员稍后再发送同一个 `https://github.com/antirez/kilo` 链接,Bot 会识别为「已查过」,直接返回 ♻️ 带描述的归档卡片,不再重复抓取外部数据源,响应几乎瞬时返回。这一机制保证了热门仓库的反复提问不会消耗额外的网络资源。

### 小贴士

- 直接粘贴完整链接即可,无需加 `/repo` 之类的指令前缀,Bot 会自动识别 URL 中的仓库归属信息。
- 卡片中的话题标签(如 `#c`、`#editor`)由 Bot 根据仓库元数据自动生成,可以帮助你快速判断仓库方向,适合在群聊中做技术选型讨论时引用。
- 若 Bot 返回的描述过于简略或与你的预期不符,可以尝试发送「重新描述」类指令(若 Bot 支持),或在链接前加 `@owner/repo` 的简写形式触发重新抓取流程。
