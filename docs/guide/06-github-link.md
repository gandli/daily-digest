## GitHub 仓库链接 → 单仓查询

当你向 Bot 发送一个 GitHub 仓库链接时,它会先查询本地缓存,如果命中就直接返回归档卡片;未命中则会抓取仓库元数据、调用 deepwiki 或 zread 获取描述,然后存档并返回卡片。

### 步骤 1: 发送 GitHub 仓库链接

在聊天窗口中粘贴形如 `https://github.com/owner/repo` 的完整 URL,直接发送给 Bot。例如发送 `https://github.com/antirez/kilo`。

Bot 接收到链接后会自动识别 URL 类型,进入仓库查询流程。

### 步骤 2: 等待 Bot 抓取与返回结果

Bot 会按照以下顺序处理:

- **查询本地缓存**:如果该仓库之前已被查询过,直接返回已有的归档卡片,不再重复抓取。
- **首次查询**:若缓存未命中,Bot 会依次执行抓取 GitHub 仓库元数据(仓库名、star 数、主要语言、作者等)、调用 deepwiki 或 zread 接口获取一段描述文案、写入存档、生成归档卡片。

### 步骤 3: 阅读返回的归档卡片

首次查询完成后,Bot 会返回一张带描述的归档卡片。以 `https://github.com/antirez/kilo` 为例,你会看到类似下面的内容:

> **antirez/kilo** ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂 [查看归档]

卡片通常包含以下信息块:

- **仓库标识**:`owner/repo` 格式的仓库全称。
- **Star 数与主语言**:如 `⭐ 3.2k · #C`。
- **作者**:仓库所有者用户名。
- **描述文案**:由 deepwiki/zread 生成的简洁介绍。
- **话题标签**:根据仓库主题自动生成的 hashtag,如 `#trending #c #editor`。
- **归档链接**:点击 `🗂` 后面的链接可查看完整归档内容。

![antirez/kilo 归档卡片,含 star 数、语言、描述与标签](assets/06-github-link-r1.png)

如果该仓库之前已被查询过,Bot 会回复一张带 ♻️ 标识的归档卡片,直接展示已有数据,不再重复抓取。

---

### 小贴士

- 链接必须保持 `https://github.com/owner/repo` 的完整形式,只发送 `owner/repo` 这样的简写不会被识别为仓库查询请求。
- 首次查询的卡片与再次查询的卡片样式略有区别:首次卡片包含抓取到的描述与标签,再次卡片会带 ♻️ 标识,表示数据来自本地缓存。
- 卡片中的话题标签由 Bot 根据仓库语言和主题自动生成,可作为快速筛选同类项目的参考。
