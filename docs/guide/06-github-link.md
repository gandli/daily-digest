### 步骤 1:复制并粘贴 GitHub 仓库链接

在 Telegram 对话中找到目标 Bot,直接将形如 `https://github.com/owner/repo` 的完整仓库 URL 粘贴到输入框并发送。例如本次演示中,用户发送的是 `https://github.com/antirez/kilo`。

### 步骤 2:等待 Bot 处理并返回归档卡片

Bot 收到链接后会执行查询与归档流程:

- 若该仓库在 Bot 数据库中**已经存在**(即之前有人查过),Bot 会直接返回一张「♻️ 带描述的归档卡」,包含仓库名、星标数、主题标签等元信息,本次不再重复抓取。
- 若该仓库是**首次查询**,Bot 会自动完成以下动作:抓取 repo 元数据 → 调用 deepwiki/zread 等源补充描述 → 写入存档 → 生成一张全新的归档卡片返回。

本次演示属于**首次查询**场景。

### 步骤 3:查看返回的归档卡片

Bot 回复了一张格式化的卡片,内容如下:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。 #trending #c #editor 🗂 <a href=…

卡片中可看到仓库路径、3.2k 星标数、C 语言标签、作者 antirez,以及一句由 deepwiki/zread 生成的中文描述,并附带分类标签 `#trending` `#c` `#editor` 和一个存档链接入口。

![首次查询返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 4:继续对话或开启新查询

收到卡片后,你可以直接点击卡片中的存档链接查看完整归档页,也可以继续发送下一个 `https://github.com/owner/repo` 链接查询其他仓库。Bot 对每个新仓库都会重复上述「首次 → 抓取 + 存档 / 重复 → 复用归档卡」逻辑。

## 小贴士

1. **必须粘贴完整 `https://` 链接**:仅发送 `owner/repo` 简写形式无法触发查询,链接前缀是 Bot 识别的关键。
2. **同仓库二次查询会秒回归档卡**:若希望 Bot 重新拉取最新元数据(如星标数变化),目前需换一个未被收录的仓库测试,或在卡片中寻找刷新入口。
3. **描述语言取决于源站内容**:本次返回的是中文描述,得益于 deepwiki/zread 的中文支持;部分冷门仓库可能仅返回英文,卡片标签 `#trending` `#c` `#editor` 由 Bot 自动归类,可作为快速筛选依据。
