### 步骤 1：发送 GitHub 仓库链接

在聊天窗口中，直接粘贴目标仓库的完整 URL，例如 `https://github.com/antirez/kilo`，无需添加任何额外说明或命令。Bot 会自动识别这是一个 GitHub 仓库链接，并开始处理查询请求。

### 步骤 2：首次查询——抓取元数据并生成卡片

如果该仓库是第一次被查询，Bot 会经历一个稍长的处理流程：

1. 调用 GitHub API 获取仓库的基础元数据，包括仓库名、Star 数、主要语言、作者、描述等。
2. 进一步请求 deepwiki 和 zread 两个数据源，补充仓库的功能描述与背景信息。
3. 将原始仓库页面存档，确保信息可追溯。
4. 整合以上数据，生成一张带描述的归档卡片，发送给用户。

最终你会看到如下格式的回复（以 `antirez/kilo` 为例）：

> **antirez/kilo** ⭐ 3.2k · #C 👤 antirez  
> 这个仓库实现了经典的文本编辑器，代码精炼，适合学习 C 语言。  
> #trending #c #editor  
> 🗂 \<归档链接\>

卡片中包含 Star 数、语言标签、作者、简介、话题标签以及归档链接，方便你快速了解仓库概况并随时回溯。

![首次查询返回的归档卡片](assets/06-github-link-r1.png)

### 步骤 3：再次查询——直接返回归档卡片

当你或其他用户再次粘贴同一个仓库链接（例如 `https://github.com/antirez/kilo`）时，Bot 不再重复抓取和描述生成流程，而是直接从缓存中取出已有的归档卡片并发送。响应速度会比首次查询明显更快，且卡片内容与首次保持一致。

## 小贴士

- **粘贴即触发**：只需发送纯链接，Bot 会自动识别仓库类型，无需使用斜杠命令或额外关键词。
- **首次较慢属正常**：第一次查询时 Bot 需要抓取元数据、调用第三方描述源并完成存档，耗时通常在数秒级别；后续查询会显著加速。
- **归档链接可回溯**：卡片末尾的 🗂 链接指向仓库的归档快照，即使原仓库被删除或修改，你仍可通过该链接查看存档内容。
