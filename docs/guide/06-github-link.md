### 步骤 1: 粘贴 GitHub 仓库链接

在 Bot 对话窗口中,直接将 GitHub 仓库的完整 URL 粘贴到输入框,形如 `https://github.com/owner/repo`,然后发送。例如本次发送的链接是 `https://github.com/antirez/kilo`。

### 步骤 2: 等待 Bot 识别并处理

Bot 会自动识别该消息为 GitHub 仓库链接,触发仓库元数据抓取流程。Bot 会同时调用 GitHub 官方接口获取仓库基础信息(名称、星标数、作者等),并通过 deepwiki、zread 等数据源补全仓库描述与主题标签。这一步通常需要几秒,期间 Bot 会以"typing"状态提示正在处理。

### 步骤 3: 查看首次查询的归档卡

首次查询时,Bot 会返回一张带描述的归档卡,内容包含仓库名、星标数、主要语言、作者、仓库简介以及相关话题标签,卡片底部附带归档链接,方便后续回看。本次针对 `antirez/kilo` 的回复如下:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez
> 这个仓库实现了经典的文本编辑器,代码精炼,适合学习 C 语言。
> #trending #c #editor
> 🗂 [归档链接]

完整效果见下图:

![首次查询 antirez/kilo 返回的归档卡](assets/06-github-link-r1.png)

从卡片中可以读到三个关键信息:仓库语言为 C(对应 `#C` 标签)、作者是 antirez 本人(👤 antirez)、以及一段由 deepwiki/zread 生成的简介,这些信息会被一并写入 Bot 内部存档,供日后检索复用。

### 步骤 4: 复用历史记录(已查过的仓库)

对于 Bot 已经处理过的仓库,无需再次粘贴完整链接也不会重新抓取元数据。直接发送相同链接后,Bot 会从本地存档中调取已有的描述与标签,直接返回归档卡(♻️),响应速度明显快于首次。验证方式是:卡片中"🗂"之后的归档链接应当与首次查询时一致,星标数与简介也保持不变;若发现卡片内容与首次有出入,说明该仓库被 Bot 重新抓取了一次,通常发生在仓库本身发生重大变更或数据源更新之后。

### 步骤 5: 延伸用法

拿到卡片后,用户可以直接点击归档链接跳转到完整存档页,也可以基于该仓库继续向 Bot 提问,例如"这个项目还活跃吗"、"和它类似的仓库有哪些"等,Bot 会结合已抓取的元数据给出更精准的回答。

## 小贴士

- **发送链接时无需附加任何说明文字**,Bot 仅凭 URL 即可识别仓库类型,多余的文字反而可能干扰解析。
- **如果链接中包含分支或路径**,例如 `https://github.com/owner/repo/tree/main`,Bot 会按仓库根目录处理,忽略后续路径部分;若想查询某个文件,建议使用专门的文件查询指令。
- **星标数为缓存快照**,Bot 不会实时刷新;若需要最新数据,可以先在 GitHub 页面确认后再向 Bot 询问具体数字。
