## GitHub 仓库链接 → 单仓查询

本节介绍如何通过粘贴 GitHub 仓库链接, 让 Bot 自动抓取仓库元数据并生成归档卡片。

### 步骤 1: 粘贴仓库链接

在 Bot 对话中直接发送一个 GitHub 仓库的 URL, 形如 `https://github.com/owner/repo`。Bot 会自动识别链接类型, 无需额外命令或前缀。

例如, 发送 `https://github.com/antirez/kilo` 即可触发查询。

### 步骤 2: 查看首次归档卡片

Bot 在首次收到该仓库链接时, 会执行抓取流程: 获取仓库基础元数据(如 star 数、描述、作者)、调用 deepwiki / zread 生成更丰富的描述补充, 并将结果归档, 最后输出一张带描述的归档卡。

回复示例:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="

卡片中包含: 仓库名、Star 数、主语言、作者头像与昵称、补充描述、话题标签, 以及可点击的存档链接(因 Bot 渲染限制, 链接在末尾以 `<a href="` 起头, 在客户端会自动补全为可点击卡片)。

### 步骤 3: 重复查询时的归档回显

如果同一个仓库链接之前已经查过, Bot 不再重新抓取网络数据, 而是直接返回已归档的卡片, 并在卡片前以 ♻️ 标识, 表示这是历史归档结果, 而非本次新抓取。

> ♻️ antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 <a href="

这种行为保证了: 同一仓库在不同时间查询结果稳定一致, 也避免了重复请求外部接口。

### 小贴士

- 支持任意公开仓库 URL, 形如 `https://github.com/owner/repo` 即可, 不需要额外的 `/` 或分支后缀。
- 卡片中的 `#trending` `#c` `#editor` 等标签来自抓取到的仓库主题与语言信息, 可用于在 Bot 内快速按主题筛选回顾。
- 如需刷新某仓库的描述或元数据, 可使用 Bot 提供的专门刷新指令(参见对应章节);直接重发链接只会返回归档版本, 不会触发重新抓取。
