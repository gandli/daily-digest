### 步骤 1: 发送 GitHub 仓库链接

在聊天窗口中,直接粘贴目标仓库的 URL(形如 `https://github.com/owner/repo`),无需附带任何额外文字或命令。Bot 会自动识别链接格式并触发 GitHub 仓库查询事务。例如粘贴 `https://github.com/antirez/kilo` 后,Bot 会立即开始处理。

### 步骤 2: 首次查询(抓取元数据 + 描述)

如果是该链接的首次查询,Bot 会:

1. 调用 GitHub API 抓取仓库的基础元数据(仓库名、Star 数、主要语言、所有者等);
2. 依次请求 `deepwiki` 和 `zread` 两个外部服务,获取仓库的结构化描述;
3. 在内部完成存档(将元数据与两份描述合并存储);
4. 将归档结果格式化为单条卡片消息返回给你。

由于这是首次查询,Bot 不会发送前置提示,而是直接给出完整的归档卡。

### 步骤 3: 接收归档卡

Bot 会在几秒内回复一条结构化卡片,包含仓库核心信息和描述。例如针对 `antirez/kilo`,你会看到:

> antirez/kilo ⭐ 3.2k · #C 👤 antirez 这个仓库实现了经典的文本编辑器, 代码精炼, 适合学习 C 语言。 #trending #c #editor 🗂 …

卡片头部是仓库名、Star 数、语言标签、所有者头像与名称;中部是来自 deepwiki/zread 的综合描述;尾部是自动生成的话题标签和指向存档详情的链接(被截断的 `<a href="…` 部分在 Telegram 客户端中会渲染为可点击按钮)。

![首次查询返回的归档卡](assets/06-github-link-r1.png)

### 步骤 4: 后续查询(命中缓存)

当你再次粘贴同一个 `https://github.com/owner/repo` 链接时,Bot 会跳过抓取与外部描述请求,直接读取已有归档,在卡片前追加一个 ♻️ 标识,提示本次响应来自缓存而非重新抓取。返回内容、字段顺序、标签均与首次一致,仅多出回收符号便于区分。

## 小贴士

- 粘贴链接时无需 `@Bot` 或额外命令,直接发送 URL 即可触发;消息中混入手动输入的文字也不会影响识别。
- 归档卡中的 `#trending #c #editor` 等标签由 Bot 根据仓库主题与语言自动生成,不可手动指定,适合作为二次检索的关键词。
- 卡片尾部被截断的 `<a href="…` 在 Telegram 中是「查看完整存档」按钮,点击即可展开完整的元数据 + deepwiki + zread 合并视图。
