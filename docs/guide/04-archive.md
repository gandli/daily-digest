### 步骤 1:发送 `/archive` 命令

在 Telegram 对话框中输入 `/archive` 并发送。Bot 收到指令后,会立即回复当前页的历史存档列表消息。消息顶部会显示页码标识,例如「第 1/2 页,共 14 条」,随后逐条列出历史存档,每条包含仓库名(形如 `sharkdp/bat`)、日期、摘要说明以及对应的 GitHub 链接。消息底部会附带一个 inline keyboard,提供上一页(◀️)与下一页(▶️)按钮,以及当前页对应的 `arch:pg:0` 回调按钮(代表第 1 页的索引为 0)。如果当前已是第 1 页,◀️ 按钮将不会显示。

![第 1 页历史存档列表](assets/04-archive-r1.png)

### 步骤 2:点击下一页按钮

点击消息底部的 `arch:pg:1` 按钮(或等效的 ▶️ 翻页按钮),Bot 会立刻更新这条消息,展示下一页内容。页码标识会变为「第 2/2 页,共 14 条」,列表项会切换为第二页的存档记录(例如 `demo/repo-02` 条目),每条依旧带仓库名、ISO 时间戳、摘要、标签(如有)以及 GitHub 链接。消息底部的 inline keyboard 会同步更新为上一页按钮 `arch:pg:0`,因为已翻到末页,▶️ 按钮将不再显示。

![第 2 页历史存档列表](assets/04-archive-r2.png)

### 步骤 3:浏览条目链接或继续翻页

在第 2 页视图中,你可以直接点击列表内嵌的 GitHub 链接(`<a href="...">` 渲染的可点击锚文本)跳转到对应仓库页面查看源码,也可以继续点击 ◀️ 按钮返回第 1 页。每次点击翻页按钮后,Bot 都会以「编辑原消息」的方式回复,而不是发送新消息,从而保持对话列表整洁;若列表超过两页(例如未来出现 3 页以上),中间页会同时显示 ◀️ 和 ▶️ 两个按钮,便于前后翻页。

### 小贴士

- 翻页按钮本质上是 inline callback 按钮,务必点击消息底部的按钮而非手动输入文本,Telegram 客户端会将点击事件以 callback query 形式回传给 Bot 处理。
- 当前页码索引从 0 开始,因此「第 1/2 页」对应的回调数据是 `arch:pg:0」,「第 2/2 页」对应 `arch:pg:1」,了解这一规则有助于排查按钮无响应的问题(通常是因为会话过期导致 callback 数据失效,此时重新发送 `/archive` 即可刷新)。
- 列表中每条消息均提供 GitHub 直达链接,无需再单独触发 `/get` 或搜索命令即可快速进入仓库,适合在回顾历史推荐时批量浏览。
